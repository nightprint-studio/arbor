# Changelog

All notable changes to Arbor are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **A material's two halves navigate to each other.** <kbd>Ctrl</kbd>+<kbd>B</kbd> on a shader `struct` or one of its members opens the `#[derive(ShaderType)]` it has to match — the same field, not just the file — and from the Rust side it goes the other way. A binding variable in the shader reaches the `#[uniform(n)]` field that supplies it, and back. A declaration split over two files has no primary half, so every join works in both directions.

- **The Bevy components panel says where each thing is created.** A signature answers who *reads* a component; nothing answers who ever makes one — so a type six systems read used to look like it appeared by magic. Every `spawn`, `insert`, `insert_resource`, `add_message` and `init_state` site is now a row under the declaration, naming the function it happens in and the argument it was given (`spawn_player — Health(100.0)`). It reads call sites rather than signatures, so a spawned tuple is one row per component.

- **A material's bind group is visible beside its shader's.** Each `#[uniform(0)]` / `#[texture(1)]` is a row under the material, carrying what the shader declares at that index — the Rust side and the WGSL side of one binding on one line, which is what reading both files was for.

- **A Bevy material and its shader are checked against each other.** Nothing in the toolchain does: a `#[derive(ShaderType)]` struct in Rust and a `struct` in WGSL describe the same block of bytes in two files, and getting a field's type or its position wrong still compiles — the uniform is just quietly read with a different layout than it was written with. Bennu compares them field by field, checks that every `#[uniform]` / `#[texture]` / `#[sampler]` exists in the shader's material bind group, and that a stage named in Rust has an entry point in the shader. <kbd>Ctrl</kbd>+<kbd>B</kbd> on a shader path opens the shader; on a `.wgsl` it lists the materials that run it; and the new **Shaders** panel is that list keyed the other way round. Both asset forms are understood — a game's `assets/` and a library's `embedded://`, including a path written as a `const`.

- **Fonts open as a specimen.** A `.ttf`, `.otf`, `.woff` or `.woff2` shows a field you type into with size, weight, tracking and italic beside it, a waterfall at eight sizes, and a measured coverage column per Unicode block — instead of being refused as a binary. Coverage is measured by rendering rather than read from the font's tables, so it works on anything the browser can load with nothing installed. They get their own icon in the tree.

- **Bennu has a welcome tour.** Six steps on the first launch — what it is, opening a project, where the panels are, getting around code you have not read, and how a language that is not Java gets served. Re-openable from the Command Palette. It is Arbor's own tour dialog with Bennu's content in it, and it keeps its own record of having been seen: finishing one product's tour is no reason to stop introducing the other.

- **Animations, Keyboard Inputs and Terminals settings are shared too.** They join Appearance in Bennu's, merula's, Picus's, the File Explorer's and Tyto's settings, as far as each applies. The terminal shells especially: Bennu's terminal has always been Arbor's terminal, so the page that configures it now sits in both.

- **Appearance settings are in every product's settings, not only Arbor's.** Font scale, window controls, the compact title bar, the theme and the minimized-dialogs cap already applied to every window; now they can be changed from Bennu, merula, Picus, the File Explorer and Tyto as well, from the same page rather than a copy of it.

- **Bennu's activity bar can be rearranged.** Drag the icons on either rail into the order you want and hide the tools you do not use — *Customize Activity Bar…*, in the Command Palette, the gear menu, or Settings → Interface → Appearance. It is Arbor's own editor, over Bennu's rails; the two products keep their arrangements separately. Only the project tree cannot be hidden, and a tool a project does not offer keeps the place you gave it for when it comes back.

- **Bennu's manual is forty pages instead of twelve.** The two pages that carried half of it — *Editing & navigation* ran to forty headings, from rainbow brackets to Struts action resolution — are now one page per topic, grouped by where you would look: Projects, Editor, Structural search, Java & JSP, Rust, Build/run/test, Reference. Search results are worth choosing between again, because the page title that comes back with a hit says what the page is about. There is a proper **Getting Started** too.

- **Files can be deleted from the project tree — and undeleted.** <kbd>Del</kbd> on the focused row or **Delete…** from the right-click menu, with a confirmation that says what it is about to remove. It does not use the system trash: the files go into the local history, so <kbd>Ctrl/Cmd+Z</kbd> with the tree focused puts them back, the toast carries the same Undo, and days later they are still under **Local History › Deleted**. That is also why the undo works identically on macOS, where the OS trash has no way to put a file back where it came from. Two undo stacks, deliberately: in the editor those keys still mean "un-type that".

- **Shaders navigate, explain themselves, and complete their imports.** Go-to-declaration, find-usages and hover now work on a `.wgsl` with no language server — a hover on your own function shows its signature and the `//` block above it (WGSL has no doc-comment syntax, so those lines *are* the documentation), and one on a built-in or an attribute says what the language says. `#import` lines complete too, braced multi-line form included: the modules your project declares with `#define_import_path` first, then Bevy's own.

- **Shaders are a first-class file type.** A `.wgsl` gets highlighting built for WGSL rather than borrowed from C — `@group` / `@binding` / `@vertex` read as the interface, `vec4<f32>` as a type, `textureSample` apart from the functions you wrote — and, with nothing installed, it is **compiled**: Bennu validates it through **naga**, the front end wgpu and Bevy use, so a squiggle is an error the shader would really have hit at pipeline creation. Completion offers the file's own bindings and structs before the language's vocabulary, and find-usages resolves whole words in the file. A shader composed with naga_oil (`#import`, `#ifdef`) is deliberately not compiled alone — half its names live in the module it imports, and checking it standalone would paint a correct shader red. Note that installing `wgsl-analyzer` does not currently improve that case: its module system is WESL, not naga_oil.

- **Bennu can install a language server for you.** Settings → Language Servers now has an **Install** button beside each missing server that is distributed through a package manager you already have — `rustup`, `cargo`, `go`, `npm` — including **wgsl-analyzer**, which is now in the catalogue. It runs the command rather than downloading a binary, so the server lands where the rest of your toolchain lives and keeps working afterwards; the build streams into the Build panel, because `cargo install --git` takes minutes.

- **Word documents open in a tab.** A `.docx` renders as the page Word laid out — styles, tables, images — instead of being refused as a binary or flattened into approximate HTML. Read-only, never a buffer, with a button through to the system application.

- **`.ron` finally reads like RON.** It used to borrow Rust's highlighting, which meant a field called `type:` or `mod:` came out as a keyword while the field names — the thing a RON file is mostly made of — had no colour at all. It has its own mode now. Shaders, RON, Word, Excel and PDF also have their own icons in the tree, and `.log` files got theirs back (a duplicate entry had been quietly replacing it with the plain-text mark).

- **Local history.** Bennu now keeps its own record of what every project file used to be — underneath git, not beside it: git protects you from the commit onwards, and most of the ways a file is lost happen before that. <kbd>Alt+Shift+H</kbd>, the right-click menu in the editor or the tree, or the Command Palette. A revision is kept on every save, on every write a tool makes (a refactor, a generate), on a change that happened outside Bennu, and on a rename — not on every keystroke, which is what the editor's own undo is for. Labels never expire; everything else is kept for a week within a size budget, and files git ignores are skipped. Nothing is written inside the project.

- **The files you deleted are a list, not an expedition.** Local history's fourth scope is everything the project no longer has — flat, searchable, newest first, with the path and how it went (a delete, or a move somewhere else), and one button to put it back where it was. A deleted file has no row anywhere to right-click, so reaching its history through the old folder's change sets, having remembered the folder yourself, was the only way it could have worked. Deleted files also stay visible in the folder scope, struck through and exactly where you left them.

- **New files follow the project's language.** A Cargo root is offered Rust templates — empty file, struct, enum, trait, module, test module — instead of a Java class it cannot compile. The field asks for what each language actually names: a type in Java, a `snake_case` module in Rust (`atlas_player` gives you `atlas_player.rs` holding `AtlasPlayer`), and **Module** creates the directory form, `atlas_player/mod.rs`.

- **The compiler's errors are on the scrollbar too.** After a build, whatever `javac`, Maven or `cargo` reported for the file you have open is a red or yellow mark on the right-edge strip and a squiggle on the line, instead of a list in the Build panel you had to travel to and come back from. Clicking a mark now lands the caret on that exact line rather than near it, and the strip finally draws a thumb, so it says where in the file you are.

- **The project tree marks what git ignores, and what is hidden.** Ignored entries are dimmed the most, hidden ones (a leading dot) sit between them and a normal row, and both stay listed — a stale ignored artifact you cannot see is one you cannot explain. Nested `.gitignore` files, negations and `.git/info/exclude` all count, the way git counts them.

- **A crate or Maven module reads as one in the project tree.** A directory holding a `Cargo.toml` or a `pom.xml` is where a build target is declared, not just a folder of files — so it is drawn as a filled, accented folder against everyone else's outline. Same shape, different weight: the top of a workspace tells you which folders are packages without opening any of them, and without a second glyph to learn.

- **A test run an assistant asks for always comes back.** A test that never terminates used to hold the call open for as long as anyone was willing to wait, which is indistinguishable from the tool being broken. The run is now stopped after ten minutes — or sooner, if the client asks — and the answer says it was stopped, with whatever had finished by then. A stopped run is never reported as a pass. This bounds the *call*, not each test: with `cargo test` a whole target shares one process, so the run goes rather than the one case that hung.

- **An exported atlas doesn't bleed between frames.** Each frame now sits inside a one-pixel guard filled by repeating its own border, so a renderer that filters the texture — a zoom, a non-integer scale — samples the colour that was already there instead of the neighbouring frame's edge. Transparent padding would have swapped one defect for another (a frayed edge instead of a dirty one); repeating the border fixes both. Set the guard to 0 for a tighter pack when the atlas is only ever drawn 1:1.

- **A recorded sequence can become a sprite atlas.** A frame sequence exports to PNG **pages** plus an `atlas.ron` sheet that says where every frame sits and how long it is held — a folder a renderer can draw from with one texture upload instead of one per frame. Press <kbd>E</kbd> in the player or use the button in the library; an AI client can ask for it too. A recording too long for one page spills into further pages rather than being shrunk, and each frame records which page it belongs to.

- **Tyto records image sequences, not just video.** A recording can now produce a folder of numbered stills instead of an MP4 — same countdown, same snip selector, same control bar, only the file at the end differs (<kbd>Ctrl+Shift+F</kbd> switches). Frames are lossless, so text and thin lines survive where video compression softens them, and a frame is written only when the screen actually changed: a still screen costs one image however long it stays still, and each frame remembers the moment it belongs to, so it plays back at real speed. Sequences play in the library with a full transport — timeline, single-frame steps, loop, 0.5×/1×/2× — and an AI client can record one and read any frame back out of it.

- **AI tool surface (MCP), backend half.** A handler can now opt into being callable by an AI client with `#[handler(mcp(...))]`: it declares a safety class, and its `///` doc comment and args-struct field docs become the description and JSON Schema a model reads — so a tool's documentation and its rustdoc cannot drift apart. Exposure is opt-in, never automatic. Bennu exposes six read-only verbs (open + summarise a project, list its types, list its files, read a file in the project's real encoding, find TODO markers, check the index state) and Tyto six (list capturable screens and windows, capture one — by window *title*, returned as an image rather than a file path — read the on-screen accessibility rectangles, check whether a recording is running, record a frame sequence for a fixed duration, and read one of its frames back by index or by moment).
- **Arbor tells an AI client what you have open**, as MCP *resources* rather than as a tool call. The open projects — from Corvus's repositories and from every other product's recents — are offered for the client to attach, so a session can start knowing what is being worked on instead of spending its first call asking. Read-only and un-prompted, and safe for the reason it is useful: a resource reports *that* a project is open and where, never what is inside it. Reading a file is still a tool call, gated by project scope and policy like every other one.

- **Bennu is reachable by name, not by byte offset.** Its navigation answers from a caret position, which is the right unit for an editor holding a buffer and useless to anything that has only read a stack trace. Two verbs close that gap for AI clients: **`bennu_symbol_at`** takes a file, a line and a column — counted the way an editor and a compiler error count them, in characters rather than bytes, so an accented Cp1252 source resolves where you pointed — and reports what is there and where it is declared; **`bennu_find_symbol`** finds a type or member by name against the semantic index, so a method called `process` is one declaration rather than two hundred grep hits, with exact names ranked above longer ones that merely contain them. Both say *why* an answer is empty: "not on a symbol" and "the index is still building" are different problems, and a bare empty result cannot tell them apart.

- **An AI client can ask who uses a symbol.** Find-usages answers from the project's reference index, so each occurrence is resolved to a declaration first and only the ones that really are this symbol come back — a method called `process` is its own handful of call sites rather than the two hundred lines a text search returns. Addressed by line and column, on the declaration or on any use of it, and grouped by file with the heaviest first, so the blast radius of a change is visible before a single file is opened. Columns are recomputed against each file in its real encoding, so a coordinate from an accented source is one you can point at again.

- **A project's tests are a list an AI client can read.** Every test a project declares, with the selector its runner needs to run exactly that one — `OrderTest#computesTotal` under Maven, `orders::tests::computes_total` under cargo — covering JUnit 3/4/5, TestNG, and `#[test]` / `#[tokio::test]` / `#[bench]` / `rstest`. Read from the sources, so it answers on a project that has never been compiled, and it reports what is **disabled**, which a test run cannot: a skipped test does not appear in its output at all.

- **An AI client can run the tests and be told what failed.** Until now the only way to run them from outside Arbor was to start a run and get an id back — the results arrived as events, which a client cannot hear, so a model could report tests as run without ever learning that four of them failed. This runs `mvn test` or `cargo test`, waits, and answers with the counts and **every failure with its message**. Name the tests you want using the selectors the test catalogue reports; a run that compiled nothing and tested nothing is reported as such rather than as a pass. It executes the project's own code, so it needs your approval like any other change.

- **Tests can be run one crate at a time.** Between "this test" and "the whole project" there was nothing, and the whole project is minutes. Naming a crate or a Maven module runs all of its tests and nothing else — which, after touching a crate, is what you actually want. The note on a run whose selection was too long to spell also stopped claiming more was run than asked for when the fallback happened to cover exactly what was asked for; it now checks the count rather than assuming.

- **A long call says what it is doing while it does it.** A tool that takes minutes used to have two things to say — the id it started with and the answer — separated by silence, which reads exactly like a hang. Arbor now answers those calls on a live stream: which class is running, which crate is compiling, how each target finished, and the result at the end. Offered only to a client that asked to read one; anything else gets the same answer as a single reply. Meanwhile Bennu's own Tests panel fills in live, because it is the same run — watching what a model is running is a matter of opening the panel.

- **One file can be checked for problems without building anything.** The resolver-backed validation a Java file gets in the editor — unknown members, type and inheritance errors, unused imports, syntax — plus the framework checks and, for a Rust file, whatever the language server last published, each problem at a line and column with the source line beside it. An empty answer says whether the index had finished building, because before it has, "no problems" is not yet an answer.

- **You can see what an assistant can see.** <strong>Show AI tools</strong>, from the Command Palette or the home surface's settings menu, lists every tool Arbor exposes, by product, each with what it does and which class of action it belongs to — the same descriptions the model reads, since both come from the handler's own documentation rather than from a list kept in step by hand. Products you have not switched on are shown dimmed with their tools intact: deciding whether to expose one is a decision about what it would let an assistant do.

- **You can see who is connected.** The endpoint page lists every AI client that has introduced itself since Arbor started — its name, its version, when it last did — and how many are listening for updates. "Is anything actually talking to this?" had no answer anywhere before, which made every other question about the endpoint harder than it needed to be. Honest about its limits: connections are not kept, so it records handshakes rather than presence, and a client that quit leaves nothing behind to notice. Calls are counted separately from handshakes, because after Arbor restarts a client that is plainly working has no reason to introduce itself again — and "nobody has connected" would be the wrong thing to read while it does.

- **A connected AI client is told when the tools change.** A client asks for the tool list once, when it connects, and keeps it — so rebuilding a backend, or switching a product on, left it offering tools that were gone and blind to the ones that had arrived, with nothing anywhere saying so. Arbor now announces the change and the client re-reads the list on its own. Nothing else is ever pushed unasked.

- **You can watch what an AI client is doing, from anywhere.** The call log used to be a page of the launcher's settings that filled in only once a call had finished — silent for exactly as long as something was running, which is the only time anyone is watching. Now a row appears the moment a call arrives and updates through waiting, waiting-for-your-approval, running, and however it ended; a running call shows the output it is producing, the same lines the client is sent. It opens from every product's Command Palette (**Show AI Activity**) and from the home surface's settings menu, because "what is that assistant doing right now" is asked from wherever you happen to be working — and it is no longer a page of the AI settings, which was the same list in a place you had to go looking for it.

- **The call log survives a restart.** It used to be memory only, which meant the call you wanted to look at — the one from the session where you noticed something odd — was already gone. Rows carried over from earlier runs are marked as such and carry their date, and *This run only* narrows to the current session. It lives in your Arbor profile beside your settings, never in a project; it is capped rather than kept forever; and **Clear** deletes the file rather than emptying it. A call that was still running when Arbor stopped is kept and read back as *interrupted* — worth seeing, and sometimes why it stopped — rather than left claiming to be in flight forever. Arguments sit on one line until you ask for them — they are the auditable part of a call and are never hidden, but a screenful of JSON per row is a page nobody reads.

- **The activity log narrows to one product.** Every call already recorded which backend served it and the page never showed it. A picker appears once more than one product has been called, so "what has Bennu been asked to do" is answerable without reading past everything else; a row names its product only when the tool's own name does not already, since "bennu · bennu_test_run" is the same word twice.

- **The activity filters say what actually happened.** Calls are bucketed by what became of them — ran without needing permission, you approved, you declined, refused by rules, failed — instead of one lump "asked you". A bucket only appears when it has something in it, and "in flight" is one of them. "Ran freely" is the set worth reviewing: it is what your settings let through without asking.

- **AI access is managed across projects, not one at a time.** The project rule window is now the list and the rule side by side: pick any project on the left, set what it allows on the right, add one, remove one, and see at a glance which of them say something of their own. It opens on the project you came from rather than being about only that one — comparing what you granted elsewhere used to mean closing and reopening it. You choose from what Arbor already knows — everything you have opened, in any product, is offered and joins the list in one click, and opening the window from a product puts that product's own projects first. The folder picker is left for a path Arbor has never seen. The list is also the scope under *Listed projects*, so it says which of the two it currently is and can be made the gate from there.

- **A project can grant one tool without granting its class.** Project rules gained a second tab where any single tool can be set to allow, ask or refuse on its own — the grant a class cannot express: "this checkout may be written to, but only by the file-saving tool" would otherwise mean loosening every tool that modifies anything. A tool named there outranks its class; everything unnamed keeps following the classes, so the list stays short and a rule written today still follows the tool set as it grows. The rule modal is now two tabs, with the project's path where it reads as identity rather than as a field you might edit.

- **The framework catalogs are answerable by an AI client.** One tool lists what a framework contributes to a project: Spring beans with their classes, the endpoints it serves, MyBatis mappers, and each Bevy component, resource, message and system together with the systems that read and write it. These are the questions a text search answers badly — "which beans exist", "what does this serve", "who touches this piece of ECS state".

- **A Rust workspace describes itself to an AI client**: member crates, what each depends on, and the third-party crates with the versions actually resolved — for seeing the shape of an unfamiliar workspace, working out what a change would rebuild, and spotting dependencies that have moved on. Read from the manifests and the lockfile, so it answers on a project that has never been built.

- **An AI client can plan a rename the way Bennu does.** It answers from the project's whole reference index, so it separates a real reference from an identifier that merely shares the name, and follows a class rename into imports and Spring bean declarations — none of which a textual search-and-replace can do. Sites come addressed by line and column rather than byte offset, each carrying the text currently there so a stale plan is caught before it is applied, and the engine's inferred guesses (a call to a same-named method whose overload could not be told apart) are flagged as such rather than mixed in with the exact ones. It plans only; nothing is written.

- **Bennu tells an AI client what a codebase is built on.** A new tool reports which frameworks it recognises in a project and how much of each it found — Struts actions, Spring beans and properties, MyBatis mappers, JSP taglibs, Bevy systems. In a legacy enterprise stack the behaviour lives in XML configuration rather than in the Java, so the file you would have opened first is often not where the answer is; this is the call that says so before any source is read.

- **Registering an AI client is a one-off.** The endpoint's bearer token is now minted once and kept, instead of being regenerated on every restart — it lives in the client's own configuration, so a credential that rotated on its own meant re-registering the server every time Arbor started, and it was never buying any security: the endpoint only exists while Arbor runs, and turning it off revokes access outright. Rotation is now a deliberate act, **Regenerate token**, which is when it is actually worth having.

- **A record of what an AI client actually did.** AI tool access grew an **Activity** page: every call this run, newest first, with its arguments, its outcome, and — for a refusal — the reason the model was given, in the same words it read. Refusals are rows too, because a refused call is either the gates working or a setting tighter than you meant, and both are worth seeing. Kept in memory only: a trail of this session, not a log file growing on disk. Filters for the two that matter — what was refused, and what asked you.

- **Documentation for the whole AI surface**, under Settings → AI tool access: connecting a client, the four gates, per-project rules and the edges they have, how a prompt is answered, and what each product exposes.

- **AI permissions answer per project, not once for everything you own.** Which backends a client may reach and what it may do with them can now be said for one project in particular — the interesting grant being exactly the one a single switch cannot express: that *this* checkout may also be written to, while everything else stays read-only. Every field is an override with an explicit **Inherit** position, so a project states only what it disagrees with and tightening the global settings still tightens every project that never objected; each inherited row shows what it currently resolves to, because "what happens here" is the question being asked. Rules are edited from two places — the project list in AI tool access, where you can see everything you have granted at once, and the settings menu of the window a project is open in, where you already are when you want to change it. They live in **your** profile against the path, never in the project: a permission file inside a repository is one that gets committed, and a shared repo could otherwise hand `destructive: allow` to everyone who clones it. A call naming paths in several projects gets the strictest of their answers, and one naming no path at all — a screen capture — is still decided globally, since attributing it to whichever project happens to be open would be a guess dressed up as a permission.

- **AI tool surface (MCP), the launcher half.** Settings → **AI tool access**, from the launcher's gear menu or the Welcome page's, turns on a loopback endpoint an AI client connects to (`claude mcp add --transport http …`, the whole line is there to copy). Off by default, and four gates decide the rest independently, all starting closed: which **products** are reachable, which **project folders** are in play (only what you have open, a folder list you choose, or anywhere — spelled out rather than hidden), and what happens per **class of action** — reads run, changes ask, destructive is refused. A prompt shows the tool, what it says it does, and *the actual arguments*, because "write a file" and "write this file" are different questions; closing it, pressing Escape, pressing Enter and walking away all mean no. Every call is logged with its arguments and outcome, in memory only. A path outside scope is refused without a prompt at all — a request for something private never becomes a dialog you might click through.

- **Bennu**: **Bevy ECS support.** A project whose `Cargo.toml` declares `bevy` gets three catalogs and a gutter. **Components** (<kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd>, or the rail button) lists every component, resource, message, event and bundle, each expanding into the systems that read it, the ones that write it, the ones that only filter on it (a marker component's whole job) and the bundles that carry it — "who writes `Health`" is a question about system signatures, and a text search answers it with every comment that mentions the word. **Systems** lists what runs, badged by schedule. **Access conflicts** lists the pairs of systems in one schedule that contend over the same data and therefore can never run in parallel, tagged `ordered` when the project already sequences them and `unordered` when nothing does — the second being a frame-order dependency nobody wrote down, and the only one also **warned about in the editor** (a system in a set is never accused, since `configure_sets` is not read). Every ECS declaration carries a gutter mark pointing at the systems that touch it. A project on an engine of its own is read through it: fulcrum's per-domain parameters (`DomainResMutParam`, `DomainMessageReader`, …) count as the `Res` and `MessageReader` they wrap, so a declaration nothing mentions directly still lists what touches it. Read from the sources alone: no build, no running game. It reports only what stays true of a partial reading — a conflict cannot be undone by a plugin's systems — so it never claims two systems run in parallel and draws no ordering graph.

- **Bennu**: **a module graph** — <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>, or the network button on the Dependencies and Cargo windows. The dependency list says what a module needs; this answers the four questions a twenty-crate workspace generates and a list cannot: who uses this, what a change to it rebuilds, what is foundational, and whether there is a cycle. Layers read left to right — dependents first, the foundation last — so every arrow in a healthy project points rightwards and **a leftward arrow is a cycle**; the whole ring is named rather than the single pair cargo mentions when it refuses. A `dev-dependency` is dashed and does not count as closing a cycle (cargo compiles a crate's tests separately, so that arrangement is normal) while still counting towards what rebuilds — under Maven, where the reactor refuses any cycle, a `test` scope closes one like anything else. The list beside the drawing sorts by rebuild impact, layer or third-party weight and is fully keyboard-driven. **Solo** (<kbd>Alt</kbd>+<kbd>S</kbd>) isolates one module's world — everything connected, or only what it is built on, or only what it would break — as a real filter, so the rest stops taking up room; it follows the selection, so you can walk a chain one crate at a time. Long edges are routed through the columns they cross instead of straight across them, so they pass beside the boxes rather than through them, and hovering a box lights its own lines. A **legend** draws each mark beside its meaning — the difference the two commonest line styles carry is one thing: a solid dependency decides the order things are built in, a dashed one does not. **Export** copies or writes the graph as Markdown (shaped for handing to a language model: every module's dependencies and dependents, plus what is most expensive to change, what nothing depends on, and the cycles), JSON, or a CSV edge list; it exports what is on screen and says which filters were on. Works for a Maven reactor too, from the same reading — nothing runs cargo or Maven, so it opens on a project that has never been built.

Which profile is active decides where Bennu's own settings and its workspaces are written, so a window that could not say which one it was on was a window you could not trust with a second profile.

- **Bennu**: **expand all / collapse all on both Tests tool windows** — the pair the run console already had, in the same order, so folding a tree is one habit in all three places.

- **Bennu**: **Expand macro is offered under <kbd>Alt</kbd>+<kbd>Enter</kbd>** on a Rust file, named after the macro it found (`Expand vec!`), beside the server's own quick fixes — "what can you do where I am standing" is one gesture. It appears only when the caret really is in a macro call, and picking it opens the expansion with nothing left to wait for.

- **Bennu**: **Rust debugging.** <kbd>Shift</kbd>+<kbd>F9</kbd> on a Cargo configuration now attaches a debugger instead of saying it cannot, and the panel is the one Java already had: the same frames, variables tree, watches, stepping and keys. Bennu speaks the Debug Adapter Protocol to whichever adapter is installed — **CodeLLDB** first, because it is the one that renders Rust's own types (a `Vec<T>` as its elements, an `Option` as `Some(3)`; without that a debugger technically works and practically does not), then **lldb-dap**, then **GDB 14+** in DAP mode. CodeLLDB ships as a VS Code extension, so it is found in the extension directory as well as on `PATH`, and lldb-dap is found inside Xcode's toolchain, which no windowed app's `PATH` includes. A launch **builds first and reads the executable's real path out of cargo's JSON** rather than composing `target/debug/<name>`, which is wrong on any project with a named profile, a renamed `[[bin]]`, a `target-dir` or a cross target — and a test binary's name has an unpredictable hash in it. Build errors land in the same console tab, so a failing build reads as one. Settings → Debugger can pin an adapter; a pinned one that is missing is reported rather than silently replaced, because the three render values differently. Breakpoints, exception stops (Rust's is a panic, not a caught/uncaught throwable) and muting all work on both debuggers, muting by uninstalling from the adapter and putting them back.

- **Bennu**: **Rust values in the debugger read as Rust values.** Neither LLDB nor GDB knows anything about Rust's types on its own, so a `Vec<Order>` was five clicks down `buf` → `inner` → `ptr` → `pointer` to an address with the elements nowhere, and a `String` was a byte buffer. Bennu now sets each adapter up to render them: CodeLLDB is told the source language so it uses the formatters it ships, and **lldb-dap — which ships none but is the adapter most macOS machines have — gets the Rust toolchain's own loaded into it at launch**, the same two files `rust-lldb` exists to load. A machine with no toolchain to borrow from gets a line at the top of the variables tree saying so and what to install, instead of leaving "unconfigured" and "broken" looking identical. Formatters only cover the standard library, so a struct of your own gets a synthesised `{id:7, total:19.9}` summary where the adapter supports one, and a count of its fields rather than a blank cell where it does not.

- **Bennu**: **read a whole value at once, as RON.** The variables tree fetches lazily, which is right — but a struct with fifteen fields, four of them structs, is nineteen disclosure triangles before you can read it, and by then it does not fit on screen. Every row with something inside it (and every watch) now carries a `{}` button that reads the value and everything under it in one request and shows it as text you can scroll, search and copy. **RON**, not JSON, because it is a Rust value and RON keeps the three distinctions JSON throws away that are exactly the ones a debugger is opened for: a named struct is not a map, a tuple is not a list, and an enum variant is a name rather than a tag field. The walk stops on whichever of a depth, a node count, a container's width or a time budget comes first and **says** it did — at the top and at the row where it stopped — because a dump silently cut reads as a complete answer. A value the debugger already rendered as a literal is printed rather than opened — Rust's formatters give a `String`, a `PathBuf` and an `OsString` their text *and* still offer children, so following those turned one path into four levels of internals and a row per character. A value containing itself is named as a cycle rather than followed. Works on a Java object graph too, from the same reading.

- **Bennu**: **watches on a native session.** A path — now including a leading `*` to follow a reference, where `*self.next` means what the same line means in the source file — is **read out of the variables tree** rather than handed to an expression evaluator: so `v[0]` in the watch box and `[0]` under `v` in the tree are the same row, it means the same thing whichever of the three adapters resolved, it knows which variant an enum is actually holding, and `v[400000]` on a million-element `Vec` fetches that one element. Anything else goes to the debugger's own evaluator, with CodeLLDB's three dialects reachable by prefix (`/se`, `/nat`, `/py`) and a prefix the running adapter does not have refused by name instead of coming back as a syntax error about a slash. And **what Rust cannot evaluate at all now says why**: `v.len()` used to return LLDB's *no member named 'len' in 'alloc::vec::Vec<i32>'* — C++ prose about a Rust type, which reads as a broken debugger — where the real reason is that a debugger can only call a function that is in the binary, and a generic one nobody called was never compiled. Method calls, macros, turbofish, `?`, `.await` and closures each get one line saying that, and what to read instead.

- **Bennu**: **breakpoints in the margin of a Rust file.** The gutter offered them on Java only — the predicate for which lines can take one was a reading of *bytecode*, so a `.rs` file got no dot anywhere. Rust has its own reading now, and it is deliberately more permissive: a native breakpoint is resolved from debug info by LLDB or GDB, and the adapter reports whether it bound, so the only lines refused are the ones that are certainly declarations — a `use`, an attribute, a `struct`, a lone brace. A `fn` line **is** offered, because both debuggers bind it to the function's prologue and it is the commonest breakpoint there is. The debug button is in the titlebar, the run menu and the palette on both ecosystems, where it was Java-only.

- **Bennu**: **a stale value in the variables tree says so instead of showing you a different object.** A native debugger's handles are void the moment the program continues and the numbers get reused, so expanding a row from an earlier stop would not fail — it would answer about whatever now holds that number. Each stop's handles are tagged, and one from a previous stop is refused by name.

- **Bennu**: **framework tooling works on a project that is not Java.** Which project owns a file was resolved through the Java symbol index, and that index is only built for a Java project — so on a Cargo root every caret-based framework question silently answered "no project owns this file", and therefore "no framework applies". That took out the whole fulcrum i18n caret surface on exactly the projects it was written for: hover on a label, go to its declaration, completion, the bundle's own markup warnings. The Labels panel worked throughout, because a catalog is asked for by project root and never went through that lookup, which is why this was invisible.

- **Bennu**: **an i18n panel for a fulcrum translation bundle**, on the right beside the editor — <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>I</kbd>, or the button that appears on the editor toolbar on a translation file. It follows the caret: the value you are on, **rendered** — styles painted from `styles.toml`, glossary terms marked, controls shown as what they are rather than pretended to be. Its parameter table lists every placeholder **the label has in any language**, so `en` passing `{amount}` while the Italian never mentions it is visible for the first time, and typing a sample value substitutes it into the preview. Four buttons write markup around the editor's selection — style, glossary, control, placeholder — with the styles and glossary keys offered from what the project actually declares and the control names from the vocabulary the project already uses. A **language picker** lists every declared language, including the ones with no translation yet, and picking one opens the file the translation would go in. On a double-quoted value carrying an escape the buttons are disabled and the panel says why, rather than writing to a byte it cannot locate.

- **Bennu**: **the markup inside a bundle's strings is coloured** — placeholder names, style names, glossary keys and controls, with a tint per construct so nesting reads as nesting. A style or glossary name the project does not declare is marked as you type, not at the next scan: a style that does not exist renders as the default, so the text appears unstyled and nothing complains.

- **Bennu**: **the fulcrum engine's i18n convention is understood.** A project with an `i18n/languages.toml` gets label tooling on both sides of the arrangement: in a `.ron` or a `.rs`, hover on a label shows what it says in every language, who has not translated it and which placeholders it expects, go-to opens the declaration in any language, completion offers the labels that continue what you are typing, and a label **no bundle declares** is a warning — the check that pays for the rest, since a mistyped label is invisible to the compiler and the engine renders the label itself on screen when it cannot resolve one. In a bundle: unclosed markup, a `$style` or `@glossary` entry that does not exist (on the name itself), and a label missing in the fallback language. A new **Labels** panel lists every label with how many places read it and which languages are missing it, expanding into one row per language and one per reading — so find-usages, find-unused and the all-languages check are one list with a filter.

- **Bennu**: **a cargo test runner**, in the same panel the Java one uses. The tree is **crate → target → module → test**, because a row reading `tests::works` is meaningless in a workspace where twenty crates have one — and every level of it runs: the ▷ on a crate row runs that crate, on a target row that target, on a module row everything under it. Rows are there before anything runs and turn green or red as each result lands, a reported case no declaration matches is added rather than dropped (an `#[rstest]`'s generated cases), and `#[ignore]`d tests are opt-in from the header. Runs always pass `--no-fail-fast`, so one broken crate does not silence the other nineteen. Both the run tree and the catalogue are virtualised and results are published in batches, so a workspace with a couple of thousand tests stays responsive while one is streaming.

- **Bennu**: **image files open as a preview** — png, jpg, gif, bmp, webp, ico, avif, tiff and svg, in a tab beside your sources, with fit / actual-size, a zoom ladder on Ctrl+scroll, the pixel dimensions and the file size, and a chequerboard so transparency is distinguishable from black. An image tab has no buffer, so Ctrl+S on one does nothing rather than writing an empty file over the artwork.

- **Bennu**: **the Go-to navigator marks a kind instead of drawing everything the same.** Every row of the Types tab used to be one generic `{}` glyph, so a struct, a trait and an enum were indistinguishable in a list where the kind is the only thing that separates them. They now wear the same lettered ring a Java class does — **S** struct, **T** trait, **E** enum, **A** type alias — and the Symbols tab uses shapes, because there the distinction worth drawing is function against constant against field. The kinds are also **named** in the language's own vocabulary: the protocol has 26 fixed symbol kinds and rust-analyzer has to report a trait as an interface, an `impl` as an object and a type alias as a type parameter, all of which are translated back before they are shown. A `union` and a `static` are not — they arrive as a struct and a constant with nothing to tell them apart, so they keep the protocol's word rather than being guessed at.

- **Bennu**: **the outline works on a language-server file.** The Structure panel and the <kbd>Ctrl</kbd>+<kbd>F12</kbd> popup ask the server, so a `.rs` file lists its structs, traits, impls and functions — with the same icons a Java type and member get, because a Rust `struct` and a Java `class` are the same thing to someone scanning a list.

- **Bennu**: **placeholders in an accepted completion.** <kbd>Tab</kbd> moves between the holes a completion inserted, <kbd>Shift</kbd>+<kbd>Tab</kbd> goes back, <kbd>Esc</kbd> leaves the run — `println!` lands between the parentheses, a function lands on its first argument. Two stops the server marked as the same value are two stops you tab between rather than one that updates the other; nothing half-works.

- **Bennu**: **folding on a server-backed file**, from the server, so it folds by *item*: a `use` block, a doc comment, a `#[cfg]`-gated module, a match arm. A `.rs` file previously had no fold gutter at all.

- **Bennu**: **occurrence highlighting** — every other place the symbol under the caret appears in the file, tinted as you rest on it. A write is tinted differently from a read, because "where is this assigned" is a different question from "where is this used", and it is the one a mutation bug is found with.

- **Bennu**: **expand / shrink selection** on <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>→</kbd> and <kbd>←</kbd> — the token, the expression, the argument list, the call, the block, on the server's own idea of structure. The whole chain arrives in one request, so pressing repeatedly walks a list already in hand.

- **Bennu**: **code lenses** — implementation and reference counts above an item, clickable. Pressing one costs no second query: the server had already found those places in order to count them, and sends the list with the count. Run and debug lenses are deliberately not asked for until the Run console can launch one.

- **Bennu**: **a Hierarchy panel** — call hierarchy on <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>H</kbd>, type hierarchy on <kbd>Ctrl</kbd>+<kbd>H</kbd>, with a direction chip for callers/callees and implementors/supertypes. Expanded one level at a time, which is what makes a recursive call chain displayable rather than a workspace sweep; a caller row jumps to the *call* rather than to the function containing it, and the panel takes the keyboard as it opens.

- **Bennu**: **macro expansion** on <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>M</kbd> — what the macro at the caret generates, in a dialog you can read, copy and re-expand from. - **Bennu**: **Reload workspace** in the command palette — the server re-reads the project's manifests and resolves the crate graph again, keeping everything it has already indexed, which a restart throws away. For what it cannot notice on its own: a `.cargo/config.toml` edit, a vendored dependency changing underneath, a `cargo add` run in a terminal.

The dialog says how many files that will be before you commit, a rename that cannot be performed changes nothing, and the edits land in the editor as one undo step. Refuses to overwrite an existing file; a change of letter case is a rename rather than a collision.

- **Bennu**: **newer-version hints in `Cargo.toml`.** A dependency that is behind gets a line above it naming the release that exists — `↑ 1.0.219 available`, in the accent colour, because an offer you would act on has to survive being glanced past where a reference count does not — and pressing it writes that version in. Quiet by construction: nothing is said about a `path`, a `git` or an inherited dependency, about a deliberate pin or a range, or about pre-releases — a wrong "update available" on a pin is worse than a missing one. Answers come from an on-disk cache refreshed at most once a day per crate, and a failed lookup falls back to the old copy rather than to silence.

- **Bennu**: **add a dependency from the UI.** The Cargo window's **＋** takes a crate name, offers its published versions and the features *that version* declares, picks the table and — in a workspace — the member, then runs the real `cargo add`: cargo writes the requirement its own way, honours `[workspace.dependencies]`, validates the features and formats the entry in the file's style. Afterwards the manifest is re-read and the language server told to resolve the project again. Turning crates.io off (same settings page) keeps this working — cargo picks the version.

- **Bennu**: **a dependency's source no longer starts a language server of its own.** Following <kbd>Ctrl</kbd>+<kbd>B</kbd> into a library opens a file under `~/.cargo/registry/src`, and that unpacked crate carries a `Cargo.toml` — so it resolved as a *workspace root* and got a second rust-analyzer, one per library you looked into, each indexing a crate from scratch and none of them able to say anything about your own code. Those locations are now known (Cargo's registry and git checkouts, the toolchain's `rust-src`, Go's module cache) and a file in one **borrows** the session that already has it open, which is your project's — it has every dependency's source in its graph by definition. A stray session left over from before is shut down when a project opens.

Both of its views read Bennu's own engines — the tree-sitter grammars are Java and JSP, the declaration model is Java's — so there it could only ever report their absence, and "no grammar for Rust" reads as though Bennu did not understand the language while rust-analyzer is answering everything else about it. Naming a language it cannot read is an honest answer only when nothing else is answering. The rail slot holds the Cargo window instead.

- **Bennu**: **a Cargo tool window, and it runs.** <kbd>Alt</kbd>+<kbd>8</kbd> on a Rust project opens the workspace: every crate with what it builds, what features it declares, and one row per cargo command — `check`, `build`, `test`, `run`, `clippy`, `fmt`, `doc` and the rest — aimed at that crate or at the whole workspace. A binary or an example runs from its row; anything else opens its source. Output goes to the same Run console a JVM launch uses, so Stop, ⟳ and the tab strip mean the same thing. Nothing here shells out to `cargo metadata`: the graph is read from the manifests, so the panel opens instantly and opens on a workspace that has never been built.

- **Bennu**: the Cargo panel names **a crate the workspace forgot** — a directory with a `Cargo.toml` that no `members` pattern covers, which compiles when you build it directly and is invisible to `--workspace` — and **a toolchain component that is missing**, because `cargo clippy` without it fails with an unknown-subcommand error that reads as a broken button rather than an absent install.

- **Bennu**: **`Cargo.toml` gets completion and diagnostics.** Completion knows where the caret is: the tables in a `[header]`, the keys of the table you are in (minus the ones already set), `workspace` after a dot on the keys Cargo actually lets a member inherit, crate *names* and *versions* from this machine's registry inside a dependency table, the spec keys inside `{ … }`, the editions and crate types where the set is closed, the features and both `dep:`/`crate/feature` forms inside `[features]`, and the real directories inside `members`. No network — the crate list is what this machine has seen, which is the trade for a popup that appears while you are still typing. Diagnostics cover the two that cost the most: a **key typo** (Cargo ignores it silently, so the dependency you added is simply not there) and a **feature referring to something that does not exist** (Cargo refuses the manifest, and the usual cause is a rename) — plus `workspace = true` with nothing behind it, a `path` or a `members` entry with no crate there, conflicting dependency sources, and a duplicate key. Red is reserved for what Cargo genuinely refuses to build; an unknown key is a warning, and a table Bennu does not recognise is not commented on at all.

- **Bennu**: **the Dependencies panel answers for Cargo too.** One panel, one report shape, the same four questions — what it is, which version you are *really* getting, who decided that, and whether it is actually there. The version shown is what `Cargo.lock` chose rather than the requirement you wrote; a `workspace = true` dependency is marked as pinned by the workspace, exactly as a Maven `<dependencyManagement>` entry is; a renamed one shows both names, and a target-specific one carries its `cfg(…)`. With no lockfile it says the versions are *unknown* instead of showing them as missing. The last group is everything in the lockfile no crate of yours declared.

- **Bennu**: a **Cargo run configuration** — a crate, a command, a target, features, a profile, and two argument fields kept deliberately apart (cargo's own flags before the `--`, the program's or the test harness's after it). Everything but the arguments and the working directory is a picker, because the workspace already knows its crates and their targets. ▶ and <kbd>Shift</kbd>+<kbd>F10</kbd> now work on a Rust project, and on a workspace with exactly one binary they need no configuration at all: pressing ▶ makes one and runs it. 🐞 stays JVM-only.

For a `.rs` file in a Cargo workspace that means the whole editing surface — completion (with the `use` line an auto-imported item needs), <kbd>Ctrl</kbd>+<kbd>B</kbd>, find usages, hover, rename, quick fixes under <kbd>Alt</kbd>+<kbd>Enter</kbd>, `rustfmt` on <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd>, go-to-type and go-to-implementations, workspace symbols, and the compiler's real diagnostics (types, borrows) from `cargo check` on save. The server does the matching, so it starts at two characters — a workspace is too large to hand over whole.

In Rust that is the difference between one colour for every capitalised name and a struct told apart from a trait, a macro from a function, a `mut` binding from an immutable one, a parameter from a local, and an escape sequence from the string around it. Layered rather than swapped, so a file is never plain text while a request is in flight or when the server is down.

Settings → **Language Servers** lists each one with the path it resolved to or — when it found nothing — how to install it, and shows what is running, what it is doing, and the server's own stderr when it refused to start. Clicking it opens the settings page that can fix it.

- **Bennu** (Java editor): **message bundles are a model, not a pile of files.** Half of what a legacy web app shows a user is in a `.properties` file, reached by a string, checked by nothing — and Struts renders an unresolved key as the key itself, so the typo ships. <kbd>Ctrl</kbd>+<kbd>B</kbd> on a key opens the line that declares it, one entry per language with what each one says; hovering shows the same without leaving the page and names the locales that do not have it yet; typing inside a key attribute completes from the bundles; and a key **no bundle declares** is underlined where it is written. A **Messages** panel lists every key with its text, how many places read it — `unused` when the answer is none — and which locales are `missing` it. What counts as a key is recognised by shape (an attribute called `key` or ending in `Key`, the `name` of an `<s:text>`, the first argument of `getText`/`getMessage`/`getString`), so `<fmt:message>`, `<bean:message>`, `<wp:i18n>`, a validator's `<message key>` and an action's own lookups are all found; a computed value (`%{keyName}`, `${row.label}`) is deliberately not treated as a key at all.

- **Bennu** (Java editor): **the Endpoints panel is about URLs, not about Spring.** A Struts `<action>` is a route in every sense a `@GetMapping` is one, and an application mid-migration answers through both — so they are now one list. An action arrives as its URL (the package namespace joined to the action name) with its `class` bean id resolved to the class that actually runs, and expands into the whole request: the interceptors it declares for itself, then each `<result>` with the page it finally reaches — `admin.Cat.tree → /WEB-INF/jsp/tree.jsp`, because following a Tiles definition by hand means the action fragment, then `tiles.xml`, then the parent it extends. Clicking a result opens the page. A `chain` or a redirect names another action rather than a view, and says so.

- **Bennu** (Java editor): the **Trees** panel reads **JSP** — both tabs. *Syntax* shows the real parse, from the same grammar that is colouring the file in front of you, so the panel and the colours can never disagree about what it is. *Model* shows the page in JSP's own vocabulary: the libraries it declares and what each `uri` resolved to, the tags with the library each came from, their attributes with the type the TLD gives them, the expressions and the scriptlets. Three things the parse cannot show and this does — the **nesting** (the grammar is deliberately flat so unbalanced markup keeps colouring, and the model pairs the tags up tolerantly), the **library** a tag belongs to (a prefix nobody declared says so, which is the most common reason a taglib "stops working"), and which values are **expressions** (`value="%{codice}"` and `value="Codice"` are the same shape to a grammar and opposite things to a reader). Page text is left out on purpose.

- **Bennu** (Java editor): **structural search runs over JSP.** A legacy Struts codebase keeps as much of its logic in pages as in classes, and a text search is even weaker there than over Java — the same tag is written across four lines as often as one. A picker beside the query field chooses the language; `<s:property $pre...$ value="$x$" $post...$/>` with `group $x$` counts every property the pages print. The language is asked rather than guessed, because a pattern compiled against the wrong grammar does not fail loudly — it matches nothing, which reads as "the project contains none of this". The Templates menu offers page queries when JSP is selected, and the `#`-completion offers the page grammar's node kinds.

- **Bennu** (Java editor): **EL and OGNL expressions are parsed, not treated as one block.** `${…}`, `#{…}` and `%{…}` used to be single tokens with a small lexer bolted on for colour, which was enough for highlighting and enough for nothing else — a structural search could see *that* there was an expression and nothing inside it. Now a **path** (a name and what is read off it — `#session.currentUser`, `items[0].price`, `fn:length(items)`) is a construct of its own, with operators, literals and spacing beside it. So `%{$pre...$ #session.$prop$ $post...$}` with `group $prop$` is every property the pages read off the session, wherever it is written and however it is spaced; the syntax tree shows the structure; and the `#` of a context reference is coloured apart from the name, because it means precisely "not a property of the action". Deliberately not a precedence tree: what anyone asks of a page is the paths, and every character between the braces is consumed by *something*, so an expression can never fail to parse — and it stops at the next tag, so an unclosed `${` (the state of every line while it is being typed) does not swallow the rest of the page.

- **Bennu** (Java editor): structural search gained a third language — **Java in JSP**. The query is Java, the files walked are the pages, and what is matched is the contents of their `<% … %>`, `<%= … %>` and `<%! … %>` blocks. It exists because of what a JSP query cannot do: to the page grammar a scriptlet is a *single token* — deliberately, since a `<` inside Java is not markup — so a page query can see that there is Java there and nothing about it, while a legacy page keeps a great deal in scriptlets. `session.getAttribute($key$)` with `group $key$` is every key the pages read out of the session, one row each. Each block is lifted out and wrapped in the smallest legal Java that makes its kind parse (statements, members, or an expression), then matched and mapped back, so a hit's line, preview and click land on the code as written and never on the scaffolding. Type constraints report *undecided* there — a lifted scriptlet is in no file, and that is this tool's word for "unknown".

- **Bennu** (Java editor): **go-to follows the Struts attributes that are expressions without saying so.** `<s:iterator value="comunicazioni.dati">` and `<s:if test="showRiferimento">` carry no `%{…}` and are OGNL all the same — the wrapper is only needed on the attributes Struts declares as strings, which is backwards from what a reader expects and is why so much legacy markup has none. <kbd>Ctrl</kbd>+<kbd>B</kbd> now lands on the property, per segment, for the tags of a library the page bound to Struts and the attributes Struts actually evaluates; `<c:if test="…">` is JSTL and is left alone. The *warning* deliberately stays on `%{…}` only: a go-to that resolves nothing does nothing, while a warning is a claim.

- **Bennu** (Java editor): **inside an `<s:iterator>` the value stack is deeper, and Bennu knows it.** The tag pushes the current element on top, so `%{codice}` written underneath it is a property of *that element* before it is anything of the action's. Go-to resolves top down — innermost element, each enclosing one, then the action — stopping at the level that actually declares the name, and a nested loop's own expression is read against its parent's element. A page variable declared inside a loop (`<s:iterator value="celle" var="cella">`) is typed the same way instead of against the action.

- **Bennu** (Java editor): **JavaScript inside a JSP is read as JavaScript.** Object keys, member accesses and call sites are each their own colour, numbers in every form are numbers, template literals colour their `${…}` holes as code, `this` stands out, and a regular expression is told apart from a division — which is what keeps one `/` from painting the rest of the line as a literal. Previously the `<script>` body got keywords, strings and comments and nothing else, so a line of jQuery came out almost entirely flat. It also treats the body as what it is — a **template that produces JavaScript** — so scriptlets, `<%= … %>`, EL/OGNL and whole taglib tags are recognised as JSP, **including inside a string**: `errore = "<wp:i18n key="X" />";` read as plain JavaScript has its string closed by the tag's own quote and everything after it coloured wrongly. The same tokenizer colours a standalone `.js` file.

- **Bennu** (Java editor): **the tag libraries a JSP declares are read.** A legacy page is mostly not HTML and mostly not Java — it is `<s:…>`, `<c:…>`, `<wp:…>`, a vocabulary written down precisely in `.tld` files that ship inside the frameworks' own jars, and that no editor was opening. Now: `<s:` **completes** that library's tags, a tag completes its own attributes minus the ones already written, and a `uri="…"` completes from every library the project can resolve. **Hover** carries the TLD's own prose — the description, the attribute's type, whether it is required, whether it takes a runtime expression — which on a library of that era is often the only documentation in existence. <kbd>Ctrl</kbd>+<kbd>B</kbd> on the `uri` **opens the TLD**, including one inside a jar (it is extracted and opened like a decompiled class); on a tag name it lands on its `<tag>` declaration, on an attribute name on the `<attribute>`. And the **checks**: a tag the library does not declare, an attribute it does not have, a required one that is missing, a `uri` nothing on the classpath ships. Each is silent where it cannot be sure — a project whose dependencies have not resolved reports nothing rather than everything, a prefix the page never declared is never flagged (it comes from an included fragment, invisible from the page), and a tag with `dynamic-attributes` or one written as a `.tag` file has an attribute list that is *unknown* rather than empty. A `.tld` is itself edited with completion and checks, against a **built-in** tag-library grammar covering both the 1.1 and 2.1 spellings: a TLD names its schema at `java.sun.com` and the only copy lives in a servlet container's jars, so the file that defines a project's whole tag vocabulary was the one XML file with no vocabulary of its own.

- **Bennu** (Java editor): **`.dtd` files are highlighted** — and the `.ent` / `.mod` fragments a large one is split into. A DTD is not XML (`<!ELEMENT` is a malformed tag to an XML highlighter), and it is what the `struts.xml`s, `web.xml`s and `.tld`s of a legacy project are written against, so it read as a wall of plain text with the occasional stretch of red. The declarations, the name each one *declares*, and the parameter entities (`%common;`) that a real DTD is mostly made of now each read apart.

- **Bennu** (Java editor): **structural search & replace** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>M</kbd>) — find code by its *shape* rather than its text, count it, and rewrite it. The pattern is Java with `$holes$` in it, parsed with the same grammar as the file, so line breaks, spacing and comments in the middle take no part in the match — and because each hole is captured, a replacement can move its parts, which no textual find/replace can do at all (`assertEquals($msg$, $a$, $b$)` → `assertEquals($a$, $b$, $msg$)`). A hole can be constrained by **type** (`$x: com.acme.Order+$`, subtypes included), by grammar node (`#string_literal`), by a glob on its text (`~get*`), or by the negation of any of those. Three clauses follow the pattern: **`or`** for the same question in another shape (a call and its method reference, counted together and de-duplicated so one place is one hit), **`in`** to scope it, and **`group`** to turn the answer from a list of places into a **table** — by a capture ("which methods, how often each"), by file, by module, or by **`enclosing`**, which answers "which of *my* methods do this" and cannot be written any other way. **`use of $m$ on <Type>`** is the shortcut for a whole API census, and the panel shows the patterns it expands to rather than hiding them. Replace is always two steps — a preview of every file's before and after, then apply, refusing anything that changed in between — and a template naming a capture the pattern does not bind is refused before a single file is read. **When the classpath cannot decide a type, the hit is kept and marked undecided rather than dropped**: a filter that silently excluded what it could not read would report "used 12 times" where the truth is "12 I could confirm, and 380 I could not read". A literal pre-filter means a typical query parses a tenth of the project; one made only of holes says *whole-project scan* in the field before you run it. Full manual under **Structural search** in the docs.

- **Bennu** (Java editor): the tree panel gained a second tab — **Model**, the *AST*, beside **Syntax**, the parse. The same file read in Java's vocabulary and all the way down: types, members, and the **bodies** — every statement and expression as `if`, `for each`, `call`, `local variable`, `binary` rather than as the grammar's node names. Four things separate it from the parse and all four are the point: the punctuation is gone; the wrappers are unwrapped (a call statement is a call, `(a + b)` is an addition); every child says what part it plays — `condition`, `then`, `receiver`, `argument`, `returns`, so a signature is *rows* with their own spans rather than a rendered string; and the **resolved type** is shown, which a parse tree cannot hold at all — `conn : java.sql.Connection`, and `Files → java.nio.file.Files` with an arrow where a bare name turns out to be a class rather than a value, which is the static-versus-instance distinction made visible. Modifiers get their own column, and a member nobody wrote is marked *generated* (a record's accessors and canonical constructor) with selection going to the declaration that owes it. Nothing is dropped silently: a construct the lowering has no entry for keeps its grammar name and its children. Types need the classpath, so on a project still indexing the tree is complete and untyped rather than absent. Both tabs filter, follow the caret and select back into the editor the same way, and each says in its own words when it cannot read a language.

- **Bennu** (Java editor): structural search can ask what a name **denotes** — `$x: @type$` for a static access, `$x: @value$` for an instance one. `orders.total()` and `Orders.total()` are the same shape to a grammar, so no pattern could separate them: the difference is not in the syntax, it is in whether the receiver resolves to a class or to a variable, and that is a question for the resolver. Constraints can now be joined with `&`, which is what makes the axis usable on one hole rather than two: `$o: @type & java.nio.file.Files$.$m$($a...$)` with `group $m$` is the census of which `Files` statics a project uses and how often each. A plain type constraint stays deliberately blind to the distinction — `$o: Order$` admits both, because in both the type in play is `Order` — and a receiver the classpath cannot reach comes back undecided rather than as "not a type". The query field completes `@type` / `@value` wherever a constraint can go, and colours the operators apart from the names they act on.

- **Bennu** (Java editor): a **Syntax tree** tool window (<kbd>Alt</kbd>+<kbd>9</kbd>, right rail) — what the parser actually built out of the buffer in front of you. It answers one question, *why did it read it that way*, so the commas and the keywords are shown by default: they are noisy and they are very often the answer. It follows the buffer rather than the file on disk, because the moment you want the tree is the moment you have typed something that parsed unexpectedly. Selection travels both ways — clicking a node selects its bytes, moving the caret opens the tree down to what holds it **and scrolls to it**, since a node revealed below the fold is a reveal you cannot see — each row names the field a node fills in its parent, an invented node is marked as one, and a walk that stopped early says so instead of implying the file ends. It draws whatever Bennu has a grammar for, and for a file it can read but not parse it says which language by name rather than showing an empty panel. It is Picus's syntax-tree panel, now shared rather than copied.

- **Bennu** (Java editor): **Go to** and **Find in project** can reach inside the **dependency jars** — the framework annotation whose package you were trying to remember, the `struts-default.xml` that declares the interceptor stack, the schema an XML file is validated against. On a legacy project that is most of what you need to read and none of it is in the tree. A **Source** picker on the header row of <kbd>Ctrl</kbd>+<kbd>N</kbd> / <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd> and <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> says whose code you are looking at: **Project**, **Dependencies**, or **Project & dependencies** — which ranks the two into one list rather than making you check two places for one question. *Dependencies* alone is the one a toggle could not express, and it is what you want when the answer is a schema or an interceptor stack some artifact declares and every hit in your own tree is noise. Every row names where it is from — the module for something this build compiles, the **artifact** for something it only depends on, because a classpath is where four versions of the same name live — and rows you cannot edit are **tinted**, so a read-only answer is never mistaken for one you can go and change. Opening a class shows its source the way a stack-trace frame already does; opening a file extracts it read-only, keeping its extension so an XML still reads as XML. Classpath rows are searched as you type rather than listed — it is hundreds of thousands of entries — so they cost nothing until there is a query. **Search the dependencies too** (Settings → Java) now moves the *default* rather than deciding whether any of it is reachable. Text read out of a jar is decoded the way the JVM reads it — a `.properties` in a library is ISO-8859-1 by specification — so an accent in a message survives instead of arriving as a replacement character, and a search for one finds it.

- **Bennu** (Java editor): a **debugger**. 🐞 (<kbd>Shift</kbd>+<kbd>F9</kbd>) launches the active run configuration with a debugger attached; click the left margin — or <kbd>Ctrl</kbd>+<kbd>F8</kbd> — to set a breakpoint. The margin only offers one where the program can actually stop: a breakpoint is a position in bytecode, so a package statement, an annotation, a signature, a bare field declaration, a comment or a lone brace get no dot at all rather than a click that silently lands three lines further down. Breakpoints belong to the project rather than to a session: they are kept in `.arbor/bennu/config.toml` beside the run configurations, they follow the lines they are on as you edit above them, and the dot says whether the VM accepted one, is still waiting for its class to load, or is disabled. It all happens in the **Run** console rather than in a second tool window: debugging is the same launch with more to look at, so the panel grows the transport controls while a session is attached, and — while the program is stopped — two columns beside the transcript with the frames that got there and the variables in the one you select (arguments, locals and `this`, expanding into fields and array elements) with your watches underneath. A watch is a path like `order.customer.name`, not an expression language. Stepping is <kbd>F8</kbd>/<kbd>F7</kbd>/<kbd>Shift</kbd>+<kbd>F8</kbd>; <kbd>F9</kbd> resumes. A step passes straight through the JDK, Spring's AOP machinery, Reactor and the logging façades instead of stopping inside `ArrayList.add` or walking `ReflectiveMethodInvocation.proceed` a dozen times — and when it lands in a **proxy**, whose methods exist only at runtime, it keeps going rather than stopping in a class whose source has never been written. Stepping into `service.place(order)` arrives at `place`. Which packages a step skips is editable in **Settings → Debugger** — remove `org.springframework.*` to step into Spring itself. **The editor follows the debugger** — every stop and every step opens the frame's file at its line and scrolls to it, so stepping into a method changes the tab for you. Runs of library frames fold into one expandable row (a stop inside a framework is forty frames of Spring around the three that are yours). <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F8</kbd> lists every breakpoint in the project to disable or remove, and is where **exception breakpoints** are added — stopping where a throwable is thrown rather than where it is caught, which has no line to click. ⊘ **mutes** them all at once: still set, still listed, not installed, so the run reaches its end at full speed. Both columns resize and collapse, and where you left them is remembered. **Bennu comes to the front when the program stops** — a breakpoint fires because of something happening in another window — but not on a step, which you did here. A launch does not begin frozen unless the configuration asks it to, and detaching leaves the program running.
- **Bennu** (Java editor): the Run, Build and Test consoles **read the output instead of just printing it** — the level, timestamp, thread, logger, exception, URL and path in each line are recognised and coloured, so the line that matters is findable without reading the ninety around it. **Stack frames are links**: a frame in a class this project declares opens that file at that line, and so do paths (with the `:42` a compiler appends) and URLs. A frame in the **JDK or a dependency** opens that class's source view — the real `.java` when the JDK ships sources or a `-sources.jar` has been downloaded, otherwise the decompiled stub, landing on the method the frame named since a stub's line numbers mean nothing. Those frames are drawn muted, so your three lines stand out of Spring's forty; a frame naming something made at runtime (a lambda carrier, a proxy) is marked but not a link, because no source for it exists anywhere. A stack trace inherits the level of the error above it, including across `Caused by:`, and a routine `INFO` a program wrote to standard error is no longer painted red along with the whole stream.
- **Bennu** (Java editor): **running your application happens in Bennu** — a **Run console** (<kbd>Alt</kbd>+<kbd>R</kbd>) with the program's own output, separate from the build log the two used to share. It opens with the command that actually ran (pasteable into a terminal), you can **type back to the program** — stdin is a pipe, so something that stops at a prompt can be answered instead of appearing to hang — ANSI colours are rendered rather than printed as escape codes, and it ends with the exit code and how long the run took. **One tab per run**, so launching again does not throw away the transcript you were reading; the input line starts collapsed, since most programs never read one.
- **Bennu** (Java editor): the title bar says **what ▷ will run** — a selector left of the run buttons showing the active configuration, opening the list grouped by category. Picking one makes it active; it does not launch it.
- **Bennu** (Java editor): a run configuration says **which module it is for**, and running one on a multi-module project works. The classpath was built from the project root, which on a reactor is the one directory that compiles nothing — so a class in a module ran against an empty classpath. It is now that module's `target/classes` first, then every other module's (so a call into a sibling resolves without `mvn install` first), then the dependencies, resolved from the module's own pom. The module is the first field of the configuration, picking a main class fills it in, and both the editor's list and the title-bar selector show it.
- **Bennu** (Java editor): a **Spring Boot configuration does not need its main class** — left empty, it starts the module's `@SpringBootApplication`, which a Boot module has exactly one of. Pressing ▷ on a project whose only entry point is a Boot application now creates a Spring Boot configuration rather than a plain one, so its Profiles field is there the first time you look for it.
- **Bennu** (Java editor): run configurations have **categories**. Adding one asks what kind first and the editor's list is grouped the same way: **Application** (a `main` class), **Spring Boot** (the same, plus its active profiles as `-Dspring.profiles.active`, with the profiles the project declares detected from its own `application-<profile>` files and the field still free text), and **JUnit** (a test scope — the whole project, a module or a class — which runs through the test runner and lands in the Tests panel). Spring Boot is offered only where the project has Spring. Configurations written before categories existed read back as applications.
- **Bennu** (Java editor): **run configurations are real** — named launch targets with a main class, program and VM arguments, a working directory and environment variables, stored per project in `.arbor/bennu/config.toml` so they survive a restart. The main class has a picker listing every entry point in the project instead of asking you to type a fully-qualified name, and on a project with exactly one entry point ▷ just runs it: no configuration to create first. VM arguments, the working directory and the environment are now actually passed to the program — they were being collected and dropped.

- **Bennu** (Java editor): a **unit-test runner** — run the whole project, a Maven module, a folder, a class or a single method, from the new Tests panel (<kbd>Alt</kbd>+<kbd>5</kbd>), the project tree's context menu, the ▷ menu, the palette, or <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F10</kbd> for the test at the caret. Results stream in class by class while the run is still going, with the failure message and stack trace beside the tree, filtering to failures, sorting by duration, and rerun / rerun-failed. What counts as a test is read from the sources — JUnit 5, 4 and 3, and TestNG — not from file names, so a `TestCase` subclass is found and a `*TestUtils` helper is not.

- **An AI client can work on a project you do not have open.** Scope was already about projects you have opened rather than about what is on screen, but the engines behind it were not: the first call now opens the project properly — manifest, frameworks, language server — with no window and no backend needing to be up first. What that costs is a language server, so one with nothing on screen behind it runs lean: it analyses a crate when a question needs it instead of indexing the whole workspace up front, keeps a bounded cache and takes two threads rather than every core, while the settings that make code resolve at all are left exactly alone. It is also stopped once it goes quiet, after a delay you choose under Bennu's language-server settings — five minutes to an hour, or never. A server for a project you have open is never stopped this way, and one started for a client and then opened in a tab stops being reclaimable from that moment.

- **An assistant can map a workspace before changing it.** A new tool reports a project's own modules — which crate depends on which, how deep the stack is, where the dependency cycles are — and, for each, how much of the project it is built on and how much rebuilds when it changes. That last number is the one worth having before proposing a change to something shared: a leaf with a high one is not a leaf. Read from the manifests only, so it answers on a project that has never been built, and it works on a Maven reactor as well as a Cargo workspace.

- **An assistant can see what a project is behind on.** One call sweeps every manifest in a Cargo workspace — the root's shared version table included, which is where a workspace that inherits its versions writes nearly all of it — and reports the dependencies with a newer release on crates.io, each with the file and line to change. A second lists what a crate has actually published, so a proposed bump is checked against reality rather than guessed. Quiet about what it cannot know: path, git and inherited entries have no version there to be behind, and a deliberate pin is left alone. Anything it could not reach is counted and said out loud instead of passing as up to date.

- **An assistant can compile the project and read the errors.** Checking a file answered from whatever the language server last published — which is the last check *your editor* ran, on the file *as you saved it* — so after an assistant edited something, nothing could tell it whether the edit compiled. Now it can run the compile itself and get the diagnostics back, each at its file and line, errors first. Name a crate or a Maven module to compile just that, which on a large workspace is the difference between a check you wait out and one you read. It needs your approval, because compiling runs code the project supplies — build scripts, proc macros, Maven plugins. A failure that produced no diagnostic carries the end of the compiler's output rather than reporting only that it failed.

### Fixed

- **Go-to in a shader no longer jumps to where the caret already is.** With the caret on a declaration, go-to answered with that declaration's own span — which reads as a broken feature, and worse, it won before the framework extensions could answer. It is what kept a shader `struct` from ever reaching its Rust layout.

- **A hardcoded bind group in a shader is no longer reported as the wrong one.** Which number the material's bind group is depends on the Bevy release and on the kind of material — it has been 1, it has been 2, and a `MaterialExtension` on 0.18 writes 3 — so pinning one of them reported twelve correctly-bound textures in a real shader as missing. What is stable is the other end: group 0 is the view and group 1 is the mesh, in every version. A literal 2 or above is now taken as the material's, which still keeps a uniform at binding 0 from matching the view's uniform at binding 0.

- **Opening a product no longer crosses two different loading screens.** The container showed a spinner labelled "Starting Bennu…" while the backend came up; the moment the shell mounted, a second, unlabelled spinner took over for the code — so one action produced two screens and the visible effect was a spinner that sometimes had a name under it and sometimes did not. It is one screen now, carrying the product's own icon, name, role and colour, with only the line at the bottom changing as the phase does.

- **The Bevy catalogs are not grey any more.** Every badge in them — `Component`, `Resource`, `Message`, `read`, `write`, `unordered` — fell through to the neutral colour, which in the one panel where the badge *is* the information made it a column of grey. Roles are coloured by what they are and accesses by what they cost: a write takes the strong colour, because it is what serialises systems and what a conflict is made of; a filter stays muted, because it reads nothing.

- **Bennu remembers where you put its panel dividers.** The left tool window, the bottom dock and the right rail kept their size until the window closed and then forgot it — Arbor's shell and merula have persisted theirs for a while. Stored as a viewport ratio, so a divider a third of the way across stays there on a different screen. The i18n panel keeps its own slot: it is given a wider default than the tool windows beside it, and one shared size meant opening it resized Maven.

- **RON files are readable again, and so is every other legacy-mode language.** A `.ron` rendered as a wall of white because the token its mode emits for a constructor — `Sequence(`, `Single(`, `Sphere(` — was `variable-3`, a CodeMirror 5 name that CodeMirror 6 has no entry for and silently resolves to nothing. Constructors and bare variants are types now, and colour like types. The same dead name was in the JavaScript mode (`new Foo`, `Promise`, `Math`) and the DTD one, so those were unstyled too.

- **A `.docx` had two toolbars.** The editor's own bar was skipped for an image and not for a document, so the file name appeared twice above a viewer with nothing to act on. The guard is on "opens as a preview" now rather than on "is an image", which is the thing that was actually meant. The read-only marker is also a badge rather than the quietest grey word in the row — it is the one fact that changes what you can do there.

- **Bennu's terminal knows which shells you have.** Shell detection ran when Arbor's shell started and nowhere else, so a Bennu window opened on its own offered a shell picker with nothing in it until you happened to open Arbor. Both windows now ask through one idempotent call, so opening the second does not start a second detection.

- **Opening Bennu no longer starts a language server for every project in the workspace.** A workspace restore opens each member to read its manifest, then puts exactly one on screen — and each of those opens was warm-starting rust-analyzer, so a five-project Cargo workspace launched five of them, indexing in parallel, for four projects nobody was looking at. Only the project you land on starts one now; the others start when you switch to them, or on the first request against one of their files.

- **Hover cards work on shaders.** Go-to and find-usages are routed by file path and were fixed; hover and completion are language-descriptor hooks and `.wgsl` had neither, so the card never appeared even though the backend had an answer ready. A language Bennu serves itself now gets the same two hooks every other language uses.

- **Go-to, find-usages, hover and compiler diagnostics work on shaders again.** Adding `wgsl-analyzer` to the language-server catalogue made `.wgsl` a served extension, and a served extension stopped every request at the server — including on the overwhelming majority of machines where that server is not installed, where there was no server to answer. A catalogue entry whose binary is not there no longer claims the language: the file falls through to what Bennu can do for it by itself. A server that is merely *starting* still owns its files, which is the case that rule exists for.

- **WGSL no longer reads as a wall of white.** Struct members, parameters and annotated bindings are coloured as the declarations they are, a call reads as a call, punctuation recedes, and a multi-line `#import bevy_pbr::{…}` is marked as the directive it is instead of having its body parsed as code in your file. The underlying cause reached further than WGSL: the `builtin` token every legacy syntax mode emits — `textureSample` here, `echo` in a shell, `count` in SQL — was not styled at all, so every standard library in the app rendered as ordinary text.

- **A language server you never installed no longer sits in the running list as "failed".** It was reported once per open project, each row offering a Restart that could only fail again — which is the same fact the Language Servers page already states, with an Install button beside it. Bennu still remembers that it looked, so opening a file does not re-scan your `PATH`, and forgets it the moment something could have changed the answer: an install, or saving the settings.

- **Tree rows collapse by clicking their chevron.** The chevron was decoration: only clicking the row body toggled a node, and panels where a click means "select this" — the test results, where clicking a test opens it — had no way to collapse anything with the mouse at all, short of "collapse all". The chevron now always toggles, whatever the row's click does.
- **A Cargo project's tests no longer wear JUnit's badge.** The Run panel, its Tests tab and the test catalogue showed the JUnit 5 mark regardless of the project, so a workspace of `#[test]`s was labelled with a Java framework it has nothing to do with. All of them now follow the project, the way the rail button already did.
- **The empty Run Configurations panel no longer adds the wrong kind.** Its "Add configuration" button created a Java Application whatever the project was, so on a Cargo project it made a configuration of a kind that isn't even offered — while the `+` above it correctly asked which kind you wanted. Both now open the same menu.
- **Rust tooling works in the installed app, not just when Arbor is started from a terminal.** Building, checking, running tests, reading the toolchain — everything that shells out to cargo looked for it on `PATH`, and an app launched from Finder does not inherit the shell's `PATH`, so `~/.cargo/bin` was missing and every one of them reported "cargo not found". It now resolves cargo and rustup where rustup installs them, and still falls back to `PATH` for installs that live elsewhere. The failure only ever appeared in the shipped build, which is why it survived this long.
- **The AI activity log no longer takes the window down with it.** Opening it a second time could crash the whole overlay with a duplicate-key error: two Arbor instances sharing a profile each rewrite the log file whole, so it could come back holding one call twice — once finished, once as it looked while still open. Duplicates are now collapsed where the list is read, keeping the copy that still knows something (a finished row over an interrupted one, the one that collected more progress between equals), and a log that disagrees with itself costs a row instead of a screen.
- **Tyto no longer dies on a Mac that refused screen recording.** The capture library turns the OS's refusal into a panic instead of an error, so simply opening the recorder — which lists what there is to capture — took the thread down and left the window blaming a timeout. The refusal now arrives as what it is, and the source picker says so in place of the displays it can't see, with where to grant it and the fact that macOS only applies the grant to the next launch. Previously the picker filled with placeholder devices that didn't exist, which made a permission problem look like a broken app. Arbor now asks for the permission itself, when you open Tyto — the moment you've said what you want it for — instead of leaving it to a background process at whatever moment it first looks around, and the picker offers a button straight to the right System Settings pane, since macOS never asks a second time.
- **"I granted it and it still says no" now says which one it is.** A refused screen recording has several causes that look identical from inside the recorder: the grant hasn't reached this process yet, it belongs to a different build, or macOS credited it to whatever launched Arbor — a terminal, if that is how it was started, which is why terminal emulators turn up in that permission list at all. Arbor now reports what it can see from its own side and names the likeliest one, instead of repeating the same instructions that already didn't work.
- **The macOS window buttons sit in the middle of the title bar.** They were riding high in it — the offset was a hand-tuned number resting on a wrong idea of how tall a window button is, so it missed by the same amount everywhere and the compact title bar inherited the standard bar's value on top of that. The offset now follows from the bar's height and the button's real size, and the cluster sits at macOS's own distance from the left edge instead of an indent chosen to look roomy — which had it landing further in than every native window beside it.
- **Tyto's settings read like the rest of Arbor.** The dialog was a flat list of labels and controls with nothing tying a row to its group, and it looked nothing like the capture panel it duplicates — the same decisions, in two visual languages, so you had to work out whether they were even the same settings. Both now use the shared settings row: a tinted glyph, the label over its explanation, the control on the right, grouped into banded cards. Screen-recording permission is a section there too, with the button to the system pane, because that is where you go looking for a permission.
- **"Save to" showed a Windows path on macOS and Linux.** The output folder defaults to wherever the OS keeps videos, and the frontend was displaying a hard-coded `C:\Users\…` guess instead of asking where that is. It now shows the real folder — and still records "the OS default" rather than freezing today's path into your config.
- **Recordings show how long they are.** The library had a duration for screenshots (none) and, once sequences arrived, for those — but never for a video, so the one kind of capture whose length actually matters was the one that didn't say it. It is read from the file's own header, so it also appears for videos that were already there.
- **JPG and WebP screenshots showed up in the library.** The format setting saved them correctly, but the library only ever looked for PNG, so anything else was invisible there — the file was on disk and nothing said so.
- **“Clear” in the captures library said it kept your files.** It deleted them, and always had. The button is now **Delete all** and says what it does.

- **An empty answer about Rust no longer reads as a verdict.** Find-usages, the per-file check and the symbol search all answer for a Rust project through rust-analyzer, which spends its first half-minute loading the workspace and returns *nothing* while it does. Their notes said the opposite — that a Cargo project has nothing still building — so "no usages" arrived as a confident fact at exactly the moment it was a wait, which for find-usages is the difference between a method being unused and not being looked at yet. Each now says which of the two it is, quoting the server's own progress, and distinguishes a server that is still loading from one that is not installed from one that has genuinely answered. Symbol search says plainly that it reads an index only Java projects build, instead of advising a caller to wait for one that will never arrive.

- **A Bevy catalog an assistant could reach but never knew about.** The framework catalog tool has always been able to list the pairs of systems that contend over the same component or resource — the ones that can never run in parallel, tagged with whether anything in the project orders them, which is where a frame-order dependency nobody wrote down shows up. Its description did not mention it, and a model does not ask for what it has not been told exists. The description now names it, along with every other catalog worth asking for by name, and points at the overview call whose own output lists them all — so the list stops being one kept in step by hand.

- **An AI client can write a project file without corrupting it.** Reading was exposed and writing was not, which was worse than exposing neither: legacy sources are frequently Cp1252, so a client would read one correctly through Bennu, edit it, and write UTF-8 bytes back over every accented character — a corruption that reads back fine to the client and is wrong for everyone else. Writes go through the user's approval like any other change, and carry the same stale-file guard the editor uses, so a save is refused rather than overwriting work done underneath it.

- **A project scope where each product answers for itself.** *What each product has open* is a scope mode of its own: under the pooled "open projects" a repository you only ever opened in Corvus was reachable by Bennu's file-reading tools, which is not what opening it in Corvus meant. Here the grant matches the act — you opened this in Bennu, so Bennu's tools may work on it, and nothing else gained anything. A product that records no projects has an empty scope, and its refusal says which of the two ways it is out: not open anywhere, or open somewhere else.

- **Bennu**: **an installed build had no backend at all.** `bennu-be` was never copied into the bundle, so an installed Arbor served the Bennu window from the shell and answered every one of its requests with "backend not running" — projects would not open, workspaces never reached disk, and the whole thing looked like a persistence bug because the workspace list is the one piece of state the frontend holds on its own. It ships now, as does `tyto-be`, which was in the same state.

- **Bennu**: **the window notices its backend arriving.** The backend is spawned as the window opens, so the loads that need it could run first and then nothing asked again — which on a slower machine (or a release build) was the whole session. It now re-reads its settings and its workspaces when the backend announces itself, the same way Picus and Sitta already did.

- **Every product**: **switching profile no longer leaves the backends on the old one.** Each product backend resolves the active profile once, at startup, and only Corvus's was told about a switch — so after changing profile Bennu would have written its workspaces, and Sitta, Picus and Garrulus their state, into the profile you had just left. They are restarted onto the new profile now.

- **Bennu**: **the <kbd>Alt</kbd> shortcuts work on macOS.** Option composes the key it is held with — Option+Shift+M is `Â`, Option+1 is `¡` — and the bindings compared the *character*, so the entire Alt family silently did nothing on a Mac: expand macro, format, and every Alt+digit tool toggle. They match the physical key now, which is also layout-proof on IT/DE/FR/ES keyboards.

- **Bennu**: **workspaces persist, including in a release build.** A restore that could not reach the backend was indistinguishable from an empty store, so the next write overwrote a real `workspace.toml` with nothing — workspaces looked like they were created, projects would not stick, and closing the window lost the lot. Release builds hit it far more often because the backend is spawned lazily as the window opens and that spawn is slower there. Nothing is written now until the file has actually been **read**, the read is retried while the backend comes up, and closing the window flushes the pending write instead of dropping it. A session that genuinely cannot reach the backend now fails to persist — recoverable — rather than destroying the previous one.

- **Bennu**: **there is always a workspace.** A default one (*Scratch*) exists from the start, so a project has somewhere to land without creating anything first, and deleting the last workspace leaves it rather than leaving nothing. *Open project…* is gone from the switcher — with a workspace always present, opening a project means adding it to one, and having both put a verb in the menu that quietly replaced the workspace's contents. *Add project…* is no longer disabled when the workspace is empty, which was the one state where you needed it most, and *New workspace…* goes straight to the folder picker and names the workspace after the project it gets instead of leaving you in a modal about naming something empty.

- **Bennu**: **a run configuration's icon says what it does.** Every Cargo configuration wore the same crate, so `app`, `editor-app` and `stub-gen` were three identical rows in a list whose only job is telling them apart. The subcommand picks the icon now — a play triangle runs, a hammer builds, a badge checks, a flask tests, a gauge benchmarks — and the group header above still says Cargo.

- **Bennu**: **Alt+Enter no longer offers Java generators on a Rust file.** The editor's own two entries — Generate constructor, Generate getters and setters — were added to every buffer's list regardless of language, so a caret in a Rust function was offered two dialogs that write Java members. They are now Java-only, and offered only where there is a type to generate into (the collector was ignoring the outline it was handed). Three further entries — add-import, surround-with-try/catch, introduce-variable — were placeholders from before the engines existed: they appeared on every file at every caret and toasted "not implemented" when pressed, so they are gone. Both engines offer the real versions: Java's from `bennu_intentions`, Rust's from rust-analyzer. What is left is ordered the way it is read — fixes first (the server's own preferred one at the top), then refactorings, with a disabled action and its reason last instead of pushing the actionable rows down.

- **Bennu**: <kbd>Alt</kbd>+<kbd>Enter</kbd> now shows intentions on a **language-server** file. The list itself had understood a server's code actions since they landed — the *key* was still gated on `.java`, so on a `.rs` it fell through to the WebView, which took it as a line break and inserted one. It is now consumed whatever the buffer is: a key that means "what can you do here" must never edit the file, even where nothing can answer.

- **Bennu**: **the Find-in-project field takes the caret on opening.** <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> left it on the source picker — the modal's initial-focus pass runs after the content's own and picks the first control in the body, which here is a dropdown three rows above the field — so the query had to be clicked before it could be typed. The field now declares itself as the target, the way the Go-to navigator already did.

- **Bennu** (Java editor): **a controller written with `@GetMapping` alone was invisible to the Spring tooling.** The pre-filter that decides which files are worth parsing looked for the substring `@Mapping`, and the verb sits between the `@` and the word — so only `@RequestMapping` ever matched. Every route on every `@GetMapping` / `@PostMapping` controller was missing from the Endpoints panel, and its beans and injections with them.

- **Bennu** (Java editor): **completion after a class name.** `Color.` offered nothing: the receiver is a type, not a value, and only values were being typed. Enum constants, static fields and static methods now complete the way instance members already did. Separately, a class can once again see **its own private members** — the enclosing type was read from a buffer that a half-typed `receiver.` had made unparseable, so the answer was "you are inside no class" and every private was judged inaccessible, in precisely the state completion runs in.

- **Bennu** (Java editor): **`@Autowired List<OrderService>` finds the beans that implement it.** A collection injection point was matched on `List` rather than on what it holds, so the one injection style that cannot be resolved any other way resolved to nothing. `Map<String, T>` is matched on its value, which is what Spring keys by name.

- **Bennu** (Java editor): a property named the environment-variable way — `SERVER.PORT` — resolves to the key it stands for. And ghost text is no longer drawn from a caret position the buffer does not have, which put a suggestion somewhere the caret was not.

- **Bennu** (Java editor): inside a `@Query`, a Postgres cast (`x::text`) is no longer read as a bound parameter `:text` the method must then declare, and an entity whose name collides with a keyword — `from Order o` — is no longer coloured as one.

- **Bennu** (Java editor): a test's failure trace and its captured output were shown **twice** in the test panel; the parser was collecting each block of text once as itself and once through its element.

- **Bennu** (Java editor): a variable bound by a **multi-catch** (`catch (A | B e)`) is no longer typed as a field of the same name that it shadows — its type is the least upper bound, which is not something to guess, so it resolves to nothing and the member checks stay quiet.

- **Bennu** (Java editor): **two generic methods that erase to the same signature are reported as the duplicate they are.** `<T> void f(T a)` and `<U> void f(U b)` read as different parameter lists and are one method to the compiler — the check was comparing the parameters as written, so the name of the type variable made the pair look like a legal overload. Parameters are now compared after each of the method's own variables is replaced by what it erases to, which is the same rule that keeps `<X extends Collection> many(X)` apart from `<X extends Map> many(X)`.

- **Bennu** (Java editor): **Entando's `<wp:i18n>` labels are no longer checked against the `.properties` bundles.** Its keys live in the platform's own table in the database, not in any file, so the unknown-key check was putting a warning under every label on every page of an Entando application — the exact failure the check is written to avoid. It is recognised by the tag name, not by the `wp:` prefix, which a page is free to rebind. Framework answers read off disk are also newline-normalized now, like everything else the extensions are handed: on a CRLF page the offsets drifted a byte per preceding line, which reads as a squiggle a line or two below what it is about.

- **Editor** (Bennu, Merula, Picus — every buffer): **undo could empty the file, and there was no redo.** Opening a file swaps the whole document into the same editor, and that swap was being recorded as an edit — so pressing <kbd>Ctrl</kbd>+<kbd>Z</kbd> past your own changes walked backwards through the files that had been open before, ending at the empty document the view started as. A swap is no longer undoable, and it now clears the history outright: what you typed in the file you just left is not something to replay at positions that belonged to it. Redo is <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> — CodeMirror puts it on <kbd>Ctrl</kbd>+<kbd>Y</kbd> on Windows and Linux, which this editor gives to delete-line, so there was none at all.

- **Bennu** (Java editor): **back / forward navigation stops at the places you went to.** Every cross-file jump is two caret events — the file opening wherever its buffer starts, then the scroll to the line you asked for — and both were being recorded, so one <kbd>Ctrl</kbd>+<kbd>B</kbd> left two stops and Back took you to line 1 of the file you had just arrived in. Worse, a Back that crossed a file recorded its own landing, which truncated the branch it had just stepped into and left Forward doing nothing. Now the scroll refines the stop the opening created, a step's own landing is never recorded, and a jump that cannot land gives up instead of blocking the history for the rest of the session.

- **Bennu** (Java editor): **find usages counts a field read without a receiver.** Only `this.count`, `other.count` and `Config.MAX` were being indexed, so the shape Java is actually written in — a bare `count` meaning `this.count` — counted for nothing, and a `final` field, which is almost never qualified inside its own class, reported "no usages" while the method above it read it twice. Rename was missing the same sites. A local or parameter of the same name is still that variable rather than the field it hides, and a declaration is not a use of itself.

- **Bennu** (Java editor): **a nested class counts its own members.** Recording a use and looking one up spelled the enclosing type two different ways for a type the project map does not hold, so a field or method of an `Outer.Inner` reported no usages from its declaration while <kbd>Ctrl</kbd>+click from the use navigated to it correctly — which is the shape this bug always takes, and the reason it survives being looked at.

- **Bennu** (Java editor): the "no such property" warning **goes quiet inside a loop whose element type cannot be resolved**. It was judging every name in every `<s:iterator>` against the action, which is the wrong class for all of them — a page of yellow, and a warning nobody reads twice. Where the element type does resolve the check keeps working and judges the name against every level of the stack; where it does not, nothing is said, because "I cannot see that type" is not evidence that a property is missing.

- **Bennu** (Java editor): a structural pattern could not contain **`${`**. The `$` was read as the start of a placeholder, so an EL pattern failed with a complaint about `{` not being a usable capture name and `$${` was the incantation — for the commonest construct a JSP pattern is made of. A name cannot begin with a brace, so `${` is now simply literal; `$$` still escapes a lone dollar.

- **Bennu** (Java editor): a JSP **tag name could not contain an underscore**. `<my_tag>` lexed as `my` followed by a stray `_tag` — an XML NCName admits one — and it also meant a structural pattern could not put a hole in the tag-name position at all, since a placeholder is an identifier with underscores in it.

- **Bennu** (Java editor): structural search offered a **template that could never run** — "Actions by the base class they extend", `class $c$ extends $b$ { $body...$ }`. A placeholder stands in for a *name*, and a bare name is not a class member, so that pattern does not compile; the template is gone and the docs now say plainly where a `...` hole works (an argument list) and where it does not (statements, class members, parameters), including that there is currently no way to write "a class extending X, whatever its body".

- **Bennu** (Java editor): a debugger watch could not go **through an array index**. `items[2].price` was refused as "an empty name in the path" — the `.` after a `]` was read as a dot with nothing in front of it, when the subscript before it is a complete step. Only a leading dot and a double dot are errors.

- **Bennu** (Java editor): `<s:text name="note.login.intro"/>` was **flagged as an unknown action property**. That `name` is a key in a resource bundle, and Struts spells several unrelated ideas the same way — `<s:i18n name>` is a bundle, `<s:action name>` an action, `<s:bean name>` a class, `<s:param name>` the parameter's own name. Only the form controls bind a property, so that is now a positive list rather than everything-that-has-a-name. The collision that forces it is `text`: Struts 1's `<html:text property="user"/>` is an input and Struts 2's `<s:text>` is a lookup — one local name, opposite meanings — so which prefix a page bound to Struts is read from its own directives rather than assumed.

- **Bennu** (Java editor): **every structural query over JSP matched nothing.** A query's alternatives are accumulated a line at a time with a separator after each, so a pattern carried a trailing newline nobody wrote. Java and SQL discard whitespace in their grammars and never noticed it; JSP declares none, so the newline was swallowed by the pattern's last token — `$a$` compiled to a text node reading `ARBOR_PLACEHOLDER_0\n`, which is not the placeholder, so the hole stopped being a hole and the query matched nothing anywhere.

- **Bennu** (Java editor): in a structural query, **`or` on a line of its own** — which is how anybody lays out two shapes of the same question — read as pattern *text* rather than as the clause. The whole query became one alternative containing the word `or`, which then matched nothing and explained nothing. It now opens an alternative whether the shape follows it on the same line or the next.

- **Bennu** (Java editor): a structural query that **failed to compile reported "nothing matches"** instead of saying so. The walk returned an empty result and the panel rendered it as a fact about the project — which is the one wrong answer a search must never give quietly, and the module says as much about every other case. It now surfaces the compile error. In the same spirit, "no results" distinguishes *read N files and matched none of them* from *found no files to read at all* — the second is a statement about the language picker or the scope, and naming the extensions it looked for is the difference between a shrug and a fix.

- **Bennu** (Java editor): the Trees panel called `<jsp:include>` an **undeclared prefix**. The standard actions are defined by the JSP specification and need no `<%@ taglib %>` — the container knows them — so the model was flagging the one vocabulary every page can rely on. The reserved prefixes now read as *JSP standard actions*.

- **Bennu** (Java editor): an embedded language's highlighter **saw the whole line up to each token instead of the token itself**, so anything a mode recognised by reading back what it had just consumed — which is how a keyword is recognised — worked only for the first token on a line. It affected the JavaScript, CSS and EL/OGNL colouring inside every JSP.

- **Bennu** (Java editor): a **public field is a property**. OGNL reads fields, not only accessors — `%{jsp_param.element}` works against a `public Element element;` with no getter anywhere, and the parameter-bag classes a legacy Struts action carries are written exactly that way, usually as a nested class of public fields. Bennu understood only `get`/`is`/`set`, so go-to did nothing, the hover said nothing, and the "no such property" warning flagged names the page reads perfectly well. Go-to now lands on the field's own declaration, and only *public* fields join the set the warning is judged against — a private one is a name a page genuinely cannot read.

- **Bennu** (Java editor): the **type** of an action property is read from the code and not from the Javadoc above it. The scan took the type as everything between the previous `;`/`{`/`}` and the accessor's name — on raw text, so a comment holding a `{@link Foo}` or a `Map<String, Object>;` put those characters between the two, and the "type" came out as `*/ public JspParamDTO`. Nothing rejects a non-empty string, so it was shown in the hover card as the property's type and was passed on to whatever tried to resolve it. Generated DTO accessors carry exactly that kind of Javadoc, which is why it was invisible on hand-written classes and reliable on the ones that matter.

- **Bennu** (Java editor): **searching the dependency classpath is fast again.** Every keystroke walked the classpath building the dot-form name of *every* class on it just to have something to match against — two allocations per class, so over half a million of them on a legacy project to answer one letter, per letter. Names are now compared where they already are, and only the few hundred that matched are turned into anything. The preview of a library row also arrives at all now (it said "nothing to preview"), and no preview — library or not — is fetched until the selection has sat still for a moment, so holding ↓ no longer queues one read per row it passes over. A file found inside a jar wears its own **file-type icon**, the same rule the project tree uses, instead of one archive glyph for every one of them.

- **Bennu** (Java editor): **a run launches with the runtime classpath, not the editor's.** Dependencies were resolved once, with every Maven scope, and that one list was used for both indexing and launching. It is the right list for the first — you edit tests, so completion has to see their dependencies — and the wrong one for the second: the JVM was handed test- and provided-scoped libraries Maven would never supply. The failure that surfaces it is not obvious, which is what made it worth chasing: a `@ConditionalOnClass` guarding a bean on a library that is only test-scoped fires in Bennu and nowhere else, so an application that starts under `mvn spring-boot:run` refuses to start here with a bean-definition conflict. Launches now resolve at the **runtime** scope, and a **Classpath** field on the run configuration takes Compile, Test or every scope for the cases where that is genuinely what you want. The resolve is cached per pom *and per scope*, so a launch can no longer hand the index a classpath with the test dependencies missing.

- **Bennu** (Java editor): the preview column in Find in project and the **Go to** modals **no longer steals the caret**. It scrolled to the result by way of the editor's go-there API, which ends by focusing — so every arrow key pulled the cursor out of the field you were typing in.

- **Bennu** (Java editor): **Find in project no longer locks up while it searches.** The scan always streamed; the panel could not keep up with it. Each batch re-assigned the whole result list (a copy of everything found so far — quadratic over a scan), rebuilt the grouping, re-laid out every row, and re-read the previewed file even though the selection had not moved. On a legacy project the main thread never came up for air: the list looked frozen, the arrow keys felt dead, and the preview never arrived until the scan ended. Batches now land on a timer, the list is **windowed** so five thousand matches are forty rows of DOM rather than five thousand, and the preview re-reads only when the selection actually changes.

- **Bennu** (Java editor): the **match is actually visible** in Find in project — in the result rows and in the preview. It was being drawn all along, against a 15%-alpha background that read as a faint tint you had to already know was there.

- **Bennu** (Java editor): structural search **streams for real**. It emitted its results in batches, which looked like streaming and was not: the whole project was walked first and the finished list was then chopped up, so nothing appeared until everything had. Matches now leave the backend as each file produces them.

### Changed

- **Bennu**: the span-aware TOML reader moved out of `bennu-cargo` into a crate of its own (`bennu-toml`). It records where every table and key is and knows nothing about what any of them mean, so it was never Cargo's — the fulcrum i18n extension reads a message bundle with the same scanner. No behaviour change.

- **Bennu** (Java editor): in a JSP, go-to and hover **follow a whole OGNL path** instead of only its first name. `%{ordine.cliente.nome}` bound three classes together and only `ordine` was reachable — the expression scan kept just the root identifier, so a caret on `nome` matched nothing at all and the gesture died before anything had been asked; now <kbd>Ctrl</kbd>+<kbd>B</kbd> on `cliente` opens it on `Ordine` and on `nome` opens it on `Cliente`, each segment resolved against the class the one before it is declared to be, seeing through `List<T>` and the other single-argument wrappers. Field names (`<s:textfield name="ordine.cliente.nome">`) and a `*-validation.xml` `<field>` follow the same rule, and so does a **page variable**: inside `<s:iterator value="%{elencoBandi}" var="bando">` the declaration is the only place the page says what `bando` holds, so it is read — the expression resolved against the action, the container seen through — and `%{bando.titolo}` follows from there. Holding <kbd>Ctrl</kbd> underlines the *segment* under the pointer rather than the whole chain, so what a click will open is what is underlined. Each type name is resolved **in the context of the file that wrote it** — its own nested classes first, then its imports, then its package — because in a legacy tree every action carries its own nested `JspParam`, `Row`, `Params`, and picking the first class in the index with that simple name walks into a different action's inner class and then reports, correctly and uselessly, that it has no such property. The walk stops rather than guesses — a property with no accessor, a type the project has no source for, a name that means five different things and nothing to say which — because a jump that lands in the wrong file costs more than one that does nothing.

- **Bennu** (Java editor): a JSP reachable through **several routes into one action class** is no longer treated as ambiguous. The picker listed three rows all reading `DettaglioComunicazioniAction` — the one thing they had in common, with the routes that told them apart left out — and, counting three candidates, switched the OGNL checking off entirely until one of the three identical-looking choices was pinned. Legacy configs declare the same class under several namespaces constantly, so it was precisely the well-travelled pages that got nothing. They now resolve on their own, and the picker shows one row per class with the routes that reach it underneath.

- **Bennu** (Java editor): **Go to** (<kbd>Ctrl</kbd>+<kbd>N</kbd> / <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>) reads nothing until you type. It used to walk every module for every class the moment it opened — a wait you paid on every use, including the ones where you already knew what you were going to type, and the reward for it was a list nobody reads. The **search field now takes the caret** on opening, which it was losing to the first control in the panel.

- **Bennu** (Java editor): in a JSP, **each taglib is a different colour**, and its `<%@ taglib %>` declaration wears the same one — so the directives at the top of the page are the legend for the thousand lines under them, and `<s:…>`, `<c:…>` and `<wp:…>` stop reading as one undifferentiated "taglib tag" when they are three libraries with three manuals. A prefix keeps its colour in every file that declares it, and two prefixes in the same page never share one. The hues stay out of the green band: every attribute value in the file is green, a tag name has one sitting two characters to its right, and a second shade of green there is not a distinction anyone can read. A prefix the page never declared keeps the plain tag colour, which is also the quickest way to spot a directive that got lost in a copied fragment.

- **Bennu** (Java editor): the framework panels — **Endpoints** first among them — read like a list you skim rather than one you decipher. A row that says it returns a `QFormDto` has told you nothing, so **any type is a door**: the chip expands into that class's fields, each composite field expands in turn, and an interface (or a class read out of a jar, which has no fields to show) is listed by the properties its getters expose and says which it is doing. Wrappers are seen through — `ResponseEntity<OrderDto>` opens on the `OrderDto` — and nothing is resolved until you click, because a catalog of two hundred routes names two hundred types and you came to look at one. Media types are shown by their short names (`JSON`, `SSE`, `XML`, `form`) instead of as `MediaType.APPLICATION_JSON_VALUE`, which was the widest thing on the row and one fact wearing thirty characters; an unrecognised one keeps its own spelling, being exactly the one worth reading. The `{variables}` in a path are lit apart from its literal segments, rows sit on a baseline grid instead of wherever their text left them, and the count beside the filter says how many rows survived it. The list can also **leave** — CSV, JSON or a Markdown table, to the clipboard or a file — carrying what is on screen rather than the whole catalog, grouping column and all, with each route's parameters flattened onto its row so the spreadsheet answers on its own.

- **Bennu** (Java editor): every preview column — Find in project, Go to, structural search — **is the editor**, read-only. Every request runs on its own thread and the editor asks four questions per keystroke — highlights, gutter, actions, diagnostics — all of which need the framework model. With that model not yet built, each of them started building its own copy, concurrently, none reusing the others' work, and every one of them started again on the next keystroke because none had finished. It is now built once, with the others waiting on it.

The classpath went on the command line, and Windows caps a command line at 32767 characters — a resolved `~/.m2` classpath passes that on its own, so the launch died with `os error 206` ("the filename or extension is too long"), which names neither the classpath nor the limit. Bennu stamps the modules' sources and resources — sizes and modification times, nothing opened — against the last successful compile, and launches straight away when they match. Maven's floor is seconds even with nothing to do: every invocation re-reads every pom, re-resolves every module's plugins and re-runs their up-to-date checks before concluding there was nothing to compile. The stamp lasts the session and is dropped when the project is re-indexed.
- **Bennu** (Java editor): the build before a run compiles **only the module being run** and the ones it is built from, instead of the whole reactor. `mvn compile` at the root of a large multi-module project costs tens of seconds with nothing to do — it still scans every pom, resolves every module's plugins and runs each one's up-to-date checks. The Build button is unchanged: it means the project.
- **Bennu** (Java editor): pressing **▷ no longer waits for Maven**. The run classpath was resolved by shelling out to `mvn dependency:build-classpath` on every launch, through a cache that was created empty each time — so the dependencies were re-resolved from scratch every run. It now uses the jars the index already resolved when the project was opened, which are the same ones completion and navigation see; Maven is only invoked when no project is open on that root.
- **Bennu** (Java editor): finding the project's **entry points is instant**. The scan parsed every `.java` in the project on every open of the run-configuration editor and every press of ▷. - **Bennu** (Java editor): **Stop actually stops a running program.** It removed the run from a list of live runs and reported success, killing nothing — the JVM went on running, holding its port and its files, with no way left to stop it short of Task Manager. It now kills the process tree, so a program that spawned children does not outlive the button either.
- **Go to class / file / symbol** (<kbd>Ctrl</kbd>+<kbd>N</kbd>, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>): the results **respond to the mouse** and are marked with the **real icons**. The row highlight named a colour this theme does not define, so neither the hovered nor the keyboard-selected row was marked at all; and classes wore generic shapes while the tree three feet away drew the lettered C / I / E / R / @ rings. The level now comes from the same place the index and the title-bar badge read it. When no JDK of that level is installed, the environment's own is used rather than a different one being substituted.

The build now resolves the launcher the same way the dependency tier already did (PATH including the batch launchers, the well-known install directories, then the project's `mvnw`).

The duplicate check now compares within one declared **product** as well as within one engine, so naming the product on each initialisation subtree tells the two apart; a repository that declares none behaves exactly as before.

Which dependencies get read is an allowlist by group id, artifact id or a prefix of either (Settings → Spring → Beans); empty by default, and empty means no jar is opened. They are shown as declarations rather than facts — Boot's auto-configuration is conditional, so each gated bean carries the conditions gating it, and none of them take part in autowiring candidates, completion or any diagnostic. Scans are remembered per artifact on disk and re-read only when that jar changes.

- **Bennu** (Java editor): a **machine-generated expression no longer takes the backend down**. Type inference walks an expression by descending it, and a generated concatenation of a few thousand pieces nests one level per piece — deep enough to exhaust the stack, which aborts the process outright rather than raising an error, so opening one such file cost every other file its diagnostics. - **Bennu** (Java editor): ghost text no longer proposes **what is already written**. The name still checked out, so the repository was recognised, but its type arguments were unreadable: every consumer asking which entity a repository manages got an empty answer and carried on, and a generated method came out as `List<> findById(Object id)`. Type lists now split at depth-0 commas only.
- **Bennu** (Java editor): the JPA dialogs opened on **the wrong entity**, and then said it had no repository. The file the button was pressed on was compared to the backend's path without normalizing the separator, so on Windows nothing ever matched and every dialog fell through to "whichever entity sorts first" — which was usually a view with no repository at all. Path identity is now one shared function.
- **Bennu** (Java editor): a dialog opened from a repository's toolbar **no longer asks which entity**. The button already said; asking again was a question with one right answer that had to be re-answered before the form was usable.

### Added

### Fixed

- **Picus** (SQL studio): **after storing an edited cell, the rows that come back are the ones that were written.** The re-read went through "the statement the caret is in" — a question about the buffer, not about the result — so in a tab holding several statements it re-ran the wrong one, and with no editor mounted it re-ran the first. A result now remembers the **text** of the statement that produced it, and that is what is replayed — so it still re-reads correctly when the query it came from has since been edited or deleted from the tab.
- **Picus** (SQL studio): **Store writes the edited cells again.** On a tab with no connection of its own — one that runs against the window's, which is most of them — the write resolved the connection by id alone instead of applying that fallback, found nothing, and returned without doing anything or saying anything. The two cases where it now cannot proceed each say so instead of leaving a button that appears to be broken.
- **Picus** (SQL studio): **a failed connection says why.** Every way of not reaching a server printed the same seven words — `error connecting to server` — because the driver's own message is a category and the reason sits one level below it, in a cause that was being thrown away. The cause chain is now kept, and the failure also reaches the log.
- **Picus** (SQL studio): **`localhost` works even where this machine cannot resolve it.** It is a reserved name that always means the loopback interface (RFC 6761), so when resolution fails for it — a VPN client's DNS layer being the usual reason — the loopback address is used instead, and the substitution is stated in the log rather than made silently. Any other host that fails to resolve is still an error, now reported as a name that did not resolve rather than as a connection that failed.
- **Bennu** (Java editor): **a fluent builder reached through a wildcard no longer collapses to `Object`.** Spring's `restClient.get().uri(…).accept(…)` was reported as "cannot resolve method `accept` in Object": `get()` hands back a `Spec<?>`, and substituting the self-returning type variable with the wildcard's `Object` made every following call in the chain a false error. An unknown type is now reported as unknown, which is silent.
- **Bennu** (Java editor): **Lombok's generated constructors exist.** `@NoArgsConstructor`, `@RequiredArgsConstructor`, `@AllArgsConstructor` (and the `@Data` / `@Value` bundles) are indexed with the parameter list Lombok actually generates and the `access = AccessLevel.…` they were given — so a class that also writes one constructor by hand no longer has the Lombok one's call sites reported as "No constructor takes N arguments".
- **Bennu** (Java editor): **a hand-written fluent accessor no longer cancels its twin.** With `@Accessors(fluent = true)` the reader and the writer share a name, and suppressing the generated member by name alone meant one hand-written `value()` removed the `value(x)` setter as well — every later verdict about that setter was really about the other method.
- **Bennu** (Java editor): **Lombok's `AccessLevel` is honoured.** `@Setter(AccessLevel.PACKAGE)` is recorded as package-private rather than public, and `@Getter(AccessLevel.NONE)` — which generates nothing — no longer indexes an accessor that doesn't exist. A positional annotation argument was invisible to the model, so no level ever arrived.
- **Bennu** (Java editor): **an enum's constants are members of it again.** A project enum was indexed without them, so nothing completed after `Color.`, `import static p.Color.*` supplied no name (and using one was reported as undefined), and switch exhaustiveness gave up on every project enum.
- **Bennu** (Java editor): **hovering a method or a class is fast.** Each hover was parsing every `.java` file in the project to look for a Javadoc — 1300 parses for one tooltip on a large project; it now reads the one file that declares the symbol. The tooltip also appears sooner after the pointer stops.
- **Bennu** (Java editor): **a `switch` over an enum whose cases are qualified (`case Status.ACTIVE ->`) is no longer reported as covering nothing.** Only the bare form counted, so a switch that covers the enum completely was told it was missing every constant.
- **Bennu** (Java editor): **a trailing `;` after a `switch` statement no longer marks the whole block as an error.** Java reads `switch (x) { … };` as a switch followed by an empty statement — legal, merely redundant — so the diagnostic is now a warning, on the semicolon.
- **Bennu** (Java editor): **the Build panel tells warnings and errors apart.** A validation that ends with warnings and no errors reads as *passed* instead of painting 324 style notes red, and each count is coloured for what it is.
- **Bennu** (Java editor): **the Forms tool window is offered only on a project that has JSP pages.** A service module was showing a toggle for a panel that could only ever be empty there.
- **Bennu** (Java editor): **the Validation button is offered only where Struts is in use.** On any other project it created a `*-validation.xml` no framework would read.
- **Bennu** (Java editor): **a variable that shares a field's name is read as the variable, the way Java reads it.** `for (Impresa impresa : impreseAusiliarie)` inside a class that also has a field called `impresa` typed every `impresa.getX()` in the loop against the *field*, so correct code was covered in "Cannot resolve method". The same hole affected `catch (FooException e)`, `if (o instanceof Foo o)` and `case Foo x ->` — every binding that may legally shadow a field. Pattern variables are bound exactly where Java binds them: the branch the test governs, the rest of an `&&`, the statements after a `if (!(o instanceof Foo f)) return;` guard — and nowhere else, so the name still means the field in the `else`. `for (var x : list)` now takes the element's type rather than the collection's, and a `var` initializer that reads a field resolves like it does anywhere else.
- **Bennu** (Java editor): a **`boolean` field already named `is…` keeps its name in its Lombok accessors.** Lombok drops the `is` it would otherwise add whenever what follows the field's own `is` is not a lowercase letter — an underscore counts — so `private final boolean is_attivo` gets `is_attivo()`, and `boolean isRunning` gets `isRunning()` / `setRunning(…)`. Bennu read the rule as "followed by a capital", generating `isIs_attivo` instead: a getter that genuinely exists was reported as unresolvable at every call site. Go-to on such an accessor now finds its field too.
- **Bennu** (Java editor): **completion offers every overload, not one per name.** Member completion collapsed same-named methods to a single entry — so `substring(int)` and `substring(int, int)` were one suggestion, nine `valueOf`s were one, and a Lombok `@Accessors(fluent = true)` getter `customer()` hid its own setter `customer("x")`, which made fluent accessors look unsupported. Each signature is now its own entry with its parameters and return type, while a method that overrides an inherited one still appears once.
- **Bennu** (Java editor): **the JDK is found on macOS and Linux.** Discovery looked in `JAVA_HOME` and two Windows `Program Files` directories and nowhere else — and an app launched from Finder, the Dock or a desktop launcher inherits the system's bare environment, not your shell profile, so `JAVA_HOME` is usually unset there. On a Mac with three JDKs installed, Bennu found none: `java.lang.String` itself would not resolve and a correct project reported thousands of unresolvable types. It now reads the standard locations of each platform — the macOS `JavaVirtualMachines` bundles, `/usr/lib/jvm`, the Homebrew `openjdk` formula, and the per-user directories a version manager or an IDE installs into — and a JDK path you configure yourself may point at a macOS bundle rather than at the `Contents/Home` inside it.
- **Bennu** (Java editor): **Maven is found when it isn't on the app's `PATH`.** Same cause: a Homebrew, MacPorts or SDKMAN `mvn` that works in a terminal was invisible to a windowed app, so resolving dependencies failed on the spot and the only trace was a line on a log nobody reads. The well-known install directories are checked, and a project's own `mvnw` wrapper is used as a last resort — so a machine with no Maven installed at all can still resolve.
- **Bennu** (Java editor): **when dependencies can't be resolved, Bennu says so.** A Maven project with no dependency tier reports every library type as unresolvable, which reads as thousands of unrelated errors rather than as one missing classpath. It now tells you once, with the reason — Maven couldn't be run, or its dependencies aren't in `~/.m2` yet. A project with no `pom.xml` stays silent, because it isn't missing anything.
- **Bennu** (Java editor): **Rebuild index re-resolves the dependencies.** The resolved jar list is cached against your poms' timestamps, so a rebuild faithfully re-served the same wrong classpath — the one button you'd reach for when library types aren't resolving was the one that couldn't fix it.
- **Bennu** (Java editor): **a multi-module project now resolves the dependencies of every module.** `dependency:build-classpath` runs once per module of a reactor, and Bennu pointed all of them at one absolute output file — so each module overwrote the previous one and what survived was whichever module Maven built last (often the aggregator root, which has no dependencies at all). Opening a class in any other module found none of its libraries and reported every type in it as unresolvable: thousands of errors on a project that compiles. Each module now writes into its own `target/` and the classpath is their union. Relatedly, the cached jar list is keyed on the newest mtime across **all** the poms, so a dependency added to a module actually invalidates it — before only the root pom counted, and a module's new library stayed invisible indefinitely.
- **Bennu** (Java editor): **two overloads distinguished only by a type variable's bound are no longer called duplicates.** `<X extends Collection> many(X)` beside `<X extends Map> many(X)` both read `(X c)` in source, so a text comparison saw one method — they erase to `many(Collection)` and `many(Map)`, and the compiler accepts both. A method's own type parameters are now part of its signature, compared by their *bounds* so that `<T> f(T)` and `<U> f(U)` — a genuine duplicate — still collide.
- **Bennu** (Java editor): a **package-private member of a nested type is reachable from its own package** again. A project nested type's binary joins its nesting with `/` (`com/acme/Outer/Inner`) — the same separator a package uses — so "the package" was read as `com/acme/Outer`, which never equals a real package: every same-package access to such a member was reported inaccessible. Private access across nests is unchanged, and a genuinely different package is still flagged.
- **Bennu** (Java editor): **a field declared by an anonymous class is no longer looked up on the outer class.** `new Foo<>() { private Bar b; … this.b … }` resolved `this` to the class where the `new` sits — which has no `b` — so every field an anonymous body declares came back as unresolvable. `this` inside an unnamed type now resolves to nothing at all rather than to the wrong type, which the checks read as "don't know" and stay quiet about. (Same fix covers `this` inside a `record` body, which had the same mistake.)
- **Bennu** (Java editor): Lombok **`@UtilityClass`** is understood — every method and field becomes `static`, the class `final`, and the private constructor exists. Calling `MyUtils.helper()` on one used to resolve to an *instance* method and be reported as a non-static member referenced from a static context.
- **Bennu** (Java editor): **records work.** A record's generated members — an accessor per component (`p.x()`, named after the component, not `getX()`), the backing fields, the canonical constructor, and `toString`/`equals`/`hashCode` — exist nowhere in the source, so every use of one was reported as an unresolvable method on correct code. They are now part of the type, and a member the record declares itself still wins.
- **Bennu** (Java editor): **Java 21 pattern labels are no longer reported as duplicate cases.** Two arms sharing a type pattern and differing only in their `when` guard — `case Pair<Boolean, Boolean> p when p.getLeft()` beside `… when p.getRight()` — read as the same label by source text, and the guard itself was being collected as if it were a case constant. Pattern labels are now left to the *dominance* rule they actually answer to, which Bennu doesn't check yet: silence instead of a verdict borrowed from the constant rule.
- **Bennu** (Java editor): a **`switch` expression's arms are no longer flagged** as "not a statement". `return switch (p) { case OWNER -> 4; … }` had every arm reported, because an arrow arm's *value* is parsed as a statement — so ordinary Java came back as a wall of errors.
- **Bennu** (Java editor): the project's Java level is read from **`<java.version>`** and **`maven.compiler.release`** too, not only `maven.compiler.source`/`target`. A Spring Boot project declares it the first way, and missing it meant falling back to Java 8 and telling a Java 21 codebase that "Records require Java 16, but the project targets Java 8".
- **Bennu** (Java editor): an enum whose constructor comes from **Lombok** (`@AllArgsConstructor` / `@RequiredArgsConstructor` with valued constants — the standard way to write one) is no longer reported as having constants with no matching constructor.
- **Bennu** (Java editor): opening a **Cargo** project no longer runs an indexing job. The backend correctly indexes nothing there, but the window armed the "Indexing project" status anyway — on every open, watching a build that had never started.
- **Bennu** (Java editor): **an edit made outside Bennu is no longer overwritten by autosave.** A file open in a tab was never checked against disk, so anything that changed it — another editor, a `git checkout`, a generator, a build — was silently lost the next time the autosave timer fired. Bennu now notices: a tab with no unsaved edits picks the new content up silently, and one with unsaved edits stops and asks which version to keep, with autosave paused for that file until you choose. The save itself is guarded too — a write whose file moved underneath is refused rather than applied, for <kbd>Ctrl</kbd>+<kbd>S</kbd>, autosave and the multi-file writes of a Rename alike. A file *deleted* under an edited buffer is not a conflict: your buffer is the last copy, so saving recreates it.

- **Picus** (SQL studio): **saving a script no longer scrolls it back to the top.** A save re-reads the repository, which empties the text cache; the editor fell back to its loading state for that instant, so it was torn down and rebuilt at line 1. Saving halfway down a long file now leaves you where you were.
- **Picus** (SQL studio): a saved script's tab **stops showing as unsaved.** The dot was set on the first keystroke and never cleared, so every file that had been edited once looked dirty for the rest of the session.
- **Picus** (SQL studio): **Cancel now always gets you out.** PostgreSQL ignores a cancel while a backend is in an uninterruptible wait, and the studio simply waited with it — a spinner that never went out, a Cancel that did nothing however often it was pressed, and a tab that would never run anything again. A cancel that is not honoured within a couple of seconds now abandons the connection and opens a new one, and says so. The old statement may still be running on the server; that is stated rather than papered over.
- **Result grid** (every product): the **row-number column keeps its header** when the grid is scrolled sideways. The header moved as one piece while the numbers stayed pinned, so after any horizontal scroll the label above rows 1, 2, 3 belonged to some other column.
- **Every product**: a dropdown whose "all of them" option is the empty value — *Every folder*, *Both*, *Any* — **shows that option** instead of rendering as an empty box with a chevron, which read as a control that had failed to load.
- **Picus** (SQL studio): a sequence with no maximum says **no limit** rather than printing a 19-digit number that was both the type's limit and, after the trip through JSON, off by 193.
- **Picus** (SQL studio): the Inventory column header names **how many folders and how many files** it counts over; it used to read "3 folders · statements", the number missing.
- **Picus** (SQL studio): the declared type in the generator form is **elided rather than sliced** — `character varying(5` was a `character varying(50)` cut mid-token, which reads as a different type.
- **Picus** (SQL studio): the connection dialog **can no longer open blank** on a connection that exists. It read the connection once at mount, so opening it while the list was still loading gave empty fields that would then have been saved over the real ones.
- **Picus** (SQL studio): **cancelling a read no longer restarts it.** The streaming read falls back to a held cursor when it fails, and a cancellation looked like a failure — so pressing Cancel re-ran the statement the slow way, on a tab that had already reported itself cancelled.
- **Picus** (SQL studio): **an abandoned query can no longer leave a cursor nobody owns.** Its reply may still arrive minutes later carrying a held result; adopting it then would close the result the user is actually looking at and orphan the one it replaced. A reply that is no longer the tab's current run has its cursor closed on the spot.
- **Picus** (SQL studio): closing or reconnecting a session that had **stopped answering** used to hang as well, because releasing its results is itself SQL and queued behind whatever was stuck. Releasing is now bounded, and the reset path speaks to the old connection not at all.
- **Picus** (SQL studio): Run on a tab that is still waiting says so instead of doing nothing.
- **Picus** (SQL studio): **a result is traced back to its table by the parser, and from the statement that ran.** It used to be worked out with a regular expression over the tab's *whole text* — so a scratchpad holding more than one statement reported every result as coming from several tables, and so did any single query carrying an `EXTRACT(YEAR FROM …)` or a subquery in its select list. Those rows were then refused editing and their `bytea` cells would not open, because opening one needs the key of a row and a row needs a table. The answer also now distinguishes a **view**, which nothing in the SQL can tell you, and says so instead of "not a table on this connection".
- **Picus** (SQL studio): clicking a large object that **cannot** be opened now says why, instead of doing nothing.
- **Picus** (SQL studio): **a restored query tab keeps the database it was bound to.** Tabs are re-opened while the connection list is still being read, so every restored tab was coming back bound to nothing — it then ran against whichever connection was active while the result panel described none, and reported the rows as read-only. The binding is now kept as written and resolved when it is read.
- **Picus** (SQL studio): **an `ORDER BY` no longer sorts the whole table before showing anything.** The row limit was only on the fetch, where the planner cannot see it, so an ordered query sorted every row — large objects included — to a temporary file before returning the first one. The limit is now part of the statement, which turns the same sort into a top-N. An ordered statement is also never wrapped to mask its large objects: PostgreSQL may hand a sub-select's rows on in another order, and a grid in the wrong order is worse than a slow one.
- **Picus** (SQL studio): **a failed read no longer poisons the connection.** The statement that reads the first window opens a transaction; when it failed part-way the session was left inside an aborted transaction block and every statement afterwards was refused until the connection was reopened — which looked exactly like the studio hanging, and went away on a restart. It is now always ended.
- **Picus** (SQL studio): **running a query straight after another one no longer waits for the first one's row count.** The exact count runs in the background, and a session is one database connection — so the new statement queued behind it, silently, for as long as the count took. The count is now given up when something the user is waiting on needs the connection; the planner's estimate stands, which is what it is for.
- **Picus** (SQL studio): **a read no longer waits for the whole result before showing the first rows.** A scrollable result used to be materialised in full on the server before a single row appeared — the row limit on the grid bounded none of it — so any query touching a large table took minutes with nothing on screen, and Cancel had nothing to interrupt. The first window is now streamed, and the scrollable snapshot is taken only if you scroll past it. Your statement is not rewritten to do it, so an `ORDER BY` is executed exactly as written. The consequence, stated: those are two reads, so without an `ORDER BY` a row may repeat or be skipped exactly at that boundary.
- **Picus** (SQL studio): the exact row count no longer forces that materialisation either — it counts the statement instead, which reads none of the columns.
- **Picus** (SQL studio): the query editor's **second toolbar is gone.** Run, Run all, Cancel and the connection were drawn twice, once per bar; what is left is the top one, carrying the schema, the engine and the server version.
- **Picus** (SQL studio): the result grid's **header now scrolls sideways with the rows**, so a wide result still says which column is which.
- **Picus** (SQL studio): **a query on a table of documents no longer takes minutes.** A result you can scroll is one the server materialises in full first, so `SELECT * FROM archivio` copied every megabyte of every `bytea` into a tuplestore before the first row appeared — and the 500-row window saved nothing, because the whole table had already been read. The large objects are now left out of a typed `SELECT *` exactly as they are in a relation tab. Their size is read from the value's storage pointer rather than by decompressing every value, which is what made the relation tab slow on the same table.
- **Picus** (SQL studio): opening a masked cell no longer **leaves a held result behind** on the server for each cell opened.
- **Picus** (SQL studio): **connecting no longer stops at "reading schema" forever.** The catalogue read asked the server to sort its result, and on a real schema — 695 tables, 15 222 columns — that sort never finished: unsorted the same query streams in 45 ms, and with *any* `ORDER BY`, including by `oid`, it did not come back at all. The ordering now happens after the rows arrive. Reading that schema went from never to 400 ms. Three further inefficiencies on the same query went with it (a per-column subquery for the primary-key flag, a plan chosen for a `NULL` parameter, and partitions listed as though they were tables), and a catalogue read that takes more than a minute now stops waiting and says so rather than leaving the studio on a spinner.
- **Picus** (SQL studio): the schema is no longer read **several times at once**. The read was started while the connection was still opening and again once it was open, and each one queued behind the last on the same connection.
- **Every backend**: **a request is always answered.** A handler that panicked used to unwind past the reply, so the caller waited on a message that would never arrive — no error in the interface, none in the log, and a window that had simply stopped. The panic now comes back as the failure it is, the backend survives it, and a call outstanding for more than fifteen seconds says which method it is waiting on. A reverse-channel handler that holds the reader thread says so too, since while it does, nothing else from that backend can be delivered.
- **Picus** (SQL studio): reading a schema can no longer be brought down by one odd column — a catalogue value that came back `NULL` where a name was expected used to take the whole read with it.
- **Picus** (SQL studio): a **NOT NULL column with a default is no longer reported as required** when left empty. An empty cell means *not supplied*, an unsupplied column is left out of the statement, and the default is exactly what fills it — so `CUSTOMIZED NUMBER DEFAULT 0 NOT NULL` was being asked for a value in the one case the default exists to cover.
- **Picus** (SQL studio): **a `DELETE … WHERE` no longer makes the generator forget the whole table.** Only an unconditional `DELETE` or a `TRUNCATE` does — and the scripts are now read in install order rather than alphabetically, so a delete is seen after the insert it removes. On a repository that reloads its tables, one such line was erasing everything read from every other folder, and the row already installed was never found.
- **Picus** (SQL studio): the diff now **says what the generator concluded about the rows** rather than reconciling in silence. "Nothing inserts into this table, so this is a new row" and "these statements insert into it but none names CUSTOMIZED, so no row could be matched on the comparison key" used to look identical — a block appended beside the row it should have changed.
- **Picus** (SQL studio): **"Changes to the scripts" no longer shows the first diff forever.** It rebuilds itself after every generation, marks itself when it describes an earlier one, and has a Recompute button — the only way to build a preview used to be a button that disappeared as soon as one existed.
- **Picus** (SQL studio): <kbd>Ctrl</kbd>+<kbd>Enter</kbd> **runs the selection again.** The editor bound it to "insert a blank line" and stopped the event, so with the cursor where it always is the key split the line and ran nothing.
- **Picus** (SQL studio): the **DML generator works with no database connected.** The table list now holds what the repository's own index knows as well as what a connection has, and pasted `INSERT`s supply their own table and columns — so the paste source no longer asks for a table it had already been told.
- **Picus** (SQL studio): the **paste source is a real SQL editor** — highlighting, and completion over the connected database's tables and columns instead of a bare text box.
- **Picus** (SQL studio): the **Inventory no longer marks what the consistency report does not.** Any count above one was tinted as a warning — the ordinary shape of a table created once and altered four times — and three separate definitions of "gap" disagreed with each other and with `CONS001`. There is now one, used by the matrix, the sidebar and the header count alike, and a legend saying what the marks mean.
- **Picus** (SQL studio): **a string containing a backslash no longer swallows the rest of the file.** The Oracle highlighting treated `\` as an escape — Oracle has no such rule — so `'C:\temp\'` left the literal open and everything after it was coloured as one string.
- **Picus** (SQL studio): a **portable script is no longer highlighted as Oracle**. Files under a folder written for both engines fell through to the one dialect they are specifically not written in.
- **Picus** (SQL studio): a **keyword can no longer become a table**. When the parser recovers from a construct it cannot assemble, whatever token sits where a name would go was read as one — so `ON DELETE CASCADE` could produce a blocking finding about a table called `CASCADE`.
- **Picus** (SQL studio): **the engine's own dictionary is no longer indexed.** `user_tab_cols`, `dual`, `v$…`, `pg_…` and anything under `sys` or `information_schema` are the engine asking itself a question — nobody installs them, and a PostgreSQL counterpart is never coming — so they got a row that could only read as an unclosable gap.
- **Picus** (SQL studio): objects the repository **only reads** are marked as such in the Inventory, never counted among the gaps, and can be hidden. A table another repository installs, read here by a view, has a row of dashes that means "not ours" rather than "missing".
- **Picus** (SQL studio): **a table a view merely reads is no longer reported as one dialect's missing change.** Reading a table in a `FROM` and inserting into it arrive at the parser as the same kind of mention, so a view over a table that another repository installs made `CONS001` report a gap in scripts that never installed it — a finding nobody could close by writing anything. The rule now compares what the scripts *change*: creations, alterations, writes, `DROP` and `TRUNCATE`.
- **Picus** (SQL studio): **a version guard written inside a PostgreSQL function body now counts.** Update scripts that wrap their work in a throwaway function — the house style of the repositories this exists for — were all reported as having no guard, because the walker gave up on a body it could only partly model instead of keeping what it did understand.
- **Picus** (SQL studio): the **throwaway wrapper function every update script replaces** is no longer reported as an object created in two places. `CREATE OR REPLACE` is the author stating that replacing is the point, and it is now read that way.
- **Picus** (SQL studio): `TO_NUMBER` is **no longer flagged as Oracle-only syntax in a PostgreSQL script** — PostgreSQL has it, and the finding sent people to rewrite working SQL.
- **Picus** (SQL studio): **a row a later update rewrote is no longer reported against the initialisation.** The update folder is a chain of deltas applied in order, and reading it as a bag of INSERTs reported every intermediate value a row has ever had — version 1.11 writes a value, 1.13 replaces it, and the initialisation carries what 1.13 left. Only the updates' last word about a row is now checked.
- **Picus** (SQL studio): a project can declare **more than one version table**, one per installed module. An update script guarding against any of them counts as guarded; with a single name, every script belonging to the second module was reported as unguarded.
- **Picus** (SQL studio): **a column quoted on one side and bare on the other is no longer read as two columns.** PostgreSQL folds an unquoted name to lower case and Oracle to upper, so a team writing `"name"` in one dialect and `NAME` in the other has written the same column twice — and every table where that happened was reported as filled in differently, naming columns one dialect "never writes".
- **Picus** (SQL studio): a finding now says **what kind of thing** it is about — "The table AGGIORNAMENTO is not touched by…". In a repository whose folders carry the same names as its tables, the old wording read as a claim about the folder it was anchored to.
- **Picus** (SQL studio): **changing a project setting now takes effect on the next check.** Switching a rule off, changing the initialisation model or classifying a folder left the held repository holding the configuration it was opened with, so re-running the consistency check gave the same answer as before and only "re-read the repository from disk" helped. The configuration is re-read on every write; the decoded text is kept, so it costs nothing.
- **Picus** (SQL studio): a row an update writes that the initialisation writes **with a different value** is now reported as a value that drifted, naming the columns and pointing at the other statement — not as a row the initialisation "never inserts", which it plainly does.
- **Picus** (SQL studio): **what a PostgreSQL `DO` block or function body does is no longer invisible.** Dollar quoting is one token to the parser, body and all, so everything a repository's PostgreSQL half did inside `$$ … $$` counted for nothing — no objects, no data, no coverage. The same change written as an Oracle `DECLARE … BEGIN … END` and as a PostgreSQL function therefore looked like a change one engine had and the other lacked, on the files where the two are most alike.
- **Picus** (SQL studio): **an INSERT that follows a DELETE of the same table is no longer called a duplicate.** Clearing a row and writing it again is how an update script is made re-runnable, and the rule fired on every one of them.
- **Picus** (SQL studio): an object **created in the initialisation and again in the update that introduced it** is no longer reported as created twice — under a cumulative initialisation that is the model working. Two files that a *fresh install* both runs still are.
- **Picus** (SQL studio): **hundreds of findings that described correct behaviour are gone.** A repository whose initialisation is kept at the latest version was being told, once per first-release row, that no update carries it — which is true, and is not a mistake. That direction is now off unless the project says the two halves are meant to mirror each other, and the report states that it is off rather than falling silent.
- **Picus** (SQL studio): **a query tab with more than one statement in it no longer appears to hang.** The whole buffer was sent as one string, which makes the server materialise every result at once and hold nothing that can be scrolled. Run now executes the selection if there is one and otherwise the statement under the cursor.
- **Picus** (SQL studio): **a view is one row in the Inventory instead of two.** Every `FROM x` is parsed as a table reference — the grammar cannot know what `x` turned out to be — so a view created once and read fifty times appeared as a `view` with one statement and a `table` with fifty, and the wrong one was the one people saw. Views, sequences and triggers also stop wearing a package's icon.
- **Picus** (SQL studio): **folders whose scripts all classify themselves are no longer listed as needing classification.** Where the engine is on the file name, the folder above has no engine and never will, and asking about it was asking for an answer that would change nothing.
- **Studio** (config editors): **saving no longer corrupts a file that has a byte-order mark or is encoded in UTF-16.** A file with a mark gained another one on every save (three saves, four marks), and a UTF-16 file was written as UTF-8 bytes underneath a UTF-16 mark — a file that would no longer open. Saving a character the file's encoding cannot hold now stops with that character named, instead of silently replacing it with an escape sequence.
- **Every greyed-out button can now explain itself.** A disabled button receives no mouse events and cannot be focused, so its "why is this unavailable?" tooltip never appeared, by mouse or by keyboard. Buttons that carry an explanation now stay reachable — hover or Tab to them — and, separately, disabled buttons finally *look* disabled and stop lighting up under the pointer.

- **File Explorer**: the window no longer stays behind after you **drop files onto it from another window** or open it on a path from a link — it now raises itself as it always meant to.
- **Canopy**: the **maximize button** in its title bar did nothing — that window was never granted permission to maximize itself, so the click was rejected silently. It now maximizes and restores like every other window.

- The **Disconnect** button on a connected Git provider was drawn plain white outside the Settings panel (for example in the new Credentials dialog) — it only ever had colours while it happened to sit inside that one panel. Low-emphasis bordered buttons are now a variant of the shared button, so they look the same everywhere.
- **Merula** (music): **exported audio now plays the instruments the script asks for** — rendering to a file (single render, stems, and *Export all*) ignored the installed sample banks entirely, so a script calling something like `.inst("mallets.hand_chimes")` was bounced on the fallback synth: what you heard live and what landed in the file were different sounds. Anything exported before this needs re-exporting, and its levels are worth re-checking (they were balanced against the wrong sound).
- **Merula** (music): an instrument name the renderer can't resolve is now **reported** instead of being silently replaced by the fallback synth.
- **Merula** (music): **downloading a sample bank or a model works again** — every transfer aborted after exactly 30 seconds with an "error decoding response", because a timeout meant for short API calls was capping the whole download; large banks are now bound only by a connection and a stall timeout, so a multi-GB bank can take as long as it needs.
- **Merula** (music): **sample-bank downloads now show live progress** instead of sitting on "Starting…" for the entire transfer — banks served without a declared size (most of them) reported no progress at all.
- **Merula** (music): the **General MIDI** bank installs again — its download host started refusing non-browser clients outright, so it now comes from a mirror of the same FluidR3 soundfont.
- **Merula** (music): **firing a clip from the launcher now actually changes what you hear** — the launcher drew its grid and accepted clicks, but the backend discarded the selection, so the base pattern kept playing. Firing a scene now re-stages the chosen clips live, loading any instrument they introduce without interrupting playback.
- **Merula** (music): the **VCSL** sample bank now indexes under real instrument names — articulation folders were being mistaken for instruments, so the bank offered `mallets.soft_mallets` and a bare `stroke`/`on`/`off` instead of `mallets.xylophone` and `bell_tree`, and several instruments were unreachable. Re-index the bank (or re-download it) to pick up the corrected names.
- **Bennu** (Java editor): **live Java validation no longer goes fully dark** — a single internal check failing on a specific file (e.g. one with accented/legacy-encoded characters) used to wipe *every* squiggle, syntax included, making validation look dead and letting real errors like calls to non-existent methods slip through. A failing check is now contained: the rest of validation keeps working and the editor keeps its diagnostics.

- **Picus** (SQL studio): a query no longer **fetches the whole table before cutting it down** — the limit is now applied by the server wherever the statement allows, so `SELECT * FROM orders` on millions of rows stops there instead of crossing the network in full.
- **Picus** (SQL studio): **turning a page of table data, and opening a table's tab, no longer re-read the entire schema** — on a database with several hundred tables both fetched every column of every relation to answer a question about one, which made paging cost far more than the rows it returned.

### Fixed

- **Corvus** (Git): committing with no configured git identity no longer dead-ends on the cryptic `config value 'user.name' was not found` error — Arbor now opens a **Set your Git identity** dialog to capture your name and email, writes them to the global git config, and retries the commit automatically.
- **Corvus** (Git): far fewer macOS Keychain password prompts — all stored secrets (git-provider tokens, PATs, refresh tokens, Jira/Linear keys) now live in a **single** Keychain item read once per session, instead of one item per credential each popping its own authorisation dialog. Note: this is a storage change, so you'll re-authenticate your providers once.
- **Corvus** (Git): cloning a *not-cloned* / *missing* workspace member from the Workspace Manager now updates the row immediately — no more manual "Locate" afterwards to clear the missing state.
- **Corvus** (Git): git operations no longer trigger the OS credential helper (e.g. macOS `osxkeychain`) configured in your global git config — which was popping a keychain password prompt on *every* fetch/push/clone. Arbor injects its own auth, so the helper is now suppressed for its git invocations; an operation whose credentials can't be resolved fails immediately with a clear authentication error instead of hanging or reporting the cryptic `could not read Username … Device not configured`.
- **Bennu** (Java editor): the **decompiled stub** shown when you Ctrl+B into a library/JDK type now renders **generic signatures** faithfully — method type parameters (`<X extends Throwable>`), wildcard arguments (`Supplier<? extends X>`), a type-variable `throws X`, and a class's own type parameters (`class Optional<T>`) — instead of the erased shape (`Supplier<X> … throws Throwable`). It reads like IntelliJ's, decoded from the bytecode `Signature`.
- **Bennu** (Java editor): types brought in by a **wildcard import** (`import com.acme.model.*;`) now resolve to the right package when several packages declare a class with the **same simple name** (common with generated JAXB `*Type` classes). Previously the editor bound whichever same-named type won the index, causing a spread of false positives — "cannot resolve method" on the receiver's members, a class wrongly reported as not overriding an inherited interface method, and "incompatible types" between two spellings of the same type. The star import now pins the exact package for a receiver's type, a supertype (`extends`/`implements`), and a method's return / parameter / field types.
- **Bennu** (Java editor): a method annotated Lombok **`@SneakyThrows`** no longer gets false "unhandled checked exception" errors — Lombok lets its body throw checked exceptions without a `throws` clause, so a direct `throw` or a checked-throwing call inside such a method is no longer flagged.
- **Bennu** (Java editor): passing an argument to a parameter of the **same type** is no longer sometimes flagged "`ComunicazioneType` cannot be passed where `ComunicazioneType` is expected" — this happened when one logical type resolved to two different internal name forms (a nested type as `Outer.Inner` vs `Outer$Inner`, or the simple name resolved through different files); the argument-type check now treats same-simple-name types as compatible.
- **Bennu** (Java editor): a **varargs logging call** like `LOG.debug("{}, {}", id, name, note)` is no longer falsely flagged "argument of the wrong type" — an argument-type check that found a single fixed-arity overload now also considers a varargs overload of a different arity that could bind the call (SLF4J's `debug(String, Object...)` vs `debug(Marker, String, Object, Object)`), and stays silent when either could bind.
- **Bennu** (Java editor): a checked exception thrown while **opening a try-with-resources resource** (`try (X x = mayThrow()) { … } catch (…)`) is no longer falsely reported as unhandled — the resource initializer is correctly treated as protected by the try's `catch` clauses (including a multi-catch `catch (A | B e)`).
- **Bennu** (Java editor): a `var` / Lombok `val` **try-with-resources resource** (`try (val out = new ByteArrayOutputStream())`) is no longer falsely flagged "must implement AutoCloseable" — its type is inferred from the initializer, and with `import lombok.val;` present `val` is no longer mistaken for the `lombok.val` type.
- **Bennu** (Java editor): **overloaded calls now resolve by arity** — a call like `dateFormat.format(new Date())` is typed as `String` (its 1-argument overload) instead of picking a differently-named-arity overload that returns something else (which caused false "incompatible types" errors). Among same-named overloads the editor keeps those whose argument count fits and, on a tie, rules out ones with a clashing primitive/reference argument; when the result is still ambiguous it leaves the expression untyped rather than guessing. Covariant overrides keep their more specific return type.
- **Bennu** (Java editor): a call to a **generic method that throws a type variable** (e.g. `Optional.orElseThrow(() -> new SomeRuntimeException(...))`, declared `throws X`) is no longer falsely flagged "unhandled exception: Throwable must be caught or declared" — the thrown type is whatever the caller supplies (often an unchecked exception), so it's no longer treated as a definitely-thrown checked exception.
- **Bennu** (Java editor): a class referencing a **sibling class in the same package** (no `import` needed, as Java allows) is no longer falsely flagged "cannot resolve symbol", and no longer mis-resolves to a same-named class in another package — a bare type name now resolves to the file's own package first, so its members, casts and exception classification are correct. This also stops a same-package **runtime exception** from being wrongly reported as "must be caught or declared" when another package declares a same-named checked exception.
- **Bennu** (Java editor): a **stream/collector chain** like `list.stream().map(...).collect(Collectors.toList()).indexOf(x)` no longer falsely flags the trailing call — a method's own generic type variable (e.g. `Stream.collect`'s result) is no longer mistaken for the receiver's element type, so `.collect(…)` is no longer wrongly inferred as the element type. Chains through such methods stay unresolved (skipped) rather than mis-typed.
- **Bennu** (Java editor): a **class literal** (`Foo.class`) is now typed as `java.lang.Class`, so `Foo.class.getName()` resolves and completion works after `Foo.class.`.
- **Bennu** (Java editor): an **untyped lambda parameter** (`foo(result -> result.bar())`) is now understood — it's typed from the lambda's target functional interface (the method parameter it's passed as), so its members resolve; and it correctly **shadows** a same-named field, so it's never mis-resolved to that field (which previously produced false "cannot resolve method" errors on the lambda body).
- **Bennu** (Java editor): accessing an element of a project **`@interface`** (`myRoute.value()`, `cfg.count()`) is no longer falsely flagged "cannot resolve method" — an annotation type's elements are now indexed as its (public, no-arg) methods, like a library annotation's.

- **Bennu** (Java editor): a **varargs** method or constructor defined in project source (`void log(String fmt, Object... args)`) now accepts any number of trailing arguments — including **zero** — instead of being falsely flagged "no overload takes N arguments". - Plugin form-DSL: `text` / `password` / `email` / `url` / `textarea` / `number` / `range` fields now accept the same `actions = { change = "…" }` slot, trailing-edge debounced by `debounce_ms` (default 250ms). Filters / live-search / scrub-driven previews no longer need a separate Apply button — the value dispatches as the user types or drags, with the latest value winning during a debounce window. Accepts either a legacy action string or a `DispatchTarget` (scoped per-node, can target a command).
- Plugin form-DSL: `radio` gains an `appearance` prop — `"segment"` renders a pill-style toggle bar (IntelliJ studio-style View switcher), `"card"` renders title+description cards, `"radio"` (the default) keeps classic radio dots.
- "What's New" modal auto-opens once after every upgrade, sourced from the in-app `CHANGELOG.md` and grouped by category. Reachable any time from the Command Palette (*Show What's New*), the About panel, or the Getting Started doc. Fresh installs stay silent — the dialog only pops after a real version bump.

- Commit graph splits into six fully reorderable columns — Graph, Branches / Tags, Subject, Author, Date, Hash. Any column (including Graph) can be dragged to any position; edge-dragging resizes; right-click offers hide / show / reset. ### Fixed

- Plugin form `arbor.ui.form.patch` no longer leaves stale children on screen when merging a fresh child subtree into a `section` / `tabs` / `tree_layout` / `wizard` / `form_field` / `tree` row — the renderer iterates children with a keyed `each`, and freshly-emitted children now go through the same auto-ID step the initial tree gets at mount, so the new markup actually replaces the old.
- F5 (refresh) now also reloads the currently visible diff panel, so externally-modified files appear updated without needing to click off and back on the file.
- Plugin forms no longer silently ignore a click on a menu item, list/card row action, or suggest-grid entry while another action is still running — they now show a brief "action already running" notice (buttons already disabled themselves with a spinner).
- Title bar app mark, hamburger menu, and workspace monogram are now the
  same height, so the left cluster reads as one aligned row.
- Plugins sometimes appeared disabled after launch until the Plugin
  Manager *Refresh* button was clicked. Boot now handshakes with the
  frontend before emitting plugin events, serialises IPC against the
  load thread, and fires the same reload signal the manual refresh
  uses — so sidebars / activity-bar items / command-palette verbs
  appear as soon as the splash dismisses.
- Idle CPU/IPC waste from plugins re-publishing identical state. The
  contribution registry now deduplicates writes by value, so polling
  views (running services, status indicators) no longer fan out

- Global shortcuts (Ctrl+R, Ctrl+B, Alt+Shift+1…, etc.) no longer leak
  through the full-screen diff overlay or any other modal dialog —

  also closes its tab when that workspace is active, so reopening the
  workspace later doesn't resurrect the tab for a repo that's no longer
  a member.
- Diff viewer scrolling no longer stutters on multi-thousand-line files —
  off-screen hunks skip the per-scroll layout work, and chunk navigation
  (F3 / Shift+F3) jumps instantly instead of smooth-scrolling through
  every intermediate hunk.
- Windows taskbar icon goes blank after the system resumes from sleep —
