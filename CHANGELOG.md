# Changelog

All notable changes to Arbor are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Corvus** (Git): **Settings Sync** — mirror your workspaces, settings, installed-mod list and light plugin data to a private GitHub repo (created automatically if it doesn't exist), so a new machine picks up where you left off. Enable it in Settings → Git → *Settings Sync* (choose GitHub; the repo name is optional and auto-generated); it auto-pushes on a configurable interval and via *Sync: Push now* in the Command Palette. *Sync: Pull & merge…* opens a per-item review where you choose local vs. remote for each workspace, settings group, mod state and plugin data — repos are matched by remote URL, and ones missing locally are listed to clone. Repository paths, credentials and heavy caches/indexes are never synced.
- **Bennu** (Java editor): **static imports are now understood** — a statically-imported member used unqualified (`import static java.lang.Math.*;` then `PI`, `max(a, b)`) resolves to its type (hover, chained-call resolution), and the "cannot resolve symbol" check no longer disables itself for the whole file when a static import is present: a specific import and a wildcard from a known type are modelled precisely, so a genuinely undefined name is still caught (only a wildcard from an un-indexed type stays fully conservative).
- **Bennu** (Java editor): **Autosave** — a modified file is now written to disk automatically (a moment after you stop typing, on switching tabs, and when the window loses focus), IntelliJ-style. On by default; **Ctrl+S** still saves explicitly. Toggle it in Settings → Editor → *Autosave* (the choice persists across sessions).
- **Bennu** (Java editor): **type-name completion** — typing a capitalised name (not after a dot) now suggests matching classes from the JDK, your dependencies and your project, each with its package (and a "(+N more)" hint when several packages share the simple name). Accepting one whose name maps to a **single** class also **adds its import** automatically (Settings → Completion → *Auto-import on accept*, on by default); an ambiguous name inserts just the name — **Alt+Enter → Import '…'** picks the package. (Member completion after `.` is unchanged.)
- **Bennu** (Java editor): an **Import class** intention (**Alt+Enter**) — with the caret on a type that isn't imported, add its `import` line in one keystroke (inserted after the package declaration and sorted among existing imports). When several classes share the simple name — across the JDK, dependencies and your project — each is offered as its own entry so you pick which to import; a type in the same package, in `java.lang`, or already wildcard-imported isn't offered.
- **Bennu** (and every code editor): **rainbow brackets** — each `()`/`[]`/`{}` is tinted by its nesting depth (a matching open/close pair shares a colour), so a block reads at a glance which bracket it closes. Skips brackets inside strings and comments.
- **Bennu** (Java editor): a suite of IntelliJ-style editor chrome — **indentation guides** (a vertical line per indent level, each tinted the same rainbow hue as the bracket that opens its block, with the block the caret is in fully highlighted), **sticky scroll** (the enclosing class › method signatures pin to the top as you scroll into a body, click to jump), a **scrollbar overview** that replaces the minimap (errors/warnings marked as bars on the right-edge strip, with a hover preview of the file at that spot, and click/drag to jump), and a top-right **file-health badge** showing the current file's error/warning counts. Each is toggleable in Settings → Editor.
- **Bennu** (Java editor): broader **Lombok** support in code intelligence — `@With`/`@Wither` copy methods (`withName(…)`), a `@Builder` / `@SuperBuilder` entry point (`Foo.builder()…`), and **`@Accessors(fluent = true)`** (getters/setters named after the field — `name()` / `name(v)` — with the chained setter returning the object) are now understood, so those calls resolve and the fluent chain isn't flagged. (Getters/setters, `@Data`/`@Value` and the loggers were already covered.) Lombok is now treated as a **capability**: its generated members, the `@RequiredArgsConstructor`-style blank-final suppression, and the `val` keyword apply **only when the file actually imports Lombok** (`import lombok.…` / `lombok.*`) — which also requires the dependency — so a project with its own same-named `@Data`/`@Getter` annotation (or no Lombok at all) no longer gets phantom getters or a mis-suppressed check.
- **Bennu** (Java editor): **Ctrl+B** / Ctrl+click on a **JDK type** (one with no project source) now opens its **real source** — full method bodies, loops, local variables, lambdas — read from the JDK's bundled `src.zip`, matching IntelliJ's attached-sources view. When the JDK ships no sources (a bare JRE), it falls back to a **decompiled stub** generated from the class's bytecode (package, type declaration, field and method signatures, with a header noting bodies aren't present). Either way the view is cached, so a second jump is instant, and it opens **read-only**.
- **Bennu** (Java editor): the **project tree** now uses IntelliJ-style icons — a distinct glyph per Java type (class / interface / enum / record / annotation), brand-colored icons for JSP / JS / TS / CSS / HTML / JSON / SQL / YAML and other file types, and folders tinted by their source root (main sources, test sources, resources, webapp) so the tree conveys main/test/resource context at a glance.
- **Bennu** (Java editor): **navigate inside library / JDK sources** — Ctrl+B / Ctrl+click on a type or method/field call *within* an opened JDK or library source file now jumps to its declaration (landing on the exact method/field), opening that type's source too, so you can walk from `Optional` into `Supplier` into `Function` like in IntelliJ. Hovering a local/expression there shows its inferred type. (Resolves against the project the source was opened from.)
- **Bennu** (Java editor): **Scan project for mojibake** — a Command Palette command (*Scan project for mojibake…*) opens a modal that scans every text file in the project for UTF-8-decoded-as-Cp1252 corruption (`Ã©` → `é`, `â€™` → `'`), listing the affected files with per-hit `garbled → correct` detail (click a hit to jump to it). One button adds all hits to the **Problems** panel as warnings. (The single-file check on the active buffer already existed.)
- **Bennu** (Java editor): **Download sources for a dependency** — Ctrl+B into a library type whose sources aren't attached opens a decompiled stub with a **"Download sources"** banner; one click fetches that dependency's `-sources.jar` via Maven (as a background job) and reloads the tab with the real source. Already-present `-sources.jar`s in your local `~/.m2` are used automatically, no download needed.
- **Bennu** (Java editor): the background whole-project analysis warm-up (after a project finishes indexing) now shows as an **"Analyzing project" job** in the Jobs overlay while it runs, and clears itself when done — so it's visible that analysis is catching up, instead of silent background CPU.
- **Bennu** (Java editor): in a **Struts config XML**, a `<result>` is now navigable and linted — **Ctrl+B** / Ctrl+click on a JSP path (`/WEB-INF/x.jsp`) opens that JSP, and on an OGNL/EL result (`${urlErrori}`) jumps to the owning action's property; a JSP path that doesn't exist under the web app gets a "JSP not found" warning, and an OGNL root that isn't a property of the action gets the same "doesn't exist on the action" warning as the JSP side.
- **Bennu** (Java editor): **hover** now shows types where they were previously invisible — hovering a `var` / Lombok `val` local (or any local variable / parameter) shows its inferred type, and hovering a JSP form field / OGNL reference / `*-validation.xml` `<field>` shows the bound action property's type and owning class.
- **Bennu** (Java editor): a JSP form field (or an OGNL root, or a `*-validation.xml` `<field>`) now navigates to the **action class's property** — **Ctrl+B** / Ctrl+click jumps to the matching `get`/`set`/`is` accessor (inherited from a project `BaseAction` too) — and a field name that isn't a property of the resolved action gets a **warning squiggle** ("this parameter doesn't exist on the action"). For a **view JSP with no form** (pure OGNL), the action is inferred from the Struts result mappings — direct `<result>/WEB-INF/x.jsp</result>` dispatcher results as well as Tiles — and a toolbar **action picker** lets you pin which action to check against when several map to the page (remembered per file). An **included fragment** inherits the action of the page(s) that include it, so the picker, go-to and warnings work on child JSPs too. Conservative: only when the action resolves to a project class whose properties are known.
- **Bennu** (Java editor): while editing a JSP, the editor toolbar has an **Insert tag** menu that drops a ready-made JSTL/Struts snippet at the caret — `<c:set>`, `<s:set>`, `<s:property>`, `<s:iterator>`, `<c:forEach>`, `<s:if>`/`<c:if>`, `<s:url>`, `<s:text>`, `<s:textfield>` — with placeholder attributes to overtype.
- **Bennu** (Java editor): **Build is now a split-button** — pick *Maven build* or *Validate (no compile)* from its dropdown; the choice is remembered and is what **Ctrl+F9** runs. Validation checks every `.java` file with the editor's diagnostics, reports timing statistics (total time, average per file, slowest file, with a fast/normal/slow verdict) in the Build tool window, and surfaces every problem it finds in the **Problems** panel, grouped by file. Only one build or validation runs at a time.
- **Bennu** (Java editor): **Rename refactoring** with a preview — rename a local variable or parameter (scope-exact, single file), a method or field (declaration plus every cross-file use), or a class (declaration, references, `import` statements, and the matching Spring `<bean class="…">` entries). A preview shows every edit grouped by file before you confirm; edits that can't be resolved precisely (e.g. an overloaded method's call sites) are flagged for review. OGNL and JSP references are not rewritten yet.
- **Bennu** (Java editor): **Build** and **Run** — Build compiles the project (Maven offline, with a `javac` fallback) and turns compiler errors into clickable diagnostics that jump to the offending line; Run launches the chosen main class with the project classpath and streams its output live. A clean build refreshes code completion with the freshly-compiled classes.
- **Bennu** (Java editor): **Go to declaration** (**Ctrl+Click** / **Ctrl+B**) — jump from a class, method, field, local variable or parameter straight to where it's declared; symbols that resolve into the JDK or a dependency jar (no project source) simply don't navigate. When you're already on the declaration itself (a method signature or a variable/class/record declaration) the same gesture shows its usages instead, like IntelliJ.
- **Bennu** (Java editor): **Find usages** (**Alt+F7**) — a caret-anchored list of every place a class, method or field is used across the project; pick one to jump straight to it.
- **Bennu** (Java editor): **Save** (**Ctrl+S**) — edits are now written to disk in the project's encoding, so rename and everyday editing persist.
- **Bennu** (Java editor): **Go to Class** (**Ctrl+N**) and **Go to File** (**Ctrl+Shift+N**) — a filterable quick-open navigator that jumps straight to a class declaration or opens a file by name.
- **Bennu** (Java editor): a **TODO** tool window listing every TODO/FIXME/XXX/HACK marker in the project, grouped by file with per-kind filters; click one to jump to it. Also, opening a binary file (e.g. an image) is now refused with a notice instead of freezing the editor, and the editor's selection highlight is far more visible.
- **Bennu** (Java editor): the **Structure** tool window is now a proper tree — a Java type shows its fields, methods and nested types grouped and nested, each member tagged with a visibility dot (public/protected/private/package), methods that carry an `@Override` annotation showing an override marker, and fields keeping the getter/setter/wither markers. It also works on **XML/JSP** files (`.jsp/.jspf/.tag/.xml/.xsd/.wsdl/.tld/.pom`), showing a nested tag outline with a key attribute (id/name/var/…); click any entry to jump to its line. Its header has **Collapse all** / **Expand all** chevrons like the Project panel.
- **Bennu** (Java editor): **live validation without compiling** — Java files are checked as you type (editor squiggles + Problems panel): syntax errors, expressions that aren't valid statements (`list.clear;`, `1+1;`), calls to methods or accesses to fields that don't exist on the receiver's inferred type, calls with the wrong number of arguments or an argument of the wrong type (`foo(1)` where a `String` is expected), an unresolved `import`, unresolved type names (a typo'd class), invalid casts and assignments/returns of an incompatible type (including `String`/number mixups like `int x = "1"` or `int y = "1" + 1`), missing returns (and returning a value from a `void`/constructor, or nothing from a non-`void`), illegal declarations/modifiers (abstract method in a concrete class, default method outside an interface, record/enum rules, …), illegal `extends`/`implements` (extending a `final` class, record, enum or interface; implementing a non-interface) — now also against your own project's classes and interfaces, not just the JDK/libraries — a concrete class that leaves an inherited abstract method unimplemented, a subclass constructor that must call `super(...)` when the parent has no no-arg constructor, reassigning a `final` variable/field that already has a value or overriding a `final` method, two methods/constructors with the same signature, two fields/parameters/locals/types redeclared with the same name in one scope, unreachable code after a `return`/`throw`/`break`/`continue`, a lambda whose parameter count doesn't match its target functional interface, a `switch` on a type it doesn't accept (`long`/`float`/`double`/`boolean`) or a `switch` expression arm that doesn't produce a value, misplaced annotations, modifying a captured variable in a lambda, a public class not matching its file name, a **package that doesn't match the file's folder** (with two Alt+Enter fixes — set the package to match the folder, or **move the file** into the folder matching its package), the restricted shape of `package-info.java` / `module-info.java`, **language features newer than the project's Java level** (records, sealed types, `var`, text blocks, switch arrows, … — a Lombok-imported `var` is allowed below Java 10), and unused, duplicate or redundant imports (a wildcard on `java.lang` or the file's own package). It complements Build (the real compiler) rather than replacing it.
- **Bennu** (Java editor): the no-compile validation now also catches — a method named the same as its class (a constructor missing its `void`-less shape), generic-syntax errors (generic array creation, instantiating a type parameter, generics in an `instanceof` or `catch`, and `this`/`super` in a static context), two overloads that collide after generic type erasure, the same interface listed twice in an `implements`/`extends` clause, cyclic inheritance, an `@Override` that overrides nothing, an unreachable `catch` (a type already caught above) or a redundant multi-`catch`, a try-with-resources whose resource isn't `AutoCloseable`, an enum `switch` **expression** that doesn't cover every constant, and a `super.method()` that doesn't exist in the superclass — plus warnings for self-assignment, constant division by zero, comparing strings with `==`, `switch` fall-through, a `return`/`break`/`continue` inside `finally`, and a stray empty statement.
- **Bennu** (Java editor): code intelligence now indexes the project's **Maven dependencies** — completion, go-to and no-compile validation resolve library types (Spring, servlet, Hibernate, Struts, …), not just the JDK and your own sources, so calls and types that come from a dependency are understood instead of silently skipped. The dependency jar list is resolved once per `pom.xml` and cached across sessions.
- **Bennu** (Java editor): the no-compile validation now also catches — a `var` local that can't infer its type (initialized with a lambda, a method reference, an array initializer or `null`), an override whose return type isn't covariant (`String` overriding a `Number` method), and a local captured by a lambda or anonymous/inner class that is then reassigned (not effectively final).
- **Bennu** (Java editor): the no-compile validation now flags the **wrong number of type arguments** — `List<String, Integer>` (a `List` takes one) or `Map<String>` (a `Map` takes two) — for JDK, library and your own generic types. Conservative: only when the type resolves and its exact generic arity is known; the diamond `<>`, wildcards and raw types are never flagged.
- **Bennu** (Java editor): a scrollable **minimap** in the editor's right gutter for bird's-eye navigation (toggle in Settings → Editor), and **Emmet** abbreviation expansion on **Tab** in JSP/HTML files (`ul>li*3`, `div#app`, …).
- **Bennu** (Java editor): syntax highlighting for the whole legacy stack, not just Java — XML/JSP, `.properties`, YAML, JSON, Markdown, HTML, CSS/SCSS, JavaScript and SQL files now open with proper colouring.
- **Bennu** (Java editor): the **Problems** panel is now grouped into a tree — a **JDK** section (warns when no JDK is installed or a fallback JDK is standing in for the level the project targets), an **Encoding** section listing the files that weren't valid in the project's declared encoding (click to open), and the active file's diagnostics.
- **Bennu** (Java editor): a **titlebar warning** appears when no JDK is installed (completion and navigation can't resolve the standard library); clicking it opens Settings. You can now add **extra JDK search paths** in Settings → JDK for a JDK installed somewhere non-standard.

Results stream in **progressively** as the scan walks the tree, so a large legacy project fills the list incrementally instead of freezing until the end.

### Changed

- **Bennu** (Java editor): the **Problems panel is now grouped by severity** — top-level **Errors** and **Warnings** nodes, each split by source (JDK, Encoding, and one node per file), so you can scan all errors first. A file with both errors and warnings appears under each with just its rows of that severity; every node is collapsible.
- **Bennu** (Java editor): the **Problems panel now updates live** for the file you're editing — fix a problem and it disappears, introduce one and it appears, without re-running the whole-project validation; that file's entry stays correct across the panel even after you switch away. Once you've run *Validate (no compile)* once, **saving** also silently refreshes the whole panel, so a fix that clears an error in a *different* file (one depending on what you changed) updates there too.
- **Bennu** (Java editor): **project validation ("Validate — no compile") is now incremental and parallel** — each file's diagnostics are cached against the exact project types it depends on, so re-validating an unchanged project is near-instant and editing a file re-checks only that file (and anything whose types it changed); the validation itself now runs across CPU cores. On a ~1,800-file legacy project a full validation drops from ~23s to ~6s (cold) and re-validation to well under a second, with identical results. By default the cache is also **warmed up in the background right after a project finishes indexing**, so the first explicit validation is already instant — turn this off in Settings → Java → *Validate project on open* if you'd rather not spend the CPU on open.
- **Bennu** (Java editor): **opening a large project is now instant** — the editor becomes usable as soon as the index is built, and the whole-project validation warm-up runs in the background *after* that instead of holding the project "not ready" until it finished. On a ~1,300-file project with many dependencies this turns a ~2-minute wait into an immediately usable editor (completion, go-to and per-file diagnostics were already live); the warm-up still fills the diagnostic cache as a background pass and is abandoned if you re-index.
- **Bennu** (Java editor): **typing stays responsive on large files** — live validation is now two-tier (IntelliJ-style): a fast pass paints syntax/structure squiggles (syntax errors, unused imports, unreachable code, duplicate signatures, …) almost immediately, and the heavier semantic pass (unknown members, type mismatches, inheritance, …) runs only after a short idle instead of on every keystroke. Same diagnostics in the end, far less work while you're actively typing.
- **Bennu** (Java editor): the semantic pass is now **incremental per method** — typing inside one method re-checks only that method's body and reuses the rest of the file's cached diagnostics, so a big legacy class stays fast to re-validate keystroke to keystroke (a signature/field/import change, or editing another file the class depends on, still re-checks what's needed). Identical diagnostics to a full check.
- **Bennu** (Java editor): the whole-project validation no longer **pegs every CPU core** — it now uses at most about **half the cores** by default (leaving headroom for the UI, go-to and completion, so the editor stays responsive during a big sweep), and you can cap it explicitly in Settings → Java → *Validation CPU threads* (set `1` for single-threaded). It's also **cancellable** now: a **Cancel** button on the "Validating…" status in the Build panel stops the sweep (and discards its partial results) so you can reclaim the machine.
- **Bennu** (Java editor): **go-to-declaration and completion no longer stall right after you type** — editing a file used to throw away the whole resolved-type memo, so the next Ctrl+click / completion re-decoded every JDK and library type from scratch. An edit now only invalidates the types declared in the file you changed, keeping every other type warm.
- The launcher now reduces to the system tray when it loses focus (JetBrains-Toolbox style) — launch a product or click away and it steps aside; bring it back from the tray icon.
- The Git backend process now starts the first time you open Corvus rather than at app launch, so sitting on the launcher (or using only the File Explorer / music windows) no longer keeps a git backend running in the background.
- The integrated terminal now batches high-rate output into a short coalescing window instead of emitting an event per read, so heavy output (build logs, `cat` of a large file) no longer floods the UI — smoother rendering with no perceptible added latency.
- Keybindings are no longer a Settings section — viewing and customising shortcuts now live together in the dedicated Keyboard Shortcuts panel (**Shift+F1**).
- Plugins can now route a notification, background job, or progress operation to a specific window via an optional `target` (`arbor.notify`, `arbor.job.spawn`, `arbor.ui.operation.start`); without it they go to the main window as before.

- **Bennu** (Java editor): a class referencing a **sibling class in the same package** (no `import` needed, as Java allows) is no longer falsely flagged "cannot resolve symbol", and no longer mis-resolves to a same-named class in another package — a bare type name now resolves to the file's own package first, so its members, casts and exception classification are correct. Chains through such methods stay unresolved (skipped) rather than mis-typed.

- **Bennu** (Java editor): an **untyped lambda parameter** (`foo(result -> result.bar())`) is now understood — it's typed from the lambda's target functional interface (the method parameter it's passed as), so its members resolve; and it correctly **shadows** a same-named field, so it's never mis-resolved to that field (which previously produced false "cannot resolve method" errors on the lambda body).

- Branches / Tags column rendering: local branches use a monitor icon, remote branches a globe icon; chips are now squared off (matching tag shape); branch names stretch with the column width instead of capping at 180px; multiple tags on a single commit collapse into a click-to-expand chip (also triggered when any tag shares a row with one or more branches). The standalone HEAD pill is gone — the HEAD branch is already styled green so the duplicate badge was noise. Default dark theme's lane-3 colour shifted from magenta-purple to indigo, and the four community themes that shipped `lane-3` literally identical to `color-tag` (Ayu Dark/Light, Solarized Dark/Light) were also retuned so branch chips on that lane don't read as tags.
- The WIP (working directory) row now lives inside the scrolling history pane, pinned just below the sticky column header. It uses the same grid layout as the commit rows so the dashed lane node lines up with the lane SVG behind it, and the "Working Directory" label / change pills sit in the Subject column — wherever the user has dragged it. It stays visible while exploring older history. Scroll-area lateral inset bumped to match the toolbar's so header, WIP and rows share the same 4 px left/right gap as the toolbar above.
- Branches sidebar groups local & remote branches and worktrees by their `/` path segments — GitKraken / Fork style folder tree with collapsible, lane-colour-matched folders. On by default; toggle from the folder-tree icon in the sidebar header (always visible, next to refresh), the **Alt+Shift+G** shortcut, or the Command Palette entry *Branches: Group by Path*. The on/off and collapsed-folder state is per-repo (saved in `.arbor/config.toml`); a host-wide `branches.grouping_recursive` knob flips between deep split and single-level.
- Plugins can mount a full main-area view via `arbor.ui.add_view` — a body surface (where the commit graph lives) that renders form-DSL content with the full node + dispatch/patch protocol. It surfaces as an activity-bar icon, a Command Palette entry, and the **Alt+Shift+V** toggle; `placement = "graph"` keeps the tab bar and bottom panel, `placement = "main"` takes over the whole body. New `on_view_open` / `on_view_close` hooks fire on the owning plugin.
- Plugins can embed an editable code/text editor in a form via the new `editor` node — a CodeMirror 6 field with syntax highlighting, line numbers and search. Its content is submitted like any field and can be pushed from the plugin with `set_value`; it can also emit scoped, debounced `on_edit` and `on_select` events for live, high-frequency UIs.
- Plugins can embed a read-only diff viewer in a form via the new `diff` node — unified and split layouts (local toggle), syntax highlighting and virtualization for large diffs. The plugin supplies the diffed hunks; updating them live is a `patch` away.
- The plugin form `tree` node gains a dynamic "data tree" mode — `lazy` children fetched on expand (the row fires a scoped `on_expand`, the plugin fills it with a `patch`), a scoped `on_select`, full keyboard navigation (arrows / Home / End / Enter), and row virtualization for large trees. Static trees are unchanged.
- Plugin form value slots can opt into *scoped dispatch*: a `select` `actions.change`, a leaf `field`, or a `vec_field` whose change targets a `dispatch` object (action or command) now ships a compact `{ node_id, slot, value, state? }` payload instead of the whole form, tracked per node so concurrent edits don't block each other. Declare `scope_state` to include a slice of the opaque form state. Bare-string actions are unchanged.
- Plugins can patch an open form's node tree granularly via `arbor.ui.form.patch(ops)` — merge props, append children, or remove nodes addressed by stable `id` without re-mounting — and mutate a single slice of the opaque form state via `arbor.ui.form.set_state_path(segments, value)` (passing `nil` deletes the key).
- Plugins can invoke each other's commands. A command registered as `invocable` can be fired by another plugin via `arbor.command.fire("<owner>::<id>")` or a form button's `dispatch = { kind = "command", … }`, gated by the new `command_invoke` permission plus the command's declared `required` tier.
- Plugins can invoke host built-in commands the same way — `arbor:git.commit|push|fetch|pull|branch_create|checkout|branch_delete|stage_all|unstage_all` (require `git = "write"`), plus `arbor:repo.refresh` and `arbor:app.open_settings` (no tier). Closed by default and gated by `command_invoke` + the declared tier; git commands target `ctx.tab_id` or the active tab.
- IntelliJ-style "compact middle packages" for file trees — *Settings → Interface → Compact file tree folders* collapses chains of single-child directories into a single row across the Files sidebar, the Stage area tree, and the commit detail file list. Also exposed as a Command Palette toggle. Conflict file lists always compact regardless of the setting.
- Markdown editor with Obsidian-style live preview — open any `.md` /
  `.markdown` file via the Files sidebar context menu and edit it
  in-place. Markdown markup is concealed per inline component: only
  the element under the cursor reveals its raw syntax (e.g. editing
  one `**bold**` word doesn't reveal the sibling `*italic*` on the
  same line). Fenced code blocks are syntax-highlighted through Prism
  so the rendering matches DiffViewer and blame. The eye button in the
  header toggles read-only; `Ctrl+S` saves.
- Shortcut **F11** toggles the full-screen diff overlay for the currently
  visible diff (stage panel, commit detail, MR detail). Press again from
  inside the overlay to dismiss.
- Command Palette verbs *Linear Issue* and *Jira Issue* — cross-tab
  ticket search that opens the detail modal pinned to the picked
  provider, visible only when signed in to that tracker. Same `#` / `~`
  query prefixes as the Issues sidebar; no per-project scoping applied.
- Minimize button on long-form dialogs (MR detail, Issue detail): parks
  a "reopen" shortcut in the status-bar dock so you can roam to other
  tabs / workspaces and pick the workflow back up later. Click a chip
  to switch to the original tab and re-open the dialog; ✕ to discard.
  Surviving workspace and tab switches comes from the action-based
  design — the chip outlives the modal component, so unsubmitted text
  and scroll position aren't preserved across the round trip. The cap
  (default 5, max 20) lives under *Settings → Appearance → Minimized
  dialogs cap*.
- Markdown editor inline media: `![alt](url)` references render as a
  real `<img>` (or `<video controls>` / `<audio controls>` based on
  the file extension — `.mp4` / `.webm` / `.mov`, `.mp3` / `.wav` /
  `.m4a`). URLs can be `http(s):`, `data:`, or filesystem paths
  relative to the markdown file (resolved through Tauri's asset
  protocol). Bare URLs on their own line are recognised too. GitHub
  user-attachments video URLs render as an "Open in browser" card
  (their signed-redirect chain can't be followed from an embedded
  WebView), so the system browser handles playback while the rest of
  the README stays in the editor. Caret on the source reveals the
  raw `![…](…)` for editing.

### Fixed

- Plugin form `arbor.ui.form.patch` no longer leaves stale children on screen when merging a fresh child subtree into a `section` / `tabs` / `tree_layout` / `wizard` / `form_field` / `tree` row — the renderer iterates children with a keyed `each`, and freshly-emitted children now go through the same auto-ID step the initial tree gets at mount, so the new markup actually replaces the old.
- F5 (refresh) now also reloads the currently visible diff panel, so externally-modified files appear updated without needing to click off and back on the file.
- Plugin forms no longer silently ignore a click on a menu item, list/card row action, or suggest-grid entry while another action is still running — they now show a brief "action already running" notice (buttons already disabled themselves with a spinner).
- Title bar app mark, hamburger menu, and workspace monogram are now the
  same height, so the left cluster reads as one aligned row.
- Plugins sometimes appeared disabled after launch until the Plugin
  Manager *Refresh* button was clicked. Boot now handshakes with the
  frontend before emitting plugin events, serialises IPC against the
  load thread, and fires the same reload signal the manual refresh
  uses — so sidebars / activity-bar items / command-palette verbs
  appear as soon as the splash dismisses.
- Idle CPU/IPC waste from plugins re-publishing identical state. The
  contribution registry now deduplicates writes by value, so polling
  views (running services, status indicators) no longer fan out
  frontend refetches when nothing actually changed.
- Global shortcuts (Ctrl+R, Ctrl+B, Alt+Shift+1…, etc.) no longer leak
  through the full-screen diff overlay or any other modal dialog —
  pressing a bound chord on top of a modal is now a no-op instead of
  firing the underlying action.
- Removing a repository from a workspace via the Workspace Manager now
  also closes its tab when that workspace is active, so reopening the
  workspace later doesn't resurrect the tab for a repo that's no longer
  a member.
- Diff viewer scrolling no longer stutters on multi-thousand-line files —
  off-screen hunks skip the per-scroll layout work, and chunk navigation
  (F3 / Shift+F3) jumps instantly instead of smooth-scrolling through
  every intermediate hunk.
- Windows taskbar icon goes blank after the system resumes from sleep —
  re-applied on every power-resume notification.
- Repository Browser: cloning from the in-app browser sometimes left the
  Clone button stuck in *Cloning…* even after the repo had been cloned;
  the modal now dismisses as soon as the clone itself succeeds and the
  workspace setup runs afterwards.

## [0.2.0] — 2026-05-24

### Added

- First-run welcome tour covering Git identity, provider connection, opening
  the first repo, Command Palette, plugin marketplace, ticket chips, linked
  worktrees and workspaces. Reopenable from the Command Palette (*Welcome
  Tour*) or the Docs panel.
- Appearance settings: Activity bar position (Left / Right / Hidden with
  edge-hover reveal), Compact title bar toggle, diff Tab width (2 / 4 / 8),
  and a switch between Mac-style coloured window controls and a flat
  Windows/IntelliJ set (also restyles close buttons in modals and panel
  headers).
- Marketplace registry can list external plugins via a one-line pointer to a
  third-party GitHub repo instead of vendoring the code. Entries without a
  `pinned_sha` get an "Unpinned" badge.
- Plugin Marketplace is reachable from the Command Palette and via
  `Alt+Shift+M`.
- Command Palette: *View MR / PR Detail* verb. Autocomplete fetches MRs
  across all states lazily and caches per tab, independent from the sidebar
  state filter.
- `Ctrl+Shift+Enter` in the commit message field commits and pushes.
- Commit split-button menu shows shortcut hints and tinted icons, matching
  the graph context menu.
- Keyboard navigation in the commit graph: Up/Down follow the current lane,
  Left/Right hop to sibling lanes, PageUp/PageDown jump a viewport,
  Home/End jump to newest/oldest loaded commit. `Alt+G` focuses the graph.
- Workspace Manager: Up/Down walks groups, workspaces and repo rows, Space
  expands/collapses, Enter on a repo opens it. Down from the search box
  drops into the list.
- File/folder picker: F6 (Shift+F6 reverse) cycles focus between the file
  list, sidebar locations and address bar; Up/Down walks the sidebar.
- F6 / Shift+F6 cycles focus across the main layout zones (titlebar, tabs,
  activity bars, sidebar, graph, bottom panel, status bar). Hidden zones
  are skipped.

### Changed

- Checkout (branch, detached commit, remote tracking branch) auto-stashes a
  dirty working directory, switches HEAD, then reapplies the stash — same
  flow as Pull. If the reapply conflicts, the resolution modal opens with
  the stash kept at index 0.
- Plugin enable / disable / uninstall cascades along required dependencies.
  Disabling asks for confirmation and turns off every transitively-required
  dependent (leaves first). Enabling with required deps off asks to turn
  them on first, and refuses if a required dep is missing. Uninstalling
  disables dependents so they don't keep running against a vanished
  service. Plugin Manager detail rows show "Depends on" and "Required by".
- Marketplace install resolves transitive required deps against the catalog.
  The confirm modal lists "Will also install: …" and downloads in dep-first
  order. Required deps not in the catalog block the install.
- Settings moved from localStorage to `~/.config/arbor/config.toml`: font
  scale, animations and speed, commit-template fallback, diff settings
  (algorithm, context, view mode, word-wrap, confirm-discard), graph page
  size, branch / tag visibility, ticket-link chips, "use theme fonts". They
  now survive WebView cache clears and can be edited from disk.
- Every remaining native `confirm()` is gone: Delete Branch, Delete Tag,
  Drop Stash, Reset Hard, Discard All, Undo Last Commit, Unlink Worktree,
  Delete Theme, Delete Worktree Link, Remove Alias Group, Clear Pipeline
  Logs, RON Studio Format and Convert-to-JSON now use the in-app confirm
  modal with Enter-to-confirm.
- Command Palette: *Delete Tag* split into *Delete Tag (local)* and *Delete
  Tag (local + origin)*, sharing the sidebar's scope-aware confirm modal.
- Conflict resolution modal: clicking *Apply resolution* / *Merge* /
  *Complete* with unresolved files jumps to the first unresolved file and
  shows a toast, instead of a hover-only tooltip on a disabled button.
- Conflict resolution toolbar: the action button is always labelled *Stage
  file*, including for modify/delete and add/modify conflicts (the choice
  is made in the two cards underneath).
- "Stash changes" prompt and full-screen diff viewer use the standard modal
  shell (backdrop, focus trap, ESC, animation).
- Welcome tour and plugin form wizard share the same step indicator widget.
- Docs pages use the shared Callout and Kbd widgets, so displayed
  keybindings reflect user remaps live.

### Removed

- Inline hover buttons (Apply / Pop / Drop) on stash markers in the graph.
  Use right-click, the sidebar Stash list, or the Command Palette.

### Fixed

- Enabling/disabling a plugin from the Marketplace detail pane refreshes
  the Plugin Manager if it's open in the background.
- Escape on a file/folder picker opened from inside another modal (Theme
  Editor, Add Worktree, Clone Repository, Studio export, …) closes only
  the picker.
- Settings, Docs, About and Studio modals show a backdrop with a spinner
  on cold start instead of feeling dropped while the module loads.
- Dropdowns are fully keyboard-driven: Tab in an open menu closes it and
  moves to the next field, Escape returns focus to the trigger,
  ArrowDown (or Alt+ArrowDown) on a focused trigger opens the menu on the

- MR / PR sidebar no longer shows a raw 404 when the remote has pull/merge
  requests disabled — sidebar, palette entries and `arbor://mr/open/<n>`
  report the feature as unavailable.
- Plugin Logs panel surfaces failures that used to be terminal-only:
  runtime errors from hook handlers and service callbacks,
  `arbor.ui.tree.set` payload validation errors, malformed `plugin.toml`
  manifests (the broken folder also shows up in the Plugin Manager as
  "Failed to load").
- Restored Unicode glyphs (em-dashes, arrows, box-drawing, bullets) in the
  Docs pages and Markdown/HTML exports, corrupted by a previous round-trip
  through Windows-1252.
- Clone Repository: the folder-picker button in the Base folder field is
  reachable via Tab.
- Docs Markdown export preserves inline `<code>` inside table cells and
  headings (previously stripped by GitHub's renderer).
- Modals no longer pop a tooltip on the freshly-focused control when they
  open. Share-worktree button in the Workspace Info header now has proper
  icon-button styling.
