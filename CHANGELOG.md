# Changelog

All notable changes to Arbor are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Picus** (SQL studio): a **trigger now shows what it does** — the `CREATE TRIGGER` the server writes itself, and the source of the routine it fires. When it fires was always the easy half of the question, and the other half meant working out which script installed this version.
- **Picus** (SQL studio): **right-click in the editor** — cut, copy, paste, and **Generate**: a skeleton for a table, view, sequence, trigger, function or procedure, written at the caret in the dialect of the buffer. A PostgreSQL trigger arrives with the `RETURNS trigger` function it cannot exist without; an Oracle one carries its body inline.
- **Picus** (SQL studio): **a script can be saved** (<kbd>Ctrl</kbd>+<kbd>S</kbd>), in its own encoding and line endings, and the repository is re-read and re-checked immediately afterwards. A character the file's declared encoding cannot represent stops the save with a reason instead of being written as `?`.
- **Picus** (SQL studio): **Results and Output have their own rail buttons** — Results on the right with the document it belongs to, carrying a dot while a statement is running; Output on the left with Consistency, where the session's log belongs.

- **Picus** (SQL studio): the SQL shorthand grew **three verbs and a row template**. `m#ordini[id]` is an upsert — `INSERT … ON CONFLICT` on PostgreSQL, `MERGE … USING dual` on Oracle, with the brackets naming the key columns rather than a `WHERE`. `a#ordini+nota:varchar(200)~importo:number(12,2)` adds and retypes columns, translating the type into each engine's spelling and refusing to add one that is already there or retype one that is not. `fc#ordini[stato='EV']` writes the cursor loop, joins included. And `i#ordini(id,codice)*3{$, 'COD_$'}` writes three rows that differ, with Emmet's `$` numbering (`$$$` pads, `$@5` starts elsewhere, `$@-` counts down, `\$` is a literal).
- **Picus** (SQL studio): a result can be taken out as **CSV, JSON, a Markdown table or `INSERT` statements**, to the clipboard or to a file. The `INSERT`s go through the same emitter the generator uses, so quoting comes from each column's declared type and Oracle gets one statement per row where PostgreSQL gets one with a tuple each.
- **Picus** (SQL studio): **rows can be edited in the grid.** Double-click a cell; nothing is written until **Store** (<kbd>Ctrl</kbd>+<kbd>S</kbd>), and **Restore** puts everything back. The SQL that ran is shown afterwards. Offered only when a row can be addressed — one source table, a primary key, and that key in the result — and the `WHERE` is built from the values the row was read with, so a key column can itself be edited.
- **Picus** (SQL studio): a read **no longer fetches large objects**, however the statement asked for them. A `bytea` or `blob` column shows its size, and clicking the cell reads that one value — text as text, bytes as a hex dump, with a Save that writes the real bytes. Which columns those are is decided from what the result contains rather than from reading the SQL, so a relation tab, `SELECT *`, `SELECT allegato` and a join all behave the same. Opening a cell still needs a key column in the result; without one the sizes are shown and say so.
- **Picus** (SQL studio): **structural replace in the open document** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>M</kbd>) — the same `$name$` patterns as the repository-wide one, in a panel beside the editor, finding as you type. Replace all is a single edit, so <kbd>Ctrl</kbd>+<kbd>Z</kbd> takes the whole thing back.
- **Picus** (SQL studio): **unsaved query tabs survive the window closing** — their text, title and connection are remembered and re-opened.
- **Picus** (SQL studio): **find and replace** in the editor (<kbd>Ctrl</kbd>+<kbd>F</kbd> or <kbd>Ctrl</kbd>+<kbd>H</kbd>), and <kbd>Ctrl</kbd>+<kbd>Click</kbd> on a name in the SQL opens that object's structure.
- **Picus** (SQL studio): **the editor underlines what the parser cannot read** — procedural code outside a routine, an unclosed parenthesis, a missing keyword. The syntax-tree panel has always known these; the editor beside it showed nothing, so a statement that could not possibly run looked fine until it was run.
- **Picus** (SQL studio): **an abbreviation is marked as one** instead of being coloured as SQL, which it is not — a tinted band while it will expand, a warning one when the backend refuses it.
- **Editor** (every product): a host can hand the editor **ranges to highlight** on top of the language's own colouring, for text that is not the buffer's language.
- **Editor** (every product): <kbd>Ctrl</kbd>+<kbd>D</kbd> duplicates the selection or the line, <kbd>Alt</kbd>+<kbd>J</kbd> adds the next occurrence as a cursor, and <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> moves a line alongside <kbd>Alt</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd>.
- **Picus** (SQL studio): the **time a statement took** is shown for writes as well as reads, and for a whole `Run all`.
- **Picus** (SQL studio): an update or a delete can carry a **composite `WHERE`** — conditions with `=`, `<>`, `<`, `<=`, `>`, `>=`, `LIKE`, `NOT LIKE`, `IN`, `NOT IN`, `IS NULL`, `IS NOT NULL` and `BETWEEN`, nested in `AND`/`OR` groups, built as a tree rather than typed as text so the rest of the product still knows what the script does. It replaces the comparison key rather than narrowing it, groups are always parenthesised in the emitted SQL, and an unfinished condition stops the generation instead of being guessed at.
- **Picus** (SQL studio): **an update or a delete with neither a comparison key nor a `WHERE` is refused.** It would touch every row in the table, it was one keystroke away, and it is not recoverable.
- **Picus** (SQL studio): **structural search and replace** across the repository (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>). A pattern is the statement itself with holes in it — `$name$` for one node, `$name...$` for a list — matched against the parsed scripts, so formatting, line breaks and comments in the middle change nothing. Replacements can reorder what they captured (`$vals.1$, $vals.0$`), and the write carries the same digests a generation does: nothing is written that has not been seen, and a file that moved stops it.
- **Picus** (SQL studio): the same pattern with **no replacement is a query over the repository** — the results are a grid with a column per placeholder, exportable as CSV, JSON or a Markdown table, to the clipboard or to a file.
- **Picus** (SQL studio): a replacement can address **a value by the column it belongs to** rather than by position — `$vals[cols=keycode]$` is "the value at the index where the column list says `keycode`". One template then normalises every statement to one column order whatever order it was written in, and a statement missing that column is reported on its own row instead of having a value quietly shifted into the wrong column.
- **Picus** (SQL studio): **Compare** groups those matches by one placeholder and lists the distinct values commonest first, which turns the pattern into a consistency check: search every `INSERT` on a table and compare the column list, and eleven statements out of ten thousand that write the columns in another order are one click away — shown, not rewritten.
- **Picus** (SQL studio): a **syntax-tree panel** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Y</kbd>) showing how the parser read the open document — click a node to select its text, move the caret and the tree opens to it. It follows the buffer rather than the file, keeps the punctuation visible because a stray comma is usually the answer, and still works on a file that will not parse.
- **Picus** (SQL studio): **an upsert into an initialisation is written as a plain `INSERT`** — that script runs once against an empty database, so "insert if missing" is answered by reading the scripts rather than by a `MERGE`, and a row already seeded is changed where it is. A **portable** initialisation can therefore take one, where before it refused: there is no portable `MERGE`, but a portable `INSERT` is as portable as SQL gets.
- **Picus** (SQL studio): the guided form **works for a table only the scripts install**. Its columns and their types are read from what the repository's own statements write into it, so picking such a table no longer produces a form with no fields at all; a table nothing anywhere describes says so instead of coming up empty.
- **Picus** (SQL studio): the generator now **reads the scripts before writing into them**. A row any script of that engine already installs is re-stated in an update as `DELETE` by key then `INSERT`, and *changed where it is* in the initialisation rather than added a second time — even when that is a different file, which then joins the diff with its own reason.
- **Picus** (SQL studio): statements go **inside a block that already guards the same versions** instead of into a second block on the same range, which would run twice on a fresh install and never on an upgraded one. What is spliced in carries its own marker, so regenerating replaces it rather than adding a copy each run.
- **Picus** (SQL studio): **destinations can be saved as a named set** and armed again in one click, with the repository so a colleague finds them too. The saved sets open the Generate DML sidebar panel, with the one matching what is armed marked, and each is addressable by name from the command palette. A set stores folders rather than paths where the repository's naming scheme can name the next update file, so it still works next release; where it cannot, the entry keeps its file name and its version bounds and says so, rather than becoming a destination with no file and an empty guard. Saving under an existing name replaces it — offered on the set's own row and in the dialog, which lists what is already there.
- **Picus** (SQL studio): the **guided form composes as many rows as you like** instead of one. A strip above the fields walks them, duplicates the current one, and marks the row holding a value that cannot be written.
- **Picus** (SQL studio): **Go to** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>O</kbd>) — one box over every script, indexed object and connection, matching loosely and in order so `agg pos` finds `AGGIORNAMENTO/2024/POS/4_13.sql`. `sort:new`, `ext:sql` and `in:FOLDER` narrow it. The overlay is shared chrome, so Bennu gets the same box over its own lists.
- **Picus** (SQL studio): a repository that installs **several products into one version table** can now say so — each product declares the predicate that selects its row, each folder declares which product's scripts it holds, and a generated block stamps the right one. A destination can also override the row for a one-off.
- **Picus** (SQL studio): **individual objects can be excluded from the rules** by name — the staging table one dialect fills, the log the installer writes, the legacy table kept for one customer. Better than switching a rule off to silence one table, which stops it watching the other four hundred. They stay in the Inventory with their coverage.
- **Picus** (SQL studio): the **comparison between the two dialects can be switched off** for a repository whose halves have drifted too far apart for it to say anything actionable. The version chain, the duplicates, the dangerous DML and the encodings all keep working, and the two rules report themselves as not run.
- **Picus** (SQL studio): a project now states **what its initialisation folders are** relative to its updates, and **which rules it wants run**. Both live in the repository's own configuration, so a colleague opening the same folder gets the same verdict; a rule that is switched off is reported as a rule that did not run, never as silence.
- **Picus** (SQL studio): **findings can be copied** — one from its row, or the whole report as it is filtered, from the panel header or the command palette. A report usually ends up in a ticket or a message, and retyping a rule id and a path is where a character goes missing.
- **Picus** (SQL studio): a **coverage number is now a way in** — click a cell in the Inventory and it lists the statements it counted, each one a jump to the file and line. Zeroes open too: "nothing here" is the answer people most want to check.
- **Picus** (SQL studio): **Run all** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Enter</kbd>) executes every statement in a query tab in order, stopping at the first failure.
- **Picus** (SQL studio): **an Emmet-style shorthand for SQL** — type `s#localstrings(keycode,value)[keycode='ita']` in a query and the statement it stands for appears greyed out; <kbd>Tab</kbd> writes it. It knows the database it is pointed at: the column's type decides where the quotes go, `>` joins a table through its foreign key, and anything it cannot resolve is refused with the reason on the line instead of guessed at.
- **Picus** (SQL studio): **a folder or a single script can be excluded from the project** — the migration scripts nobody wants counted are no longer read, indexed, checked or offered as a destination, while one script inside an excluded folder can be kept. Excluded rows stay in the tree, marked; this is not the *ignored* role, whose folders are still read and still checked.
- **Picus** (SQL studio): a **single script can now say which engine it is written for**, so a folder holding `4_12_ORA.sql` beside `4_12_POS.sql` is understood instead of left unclassified — it takes part in both engines' comparisons, each file is checked against the right dialect, and its inventory column splits per engine. A declared folder name can be pointed at file names as well; Picus still never guesses an engine from a file name on its own.
- **Picus** (SQL studio): set a script's engine from its row in the tree, or from a new dialog on <kbd>F6</kbd>; a file row shows an engine only when it says something its folder does not. When a classification is offered as a rule for the whole repository, the offer now asks whether the name means something in folder names, file names or both, and counts what each would reach.

### Changed

- **Picus, Merula, Bennu, Tyto**: the documentation panel **exports** — a Markdown README or a self-contained styled HTML page, every topic in nav order with a table of contents. It was Arbor's panel only; the converter was already shared, so it now sits in the panel every product uses and each one names its own file.
- **Picus** (SQL studio): triggers in the schema tree are **grouped by what fires them** — `BEFORE INSERT`, `AFTER INSERT/UPDATE/DELETE` — so the row is the trigger's name and the hover says which table. The timing and the events were repeated on every row, where they are the same for a whole run and long enough to squeeze the names down to five characters.
- **Picus** (SQL studio): **completion knows what may go where.** An empty statement offers the words that can open one and no longer answers with every table in the database; after `INSERT`, `GROUP` or `DROP` it offers only what can follow. Keywords are no longer cut off by the option ceiling — typing `SEL` against a real schema offers `SELECT` again. A column name carried by two tables in scope is offered only qualified, functions complete as `NAME()` with the caret inside, and a sequence completes to `SEQ.NEXTVAL` or `nextval('seq')` as the engine requires.
- **Picus** (SQL studio): in `FROM` and `JOIN`, tables reachable by a **foreign key** from what the statement already names are ranked first and say which key put them there.
- **Picus** (SQL studio): the consistency report's group bars and a relation's rows keep a few pixels clear of the panel's side walls, like the toolbar above them.
- **Picus** (SQL studio): the editor's **Generate submenu carries the icons** the sidebar, the inventory and Go to already use for those objects.
- **Picus** (SQL studio): the bottom dock holds **one panel at a time**, opened by its own button on a rail — Results, Consistency, Output, Changes — instead of one panel with a four-tab strip inside it. Each panel owns its title, its count and its actions, which is a whole row of chrome back.
- **Picus** (SQL studio): **Generate is a submenu** in the editor's right-click menu, so cut, copy and paste stay at the top of a list of four rather than of nine.
- **Picus** (SQL studio): the generator's cards are **no longer filled grey** — they are the page with a border, and only what sits inside them is raised. The toolbar floats a few pixels clear of the panel's edges instead of running wall to wall, and the tab strip has room above it.
- **Result grid** (every product): the column header and the filter row are **no longer grey**. They sat on the same elevated tone as the toolbar above them, so a table opened with three grey bands stacked before the first row of data — which is most of why one read as all chrome.
- **Picus** (SQL studio): the **connection dialog is four pages** — Identity, Server, Scripts, Session — instead of one scroll of five headed sections. A page holding a required field that is still empty is marked, so a disabled Save always has a visible reason.
- **Picus** (SQL studio): a **sequence and a trigger have no toolbar**. Everything one carried was about something they do not have: sub-views, a new row, DML from the columns, a CSV export.
- **Picus** (SQL studio): a script's **path, engine and encoding are on the toolbar**, not on a second bar of their own underneath it — and the magnifier is gone, since <kbd>Ctrl</kbd>+<kbd>F</kbd> opens the same panel and a button duplicating a binding is a button that has to be kept in step with it.
- **Every product**: all interface text now sits on **one eight-step type scale**. There were seventeen hardcoded sizes, half a pixel apart in places, which is not a hierarchy but drift — and the **Font scale** setting only moved the fraction of the interface that happened to use a token, so raising it enlarged the chrome and left the data it was meant to help you read exactly as small.
- **Every product**: the close control on panels and dialogs is an **✕** rather than a filled red disc. A saturated red circle inside a panel header reads as a warning, and window controls keep whichever platform style you chose.
- **Every product**: a **count badge is quiet**. Four solid accent bubbles down a sidebar made a set of tallies the loudest thing in the panel; vivid colour is for state.
- **Picus** (SQL studio): the **result dock opens to about half the window** instead of a flat 240px, and remembers the height you drag it to. A one-line query used to keep two thirds of the screen while its answer got three rows under five bands of chrome.
- **Picus** (SQL studio): the panes are **Rows** and **Messages** — the word "Results" no longer appears twice, one line under the other — and Messages carries the number of errors in it. The "still filling" notice is now the row counter itself, reading *loaded of total*, instead of a forty-word banner across the top of every partial result.
- **Picus** (SQL studio): a **statement in flight says so in the toolbar**, next to the button that started it.
- **Picus** (SQL studio): the connection is **named once per bar**. Its engine and installed version were spelled out again in the status bar under a toolbar already showing both, which put the same connection on screen four times.
- **Picus** (SQL studio): the generator and the Inventory **open on their content**, and the connections panel no longer carries a standing paragraph about what the colours mean — explanations that are read once belong in the Docs, not in sixty pixels of every session.
- **Picus** (SQL studio): the **structural pattern boxes wrap** and are taller, so a pattern no longer scrolls out of its own left edge.
- **Result grid** (Picus): numbers are no longer drawn in the warning colour — every id, count and price in every result came up orange, where a vivid accent is supposed to mean state. The horizontal rules between cells are gone with them; rows are told apart by hover and selection, as in the layout this window is modelled on. Right alignment and tabular figures stay.
- **Picus** (SQL studio): **a DML value is SQL when it starts with `=`, and a quoted value otherwise.** `=SYSDATE`, `=SEQ_CATALOGO.nextval`, `=(SELECT MAX(ID)+1 FROM T)` and `=ALTRA_COLONNA` all pass through as written; `==` escapes a value that really starts with an equals sign. **Breaking**: a bare `SYSDATE` or `NULL` is now the word, quoted — which is the point, since Picus can no longer guess wrong in either direction. Pasted statements arrive already in this notation, so round-tripping one through the form cannot change what it means.
- **Picus** (SQL studio): **query results moved into the bottom panel**, alongside Consistency and Output — the grid used to be welded under the editor, so a tab that had once run a query kept a third of its height for it forever and there was no way to close it.
- **Picus** (SQL studio): the **version table, the expected encoding and the analysis settings are now the project's**, edited on their own pages and written to the repository's configuration on an explicit Save rather than to this machine's profile. The table picker filters as you type and is wide enough to read.
- **Picus** (SQL studio): the **Inventory is one table per kind** — tables, views, sequences each its own, with the columns still lined up across them — instead of one long list under heading rows.
- **Picus** (SQL studio): the **Inventory matrix now has a column per engine and role** rather than one per folder — a repository with a folder per released version had hundreds, and the table was a horizontal scroll answering a question nobody asks. Expanding an object's row gives the folder-by-folder numbers behind every column, and statements landing outside the columns are counted rather than rounded away. Findings group by **folder** where they used to group by branch.

### Fixed

- **Picus** (SQL studio): **saving a script no longer scrolls it back to the top.** A save re-reads the repository, which empties the text cache; the editor fell back to its loading state for that instant, so it was torn down and rebuilt at line 1. Saving halfway down a long file now leaves you where you were.
- **Picus** (SQL studio): a saved script's tab **stops showing as unsaved.** The dot was set on the first keystroke and never cleared, so every file that had been edited once looked dirty for the rest of the session.
- **Picus** (SQL studio): **Cancel now always gets you out.** PostgreSQL ignores a cancel while a backend is in an uninterruptible wait, and the studio simply waited with it — a spinner that never went out, a Cancel that did nothing however often it was pressed, and a tab that would never run anything again. A cancel that is not honoured within a couple of seconds now abandons the connection and opens a new one, and says so. The old statement may still be running on the server; that is stated rather than papered over.
- **Result grid** (every product): the **row-number column keeps its header** when the grid is scrolled sideways. The header moved as one piece while the numbers stayed pinned, so after any horizontal scroll the label above rows 1, 2, 3 belonged to some other column.
- **Every product**: a dropdown whose "all of them" option is the empty value — *Every folder*, *Both*, *Any* — **shows that option** instead of rendering as an empty box with a chevron, which read as a control that had failed to load.
- **Picus** (SQL studio): a sequence with no maximum says **no limit** rather than printing a 19-digit number that was both the type's limit and, after the trip through JSON, off by 193.
- **Picus** (SQL studio): the Inventory column header names **how many folders and how many files** it counts over; it used to read "3 folders · statements", the number missing.
- **Picus** (SQL studio): the declared type in the generator form is **elided rather than sliced** — `character varying(5` was a `character varying(50)` cut mid-token, which reads as a different type.
- **Picus** (SQL studio): the connection dialog **can no longer open blank** on a connection that exists. It read the connection once at mount, so opening it while the list was still loading gave empty fields that would then have been saved over the real ones.
- **Picus** (SQL studio): **cancelling a read no longer restarts it.** The streaming read falls back to a held cursor when it fails, and a cancellation looked like a failure — so pressing Cancel re-ran the statement the slow way, on a tab that had already reported itself cancelled.
- **Picus** (SQL studio): **an abandoned query can no longer leave a cursor nobody owns.** Its reply may still arrive minutes later carrying a held result; adopting it then would close the result the user is actually looking at and orphan the one it replaced. A reply that is no longer the tab's current run has its cursor closed on the spot.
- **Picus** (SQL studio): closing or reconnecting a session that had **stopped answering** used to hang as well, because releasing its results is itself SQL and queued behind whatever was stuck. Releasing is now bounded, and the reset path speaks to the old connection not at all.
- **Picus** (SQL studio): Run on a tab that is still waiting says so instead of doing nothing.
- **Picus** (SQL studio): **a result is traced back to its table by the parser, and from the statement that ran.** It used to be worked out with a regular expression over the tab's *whole text* — so a scratchpad holding more than one statement reported every result as coming from several tables, and so did any single query carrying an `EXTRACT(YEAR FROM …)` or a subquery in its select list. Those rows were then refused editing and their `bytea` cells would not open, because opening one needs the key of a row and a row needs a table. The answer also now distinguishes a **view**, which nothing in the SQL can tell you, and says so instead of "not a table on this connection".
- **Picus** (SQL studio): clicking a large object that **cannot** be opened now says why, instead of doing nothing.
- **Picus** (SQL studio): **a restored query tab keeps the database it was bound to.** Tabs are re-opened while the connection list is still being read, so every restored tab was coming back bound to nothing — it then ran against whichever connection was active while the result panel described none, and reported the rows as read-only. The binding is now kept as written and resolved when it is read.
- **Picus** (SQL studio): **an `ORDER BY` no longer sorts the whole table before showing anything.** The row limit was only on the fetch, where the planner cannot see it, so an ordered query sorted every row — large objects included — to a temporary file before returning the first one. The limit is now part of the statement, which turns the same sort into a top-N. An ordered statement is also never wrapped to mask its large objects: PostgreSQL may hand a sub-select's rows on in another order, and a grid in the wrong order is worse than a slow one.
- **Picus** (SQL studio): **a failed read no longer poisons the connection.** The statement that reads the first window opens a transaction; when it failed part-way the session was left inside an aborted transaction block and every statement afterwards was refused until the connection was reopened — which looked exactly like the studio hanging, and went away on a restart. It is now always ended.
- **Picus** (SQL studio): **running a query straight after another one no longer waits for the first one's row count.** The exact count runs in the background, and a session is one database connection — so the new statement queued behind it, silently, for as long as the count took. The count is now given up when something the user is waiting on needs the connection; the planner's estimate stands, which is what it is for.
- **Picus** (SQL studio): **a read no longer waits for the whole result before showing the first rows.** A scrollable result used to be materialised in full on the server before a single row appeared — the row limit on the grid bounded none of it — so any query touching a large table took minutes with nothing on screen, and Cancel had nothing to interrupt. The first window is now streamed, and the scrollable snapshot is taken only if you scroll past it. Your statement is not rewritten to do it, so an `ORDER BY` is executed exactly as written. The consequence, stated: those are two reads, so without an `ORDER BY` a row may repeat or be skipped exactly at that boundary.
- **Picus** (SQL studio): the exact row count no longer forces that materialisation either — it counts the statement instead, which reads none of the columns.
- **Picus** (SQL studio): the query editor's **second toolbar is gone.** Run, Run all, Cancel and the connection were drawn twice, once per bar; what is left is the top one, carrying the schema, the engine and the server version.
- **Picus** (SQL studio): the result grid's **header now scrolls sideways with the rows**, so a wide result still says which column is which.
- **Picus** (SQL studio): **a query on a table of documents no longer takes minutes.** A result you can scroll is one the server materialises in full first, so `SELECT * FROM archivio` copied every megabyte of every `bytea` into a tuplestore before the first row appeared — and the 500-row window saved nothing, because the whole table had already been read. The large objects are now left out of a typed `SELECT *` exactly as they are in a relation tab. Their size is read from the value's storage pointer rather than by decompressing every value, which is what made the relation tab slow on the same table.
- **Picus** (SQL studio): opening a masked cell no longer **leaves a held result behind** on the server for each cell opened.
- **Picus** (SQL studio): **connecting no longer stops at "reading schema" forever.** The catalogue read asked the server to sort its result, and on a real schema — 695 tables, 15 222 columns — that sort never finished: unsorted the same query streams in 45 ms, and with *any* `ORDER BY`, including by `oid`, it did not come back at all. The ordering now happens after the rows arrive. Reading that schema went from never to 400 ms. Three further inefficiencies on the same query went with it (a per-column subquery for the primary-key flag, a plan chosen for a `NULL` parameter, and partitions listed as though they were tables), and a catalogue read that takes more than a minute now stops waiting and says so rather than leaving the studio on a spinner.
- **Picus** (SQL studio): the schema is no longer read **several times at once**. The read was started while the connection was still opening and again once it was open, and each one queued behind the last on the same connection.
- **Every backend**: **a request is always answered.** A handler that panicked used to unwind past the reply, so the caller waited on a message that would never arrive — no error in the interface, none in the log, and a window that had simply stopped. The panic now comes back as the failure it is, the backend survives it, and a call outstanding for more than fifteen seconds says which method it is waiting on. A reverse-channel handler that holds the reader thread says so too, since while it does, nothing else from that backend can be delivered.
- **Picus** (SQL studio): reading a schema can no longer be brought down by one odd column — a catalogue value that came back `NULL` where a name was expected used to take the whole read with it.
- **Picus** (SQL studio): a **NOT NULL column with a default is no longer reported as required** when left empty. An empty cell means *not supplied*, an unsupplied column is left out of the statement, and the default is exactly what fills it — so `CUSTOMIZED NUMBER DEFAULT 0 NOT NULL` was being asked for a value in the one case the default exists to cover.
- **Picus** (SQL studio): **a `DELETE … WHERE` no longer makes the generator forget the whole table.** Only an unconditional `DELETE` or a `TRUNCATE` does — and the scripts are now read in install order rather than alphabetically, so a delete is seen after the insert it removes. On a repository that reloads its tables, one such line was erasing everything read from every other folder, and the row already installed was never found.
- **Picus** (SQL studio): the diff now **says what the generator concluded about the rows** rather than reconciling in silence. "Nothing inserts into this table, so this is a new row" and "these statements insert into it but none names CUSTOMIZED, so no row could be matched on the comparison key" used to look identical — a block appended beside the row it should have changed.
- **Picus** (SQL studio): **"Changes to the scripts" no longer shows the first diff forever.** It rebuilds itself after every generation, marks itself when it describes an earlier one, and has a Recompute button — the only way to build a preview used to be a button that disappeared as soon as one existed.
- **Picus** (SQL studio): <kbd>Ctrl</kbd>+<kbd>Enter</kbd> **runs the selection again.** The editor bound it to "insert a blank line" and stopped the event, so with the cursor where it always is the key split the line and ran nothing.
- **Picus** (SQL studio): the **DML generator works with no database connected.** The table list now holds what the repository's own index knows as well as what a connection has, and pasted `INSERT`s supply their own table and columns — so the paste source no longer asks for a table it had already been told.
- **Picus** (SQL studio): the **paste source is a real SQL editor** — highlighting, and completion over the connected database's tables and columns instead of a bare text box.
- **Picus** (SQL studio): the **Inventory no longer marks what the consistency report does not.** Any count above one was tinted as a warning — the ordinary shape of a table created once and altered four times — and three separate definitions of "gap" disagreed with each other and with `CONS001`. There is now one, used by the matrix, the sidebar and the header count alike, and a legend saying what the marks mean.
- **Picus** (SQL studio): **a string containing a backslash no longer swallows the rest of the file.** The Oracle highlighting treated `\` as an escape — Oracle has no such rule — so `'C:\temp\'` left the literal open and everything after it was coloured as one string.
- **Picus** (SQL studio): a **portable script is no longer highlighted as Oracle**. Files under a folder written for both engines fell through to the one dialect they are specifically not written in.
- **Picus** (SQL studio): a **keyword can no longer become a table**. When the parser recovers from a construct it cannot assemble, whatever token sits where a name would go was read as one — so `ON DELETE CASCADE` could produce a blocking finding about a table called `CASCADE`.
- **Picus** (SQL studio): **the engine's own dictionary is no longer indexed.** `user_tab_cols`, `dual`, `v$…`, `pg_…` and anything under `sys` or `information_schema` are the engine asking itself a question — nobody installs them, and a PostgreSQL counterpart is never coming — so they got a row that could only read as an unclosable gap.
- **Picus** (SQL studio): objects the repository **only reads** are marked as such in the Inventory, never counted among the gaps, and can be hidden. A table another repository installs, read here by a view, has a row of dashes that means "not ours" rather than "missing".
- **Picus** (SQL studio): **a table a view merely reads is no longer reported as one dialect's missing change.** Reading a table in a `FROM` and inserting into it arrive at the parser as the same kind of mention, so a view over a table that another repository installs made `CONS001` report a gap in scripts that never installed it — a finding nobody could close by writing anything. The rule now compares what the scripts *change*: creations, alterations, writes, `DROP` and `TRUNCATE`.
- **Picus** (SQL studio): **a version guard written inside a PostgreSQL function body now counts.** Update scripts that wrap their work in a throwaway function — the house style of the repositories this exists for — were all reported as having no guard, because the walker gave up on a body it could only partly model instead of keeping what it did understand.
- **Picus** (SQL studio): the **throwaway wrapper function every update script replaces** is no longer reported as an object created in two places. `CREATE OR REPLACE` is the author stating that replacing is the point, and it is now read that way.
- **Picus** (SQL studio): `TO_NUMBER` is **no longer flagged as Oracle-only syntax in a PostgreSQL script** — PostgreSQL has it, and the finding sent people to rewrite working SQL.
- **Picus** (SQL studio): **a row a later update rewrote is no longer reported against the initialisation.** The update folder is a chain of deltas applied in order, and reading it as a bag of INSERTs reported every intermediate value a row has ever had — version 1.11 writes a value, 1.13 replaces it, and the initialisation carries what 1.13 left. Only the updates' last word about a row is now checked.
- **Picus** (SQL studio): a project can declare **more than one version table**, one per installed module. An update script guarding against any of them counts as guarded; with a single name, every script belonging to the second module was reported as unguarded.
- **Picus** (SQL studio): **a column quoted on one side and bare on the other is no longer read as two columns.** PostgreSQL folds an unquoted name to lower case and Oracle to upper, so a team writing `"name"` in one dialect and `NAME` in the other has written the same column twice — and every table where that happened was reported as filled in differently, naming columns one dialect "never writes".
- **Picus** (SQL studio): a finding now says **what kind of thing** it is about — "The table AGGIORNAMENTO is not touched by…". In a repository whose folders carry the same names as its tables, the old wording read as a claim about the folder it was anchored to.
- **Picus** (SQL studio): **changing a project setting now takes effect on the next check.** Switching a rule off, changing the initialisation model or classifying a folder left the held repository holding the configuration it was opened with, so re-running the consistency check gave the same answer as before and only "re-read the repository from disk" helped. The configuration is re-read on every write; the decoded text is kept, so it costs nothing.
- **Picus** (SQL studio): a row an update writes that the initialisation writes **with a different value** is now reported as a value that drifted, naming the columns and pointing at the other statement — not as a row the initialisation "never inserts", which it plainly does.
- **Picus** (SQL studio): **what a PostgreSQL `DO` block or function body does is no longer invisible.** Dollar quoting is one token to the parser, body and all, so everything a repository's PostgreSQL half did inside `$$ … $$` counted for nothing — no objects, no data, no coverage. The same change written as an Oracle `DECLARE … BEGIN … END` and as a PostgreSQL function therefore looked like a change one engine had and the other lacked, on the files where the two are most alike.
- **Picus** (SQL studio): **an INSERT that follows a DELETE of the same table is no longer called a duplicate.** Clearing a row and writing it again is how an update script is made re-runnable, and the rule fired on every one of them.
- **Picus** (SQL studio): an object **created in the initialisation and again in the update that introduced it** is no longer reported as created twice — under a cumulative initialisation that is the model working. Two files that a *fresh install* both runs still are.
- **Picus** (SQL studio): **hundreds of findings that described correct behaviour are gone.** A repository whose initialisation is kept at the latest version was being told, once per first-release row, that no update carries it — which is true, and is not a mistake. That direction is now off unless the project says the two halves are meant to mirror each other, and the report states that it is off rather than falling silent.
- **Picus** (SQL studio): **a query tab with more than one statement in it no longer appears to hang.** The whole buffer was sent as one string, which makes the server materialise every result at once and hold nothing that can be scrolled. Run now executes the selection if there is one and otherwise the statement under the cursor.
- **Picus** (SQL studio): **a view is one row in the Inventory instead of two.** Every `FROM x` is parsed as a table reference — the grammar cannot know what `x` turned out to be — so a view created once and read fifty times appeared as a `view` with one statement and a `table` with fifty, and the wrong one was the one people saw. Views, sequences and triggers also stop wearing a package's icon.
- **Picus** (SQL studio): **folders whose scripts all classify themselves are no longer listed as needing classification.** Where the engine is on the file name, the folder above has no engine and never will, and asking about it was asking for an answer that would change nothing.
- **Studio** (config editors): **saving no longer corrupts a file that has a byte-order mark or is encoded in UTF-16.** A file with a mark gained another one on every save (three saves, four marks), and a UTF-16 file was written as UTF-8 bytes underneath a UTF-16 mark — a file that would no longer open. Saving a character the file's encoding cannot hold now stops with that character named, instead of silently replacing it with an escape sequence.
- **Every greyed-out button can now explain itself.** A disabled button receives no mouse events and cannot be focused, so its "why is this unavailable?" tooltip never appeared, by mouse or by keyboard. Buttons that carry an explanation now stay reachable — hover or Tab to them — and, separately, disabled buttons finally *look* disabled and stop lighting up under the pointer.

- **File Explorer**: the window no longer stays behind after you **drop files onto it from another window** or open it on a path from a link — it now raises itself as it always meant to.
- **Canopy**: the **maximize button** in its title bar did nothing — that window was never granted permission to maximize itself, so the click was rejected silently. It now maximizes and restores like every other window.

- The **Disconnect** button on a connected Git provider was drawn plain white outside the Settings panel (for example in the new Credentials dialog) — it only ever had colours while it happened to sit inside that one panel. Low-emphasis bordered buttons are now a variant of the shared button, so they look the same everywhere.
- **Merula** (music): **downloading a sample bank or a model works again** — every transfer aborted after exactly 30 seconds with an "error decoding response", because a timeout meant for short API calls was capping the whole download; large banks are now bound only by a connection and a stall timeout, so a multi-GB bank can take as long as it needs.
- **Merula** (music): **sample-bank downloads now show live progress** instead of sitting on "Starting…" for the entire transfer — banks served without a declared size (most of them) reported no progress at all.
- **Merula** (music): the **General MIDI** bank installs again — its download host started refusing non-browser clients outright, so it now comes from a mirror of the same FluidR3 soundfont.
- **Merula** (music): **firing a clip from the launcher now actually changes what you hear** — the launcher drew its grid and accepted clicks, but the backend discarded the selection, so the base pattern kept playing. Firing a scene now re-stages the chosen clips live, loading any instrument they introduce without interrupting playback.
- **Merula** (music): the **VCSL** sample bank now indexes under real instrument names — articulation folders were being mistaken for instruments, so the bank offered `mallets.soft_mallets` and a bare `stroke`/`on`/`off` instead of `mallets.xylophone` and `bell_tree`, and several instruments were unreachable. Re-index the bank (or re-download it) to pick up the corrected names.
- **Bennu** (Java editor): **live Java validation no longer goes fully dark** — a single internal check failing on a specific file (e.g. one with accented/legacy-encoded characters) used to wipe *every* squiggle, syntax included, making validation look dead and letting real errors like calls to non-existent methods slip through. A failing check is now contained: the rest of validation keeps working and the editor keeps its diagnostics.
- **Bennu** (Java editor): resolver-backed checks (**call to a non-existent method**, **wrong argument count**) now fire on classes that `extend`/`implement` a **nested** JDK or library type — such a supertype failed to resolve (a `/` vs `$` binary-name mismatch), and a single unresolved supertype silently disabled those checks for the whole class.
- **Bennu** (Java editor): **member completion no longer suggests `private` members of another class** — a `receiver.` on an object of a different class now hides that class's private fields/methods (they're offered only inside their own class, per Java's rules).
- **Bennu** (Java editor): **Ctrl+B into a library / dependency type no longer spikes the CPU** — going to a type whose source isn't in the JDK `src.zip` used to linearly scan the entire archive on every jump; it's now an indexed O(1) lookup.
- **Bennu** (Java editor): **editing config XML** (Struts/Spring/Tiles) is no longer sluggish — every keystroke used to trigger a full re-scan of the whole project (re-reading every XML and Java source), whereas editing Java stayed instant. The config-graph rebuild is now coalesced onto a background worker and skips the whole-project source re-read while only XML changed, so typing in `struts.xml` is as responsive as editing Java.
- **Corvus** (Git): **Stage / unstage / discard folder** in the Stage panel works reliably again — it staged only some of a folder's files (or failed outright) because it fired one request per file in parallel, which raced on the git index; the whole folder is now applied in a single atomic operation.
- **Picus** (SQL studio): **indexing and checking a large repository is no longer unusably slow** — one with a few hundred scripts in a few large files took over five minutes to read, because the cost of working out a line number grew with the size of the file and was paid once per finding. It is now seconds, and a repository's speed no longer depends on whether its SQL is spread over many small files or a few big ones.
- **Picus** (SQL studio): **a query result cut at the row limit now says so** — a capped marker beside the row count and a banner above the grid. A truncated result and a genuinely short one looked identical, so there was no way to tell a table's end from the limit, and the grid's sorting and filters silently applied to the fetched rows only.
- **Picus** (SQL studio): **the saved query row limit now applies from startup.** It was persisted and displayed correctly, but only took effect if you re-entered it in Settings during that session — reopening Picus silently went back to 500 rows.
- **Picus** (SQL studio): a query no longer **fetches the whole table before cutting it down** — the limit is now applied by the server wherever the statement allows, so `SELECT * FROM orders` on millions of rows stops there instead of crossing the network in full.
- **Picus** (SQL studio): **turning a page of table data, and opening a table's tab, no longer re-read the entire schema** — on a database with several hundred tables both fetched every column of every relation to answer a question about one, which made paging cost far more than the rows it returned.
- **Picus** (SQL studio): <kbd>Ctrl</kbd>+<kbd>Enter</kbd> and <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd> now act on **the connection the query tab is bound to**, the one named in the bar above the editor. They used the connection highlighted in the sidebar instead, so a rebound tab could run its statement — or fail to cancel it — against a different database.
- **Picus** (SQL studio): **Cancel is no longer lost** when it arrives in the moment between a statement being prepared and being run — the request is now remembered instead of hitting a server with nothing yet to stop, which let the query run to completion after an apparently accepted cancel.
- **Corvus** (Git): **Initialize repository** no longer leaves behind a broken, half-initialized repo when a step fails (e.g. a bad remote URL or a git-identity problem) — init is now transactional: on any failure it rolls back the `.git` it created, so the folder is left clean and you can retry instead of having to delete and recreate it.

### Added

- **Picus** (SQL studio): **a project can now say what a folder *name* means in its repository** — one line declaring `POS` as PostgreSQL classifies every folder called `POS`, including the ones the next release adds. Classifying a folder whose name repeats offers, as a separate question, to make it a rule and says how many folders that would reach; the names a project has accumulated are listed and editable under Settings ▸ Project ▸ **Folder names**.
- **Picus** (SQL studio): **folders written in an engine Picus does not support are now recognised as such** — SQL Server, DB2, MySQL, MariaDB and SQLite are named on the chip and then left alone, instead of appearing forever as "no engine" and generating a question nobody can answer. Their scripts are never parsed, never compared and never written into, which also makes checking a repository noticeably faster when a large share of it belongs to another engine.
- **Picus** (SQL studio): **a folder of portable SQL can now say so** — plain statements meant to run on Oracle *and* PostgreSQL no longer have to be declared as one engine and reported as missing from the other. A portable folder counts as covering both, anything belonging to only one engine in it is flagged as a broken promise, and a generation written into it produces **one file that satisfies both** instead of two — restricted to what both accept, with anything else refused and the reason named.

- **Picus** (SQL studio): **Scripts on disk now shows the repository's real folder tree**, nested to whatever depth it has, instead of a flat two-level shape guessed from folder names. A repository that keeps its engine at the bottom — `AGGIORNAMENTO/4.13.2/ORA`, `…/POS`, `…/MSQ` — used to appear as a run of identical rows with no way to tell them apart; repeated folder names now carry the folder above them, and every row's full path is a hover away.

Right-click a folder in the tree (or <kbd>Shift</kbd>+<kbd>F10</kbd> on the focused row), or press <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> for a searchable dialog; **Inherit from above** clears a wrong guess. The chips say which answers are set on the folder and which are inherited, so it is always clear where to go to change one — and the choice is saved with the repository, so everyone opening it reads it the same way.
- **Picus** (SQL studio): the **script half is real** — the repository tree, the object inventory and the consistency report are read from disk instead of sample data. A repository belongs to a **connection**: attach the folder a database is installed from, and opening that connection brings its scripts, inventory and findings into the window. Reading the folder is immediate and checking it runs in the background, so nothing waits on the analysis. <kbd>F5</kbd> re-reads from disk; <kbd>F8</kbd> / <kbd>Shift</kbd>+<kbd>F8</kbd> walk the report, opening each finding's file at its line.

Suppressed findings stay visible behind the eye toggle with their declared reason spelled out.
- **Picus** (SQL studio): questions the reader could not settle when opening a repository — a folder whose role is unclear, a folder whose engine is a guess — are now shown above the tree instead of being resolved silently, and a repository Picus has never been told about says plainly that its layout is an inference.
- **Picus** (SQL studio): **writing to the scripts is now two steps.** The preview shows the exact bytes each file would receive — computed by the same code that performs the write, with the insertion rule stated in words — and the write hands those fingerprints back: if a file changed since you looked at it, the write is refused naming that file and nothing at all is written.

- **Picus** — a new product in the suite: an Oracle / PostgreSQL client that is also a maintainer of the SQL scripts those databases install from. It reads a script repository as the folder tree it actually is, works out which engine each part is written for, keeps them in step, and generates a change once into every folder that expects it, in the form each one requires. This release brings the full interface — connections browsing tables, views, sequences and triggers; tables showing their foreign keys (both directions) and indexes, with paged data; a query editor; the DML generator (guided form, pasted SQL or CSV, per-destination rules, live multi-dialect preview) and the consistency report. Where the installed version is recorded — table, column, and whether a date is stamped at all — is a project setting, so the version guard works beyond the one project it was modelled on. It connects to **PostgreSQL** for real — browse the schema, page through a table, run statements and cancel a long one — and remembers its settings and connections between sessions. Passwords go to Arbor's keychain, never into the project. Oracle has no driver yet and says so plainly: its scripts are still fully read, analysed and generated into, which is what a folder written for that engine actually needs. The script half runs on sample data until its backend lands, but the SQL generation itself is real: the preview, the per-destination diffs and the value checks all come from the backend generator, which is covered by tests that assert the generated statements verbatim — and a destination whose rules contradict each other (a version guard with nothing to return from) now says so instead of losing the guard silently.

  20s respectively); the PortableGit download stays untimed since the
  same connection streams a multi-MB archive.
- Markdown editor live preview: GFM tables render as a real HTML table
  with framed cells, header row and column alignment from the
  `|:--:|--:|` markers; cell content supports bold, italic,
  strikethrough, inline code, and links. An all-empty header row
  renders as a headerless grid. The caret entering the block flips it
  back to source mode for editing. Unordered list markers (`-` / `*`
  / `+`) show as a proper bullet glyph off the active line, and
  ordered list numbers align tabularly.
- Status bar slimmed down: repo path moved to the left segment; Fetch and
  "Open in browser" relocated to the graph toolbar; version pill removed
  (About still reachable from the Command Palette and the menu).
- Issue detail dialog is now self-contained: the tracker, API routing,
  and linked-commits source repo are pinned at open time, so a Linear
  ticket stays usable from a Jira-configured repo (and vice versa), and
  restoring from the parked-dialog dock no longer forces a checkout back
  to the source repo. The Linked Commits section explains itself when
  the original tab is no longer open and offers a one-click fallback to
  the current repo.
- Branches / Tags column rendering: local branches use a monitor icon, remote branches a globe icon; chips are now squared off (matching tag shape); branch names stretch with the column width instead of capping at 180px; multiple tags on a single commit collapse into a click-to-expand chip (also triggered when any tag shares a row with one or more branches). The standalone HEAD pill is gone — the HEAD branch is already styled green so the duplicate badge was noise. Default dark theme's lane-3 colour shifted from magenta-purple to indigo, and the four community themes that shipped `lane-3` literally identical to `color-tag` (Ayu Dark/Light, Solarized Dark/Light) were also retuned so branch chips on that lane don't read as tags.
- The WIP (working directory) row now lives inside the scrolling history pane, pinned just below the sticky column header. It uses the same grid layout as the commit rows so the dashed lane node lines up with the lane SVG behind it, and the "Working Directory" label / change pills sit in the Subject column — wherever the user has dragged it. It stays visible while exploring older history. Scroll-area lateral inset bumped to match the toolbar's so header, WIP and rows share the same 4 px left/right gap as the toolbar above.
- Branches sidebar groups local & remote branches and worktrees by their `/` path segments — GitKraken / Fork style folder tree with collapsible, lane-colour-matched folders. On by default; toggle from the folder-tree icon in the sidebar header (always visible, next to refresh), the **Alt+Shift+G** shortcut, or the Command Palette entry *Branches: Group by Path*. The on/off and collapsed-folder state is per-repo (saved in `.arbor/config.toml`); a host-wide `branches.grouping_recursive` knob flips between deep split and single-level.
- Plugins can mount a full main-area view via `arbor.ui.add_view` — a body surface (where the commit graph lives) that renders form-DSL content with the full node + dispatch/patch protocol. It surfaces as an activity-bar icon, a Command Palette entry, and the **Alt+Shift+V** toggle; `placement = "graph"` keeps the tab bar and bottom panel, `placement = "main"` takes over the whole body. New `on_view_open` / `on_view_close` hooks fire on the owning plugin.
- Plugins can embed an editable code/text editor in a form via the new `editor` node — a CodeMirror 6 field with syntax highlighting, line numbers and search. Its content is submitted like any field and can be pushed from the plugin with `set_value`; it can also emit scoped, debounced `on_edit` and `on_select` events for live, high-frequency UIs.
- Plugins can embed a read-only diff viewer in a form via the new `diff` node — unified and split layouts (local toggle), syntax highlighting and virtualization for large diffs. The plugin supplies the diffed hunks; updating them live is a `patch` away.
- The plugin form `tree` node gains a dynamic "data tree" mode — `lazy` children fetched on expand (the row fires a scoped `on_expand`, the plugin fills it with a `patch`), a scoped `on_select`, full keyboard navigation (arrows / Home / End / Enter), and row virtualization for large trees. Static trees are unchanged.
- Plugin form value slots can opt into *scoped dispatch*: a `select` `actions.change`, a leaf `field`, or a `vec_field` whose change targets a `dispatch` object (action or command) now ships a compact `{ node_id, slot, value, state? }` payload instead of the whole form, tracked per node so concurrent edits don't block each other. Declare `scope_state` to include a slice of the opaque form state. Bare-string actions are unchanged.
- Plugins can patch an open form's node tree granularly via `arbor.ui.form.patch(ops)` — merge props, append children, or remove nodes addressed by stable `id` without re-mounting — and mutate a single slice of the opaque form state via `arbor.ui.form.set_state_path(segments, value)` (passing `nil` deletes the key).
- Plugins can invoke each other's commands. A command registered as `invocable` can be fired by another plugin via `arbor.command.fire("<owner>::<id>")` or a form button's `dispatch = { kind = "command", … }`, gated by the new `command_invoke` permission plus the command's declared `required` tier.
- Plugins can invoke host built-in commands the same way — `arbor:git.commit|push|fetch|pull|branch_create|checkout|branch_delete|stage_all|unstage_all` (require `git = "write"`), plus `arbor:repo.refresh` and `arbor:app.open_settings` (no tier). Closed by default and gated by `command_invoke` + the declared tier; git commands target `ctx.tab_id` or the active tab.
- IntelliJ-style "compact middle packages" for file trees — *Settings → Interface → Compact file tree folders* collapses chains of single-child directories into a single row across the Files sidebar, the Stage area tree, and the commit detail file list. Also exposed as a Command Palette toggle. Conflict file lists always compact regardless of the setting.
- Markdown editor with Obsidian-style live preview — open any `.md` /
  `.markdown` file via the Files sidebar context menu and edit it
  in-place. Markdown markup is concealed per inline component: only
  the element under the cursor reveals its raw syntax (e.g. editing
  one `**bold**` word doesn't reveal the sibling `*italic*` on the

  visible diff (stage panel, commit detail, MR detail). Press again from
  inside the overlay to dismiss.
- Command Palette verbs *Linear Issue* and *Jira Issue* — cross-tab
  ticket search that opens the detail modal pinned to the picked
  provider, visible only when signed in to that tracker. Same `#` / `~`
  query prefixes as the Issues sidebar; no per-project scoping applied.
- Minimize button on long-form dialogs (MR detail, Issue detail): parks
  a "reopen" shortcut in the status-bar dock so you can roam to other
  tabs / workspaces and pick the workflow back up later. Click a chip
  to switch to the original tab and re-open the dialog; ✕ to discard.
  Surviving workspace and tab switches comes from the action-based
  design — the chip outlives the modal component, so unsubmitted text

- Markdown editor inline media: `![alt](url)` references render as a

  the file extension — `.mp4` / `.webm` / `.mov`, `.mp3` / `.wav` /

  WebView), so the system browser handles playback while the rest of
  the README stays in the editor. Caret on the source reveals the

### Fixed

- Plugin form `arbor.ui.form.patch` no longer leaves stale children on screen when merging a fresh child subtree into a `section` / `tabs` / `tree_layout` / `wizard` / `form_field` / `tree` row — the renderer iterates children with a keyed `each`, and freshly-emitted children now go through the same auto-ID step the initial tree gets at mount, so the new markup actually replaces the old.
- F5 (refresh) now also reloads the currently visible diff panel, so externally-modified files appear updated without needing to click off and back on the file.
- Plugin forms no longer silently ignore a click on a menu item, list/card row action, or suggest-grid entry while another action is still running — they now show a brief "action already running" notice (buttons already disabled themselves with a spinner).
- Title bar app mark, hamburger menu, and workspace monogram are now the
  same height, so the left cluster reads as one aligned row.
- Plugins sometimes appeared disabled after launch until the Plugin
  Manager *Refresh* button was clicked. Boot now handshakes with the
  frontend before emitting plugin events, serialises IPC against the
  load thread, and fires the same reload signal the manual refresh
  uses — so sidebars / activity-bar items / command-palette verbs
  appear as soon as the splash dismisses.
- Idle CPU/IPC waste from plugins re-publishing identical state. The
  contribution registry now deduplicates writes by value, so polling
  views (running services, status indicators) no longer fan out
  frontend refetches when nothing actually changed.
- Global shortcuts (Ctrl+R, Ctrl+B, Alt+Shift+1…, etc.) no longer leak
  through the full-screen diff overlay or any other modal dialog —
  pressing a bound chord on top of a modal is now a no-op instead of
  firing the underlying action.
- Removing a repository from a workspace via the Workspace Manager now
  also closes its tab when that workspace is active, so reopening the
  workspace later doesn't resurrect the tab for a repo that's no longer
  a member.
- Diff viewer scrolling no longer stutters on multi-thousand-line files —
  off-screen hunks skip the per-scroll layout work, and chunk navigation
  (F3 / Shift+F3) jumps instantly instead of smooth-scrolling through
  every intermediate hunk.
- Windows taskbar icon goes blank after the system resumes from sleep —
  re-applied on every power-resume notification.
- Repository Browser: cloning from the in-app browser sometimes left the
  Clone button stuck in *Cloning…* even after the repo had been cloned;
  the modal now dismisses as soon as the clone itself succeeds and the

### Changed

  dirty working directory, switches HEAD, then reapplies the stash — same
  flow as Pull. If the reapply conflicts, the resolution modal opens with
  the stash kept at index 0.
- Plugin enable / disable / uninstall cascades along required dependencies.
  Disabling asks for confirmation and turns off every transitively-required
  dependent (leaves first). Enabling with required deps off asks to turn
  them on first, and refuses if a required dep is missing. Uninstalling
  disables dependents so they don't keep running against a vanished
  service. Plugin Manager detail rows show "Depends on" and "Required by".
- Marketplace install resolves transitive required deps against the catalog.
  The confirm modal lists "Will also install: …" and downloads in dep-first
  order. Required deps not in the catalog block the install.
- Settings moved from localStorage to `~/.config/arbor/config.toml`: font
  scale, animations and speed, commit-template fallback, diff settings
  (algorithm, context, view mode, word-wrap, confirm-discard), graph page
  size, branch / tag visibility, ticket-link chips, "use theme fonts". They
  now survive WebView cache clears and can be edited from disk.

  Drop Stash, Reset Hard, Discard All, Undo Last Commit, Unlink Worktree,
